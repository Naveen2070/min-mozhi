## BUG-80 fixed: new checker code E0304

- Decision (user): a new code, E0304, rather than reusing E0302. It enforces
  the existing spec/02 section 1.5 rule (an omitted child `clock`/`reset`
  connects to the parent signal of the same name), so no language change.
- `checker/names/insts.rs`: after the E0302 check, every omitted
  clock/reset must name a parent port, clock, reset, wire or reg; otherwise
  E0304 on the instance, naming the port and the child, with a `help:`
  showing the explicit connection. A same-named `const`/param/mem/instance
  is not a signal and still errors. Applies to real children and externs.
- Registry (R10): `ALL_CHECKER_CODES` 76 -> 77 (sorted),
  `mimz explain E0304`, catalogue row and reverse index in `docs/code/11-checker.md` (the
  index was also stale: now `E0401`-`E0420`, no `W0001`), fixture
  `tests/fixtures/errors/e0304_implicit_clock_no_parent.mimz`, spec/02
  section 1.5 sentence. Not localized (needs native review); counts now
  "35 of 77" in ROADMAP, spec/04, `morph.rs`, architecture.
- The check found a live case: `showcase/tamil-pure/edhiroli.mimz` left
  `UartTx`'s `clk`/`rst` floating (parent clock is `கடிகை`). Connected

  only `.clk(clk), .rst(rst)` -> `.clk(katikai), .rst(miittal)`.
- `mimz ir` on BUG-80's repro now reports E0304 (exit 1) instead of an

## Added: the Verilog backend (synthesis v1 phase 1 Task 3)

- `mimz_core::backend` (`mod.rs`, `verilog.rs`): `verilog::emit(&ir::Module)`
  -> `Emitted { text, top, ports }`, one flat Verilog-2005 module, one
  statement per cell; `legal_name` makes identifiers ASCII-legal and unique
  (Tamil romanized via `emit_verilog::translit`, now `pub(crate)`).
- Semantics follow `ir::exec`: arithmetic sign-extends both operands when
  either pin is signed, `Shl`/`Shr` unsigned, `Neg` signed, `Mux` picks `a`
  when `sel` is 1, registers `= 0`, a non-power-of-two `Mem` read is guarded
  to return `init` past the end, black boxes get `#(.P(v))` and their
  `verilog_name`.
- `ir::failure::Stage::Emit`: a `limitation` while emitting is a
  `Limitation`; `src/commands/ir_pipeline.rs::report` has the Internal header.
- Tests: 15 unit (`backend/tests.rs`), 1 failure test, 5 goldens
  (`tests/ir_verilog_golden.rs`, `tests/golden/ir_verilog/*.v`, banner line
  stripped). Deliberate breakage: per-pin sign flag, always-unguarded memory
  read, dropped `#(...)` each fail their named test.
- `from_src` in the unit tests elaborates in `SimMode::Lower` (the plan used
  the default `Warn`, which yields no `BlackBox` cell for the extern tests).
- Docs: spec/07-ir.md v0.5 (new section 6a, Backends), architecture row,
  `docs/code/13-tooling.md` Backends section, test map, README badge.
- Fix round 1 (review): `VERILOG_KEYWORDS` is now the full IEEE 1364-2005
  Annex B list (`table`, `event`, ... were missing); black-box module,
  parameter and port names are romanized like the AST emitter (explicit
  alias kept verbatim; the IR marks an alias as `verilog_name !=
module_name`); `Not`/`And`/`Or`/`Xor` with `out` wider than `a` is a
  `Limitation` (validate does not reject it); golden banner asserted;
  Tamil-name test checks the romanized spellings; tooling.md bullets
  reordered. +2 tests.
- Review: opus task review found every cell kind's semantics equal to
  `ir::exec` (including `Concat` pin order); 0 Critical, 2 Important (both
  from the plan's own code: incomplete keyword list, extern names not
  romanized), fixed in round 1; sonnet re-review: all addressed.
- Deferred (new open sub-gap in `docs/audit/gaps.md`, GAP-1, "limits of
  the IR Verilog backend"): alias detected only as `verilog_name !=
module_name`, so an alias equal to the name is romanized (no effect for
  ASCII); two Tamil extern pin or parameter names that romanize alike (for
  example `நீ`/`னீ`) are not renamed apart and would give duplicate
  connections (the AST emitter renames them); zero-width `range(0)` and
  signed `widen` of empty `Bits` have no guard.
- Constraints for Task 4 (same sub-gap): `ir::exec` samples an async reset
  only at the clock edge while the Verilog resets immediately, so the
  harness drives inputs, takes one full edge, then samples; `ir::exec`
  ignores register edges, so designs that mix rising and falling registers
  are left out of the comparison.
- Tests 1594 -> 1617 (+23).
