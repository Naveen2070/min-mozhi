# 2026-09-18

## Implemented: GAP-1 closure Task 6 — signed `ir::Bits`

- `ir::Bits` is now `{ nets: Vec<NetId>, signed: bool }` (was a bare
  `Bits(Vec<NetId>)` tuple) — `Bits::unsigned()`/`Bits::signed()`
  constructors, `width()` unchanged. Authorized by the 2026-09-10 Decision
  block (Task 1).
- Migrated every `Bits(...)`/`.0` call site across `ir/lower.rs`,
  `ir/exec.rs`, `ir/validate.rs`, `ir/print_line.rs`, `ir/print_sexpr.rs`,
  `ir/parse_line.rs`, and the test files that construct `Bits` directly
  (`lower_array_fn_params.rs` needed no change — it never constructs one;
  `tests/validate.rs` did).
- Fixed `UnOp::Neg`'s width divergence: `out` now grows by one bit when the
  operand is signed, matching `checker::widths::ops`'s `Signed(n) ->
Signed(n+1)` (previously stayed at `a.width()` unconditionally).
- Fixed `BinOp::Mul`'s literal-sizing divergence: a literal operand now
  sizes to the other operand's declared width before the multiply, at the
  `ExprKind::Binary` call site (mirrors the const-shift-amount fix's own
  approach).
- Lowered `min`/`max`/`abs` for real (previously `unimplemented!()`): `Lt` +
  `Mux` for min/max, `Neg` + sign-bit-select + `Mux` for abs — no new
  `CellKind` needed. Extracted a shared `push_mux_cell` helper (used by
  `FnStmt::If`, the register reset mux, and this code) instead of writing
  the `Cell { kind: Mux, .. }` literal a fourth time.
- Lowered `extend`'s sign-extend branch: reads `base.signed` directly
  instead of the old `arg_is_definitely_unsigned` heuristic, which could
  only recognize two source shapes and refused (panicked) on everything
  else. Sign-extension is pure net replication (the MSB's net repeated),
  no new cell — same convention as `Slice`.
- Deleted `arg_is_definitely_unsigned`, `expr_is_definitely_signed`,
  `unshadowed_signal_signed`, and (now-orphaned) `declared_signed` —
  `cmp_signed` for `Lt`/`Le`/`Gt`/`Ge` is now `a.signed && b.signed`, read
  straight off the already-lowered operands.
- `Builtin::SignedCast`/`UnsignedCast` now actually flip `Bits::signed`
  (previously a bare pass-through, since `Bits` had nothing to flip) —
  necessary for the cast to mean anything downstream; `Encoding` stays a
  pure pass-through.
- Necessary plumbing beyond the plan's literal text, required for the
  above to be reachable at all on real signed ports (not just casts):
  input ports, register Qs, and extern-instance outputs now carry
  `signed` from their declared `Width` at allocation time — without this
  a `signed[8]` input's `Bits` stayed `signed: false` forever, and the
  `Neg`/`min`/`max`/`abs` fixes above would never see a `true` to act on.
- Found and fixed one more latent bug while adding value-level tests for
  `abs`: `ir::exec`'s `Neg` cell read its operand as unsigned raw magnitude
  (`get_bits` always reconstructs `Val::signed: false`), so negating a
  genuinely negative operand computed the wrong two's-complement result
  (masked in the pre-existing `-a < 200` regression test, whose assertions
  were too coarse — a boolean comparison outcome — to catch it; caught by
  `abs(-128)` needing an exact width-9 value). Fixed: `Neg`'s exec arm now
  forces its operand `signed: true` unconditionally, matching the
  checker's own invariant that `-x` is never legal over an unsigned `x`.
- Rewrote the tests this closes the bug behind: three `#[should_panic]`
  "refused loudly" tests for `min`/`max`/`abs` become value-level
  Executor assertions; two `extend` `#[should_panic]` tests become
  sign-extension value assertions; the `-a < 200` comparison test is
  extended to the full input range the old bug had to dodge; the
  `signed(x)` identity test now checks nets-equality + the `signed` flags
  separately, since flipping `signed` is the whole point of the cast.
  Net +2 new test functions (`neg_on_a_signed_operand_grows_by_one_bit_
matching_the_checker`, `mul_by_a_literal_sizes_the_literal_to_the_other_
operands_width_not_its_own`) — updated `docs/code/10-test-map.md` and the
  README badge (1440 -> 1442).
- `cargo test --workspace`, `cargo clippy --workspace --all-targets -- -D
warnings`, and `cargo test -p mimz --test differential_fuzz` (default
  and at `MIMZ_DIFF_FUZZ_N=300`/`MIMZ_DIFF_FUZZ_CLOCKED_N=150`) all clean.
  The differential fuzz's IR leg deliberately excludes builtins by
  generator design (pre-existing, documented), so it mainly confirms no
  regression to the surface it does cover, not new correctness proof for
  `min`/`max`/`abs`/`extend`/`signed`/`unsigned` — that proof is the new
  Executor-based unit tests above.
