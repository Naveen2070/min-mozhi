### Headline — a CRITICAL silent-miscompile class re-opened

**BUG-28** (`extend()`) and **BUG-29** (`abs()`) in a Verilog **self-determined**
position (concat member, replication body) emit unsized operands. The simulator
passes, the hardware is wrong, and no diagnostic fires. Three reproductions,
all confirmed against Icarus:

```text
y = { b, extend(a, 8) }   sim ok  →  assign y = {b, (a)};        iverilog 000010101111  ✗
y = {2{ extend(a, 4) }}   sim ok  →  assign y = {2{(a)}};        iverilog 00001111      ✗
y = { b, unsigned(abs(a)) } sim ok →  assign y = {b, $unsigned(…)}; iverilog 010101000  ✗
```

Root cause is a single `_ => None` arm in
`crates/mimz-core/src/emit_verilog/self_determined.rs:22`. The fix machinery
already exists and works — `y = { b, a + b }` correctly hoists to
`wire [4:0] __mimz_sub_1` — so this is precisely **BUG-19's fix, landed for
operators and never extended to the builtin table**. Same LRM rule
(Verilog-2005 §5.4.1), same mechanism, uncovered case.

Worth recording _why_ the existing gates all passed it: every differential
oracle in the suite compares **simulator vs. Verilog**, and the random-program
fuzzer's generator is checker-clean _"by construction — every combine step
unifies operand widths via `extend()`"_, which keeps every `extend` in a
**context-determined** position. The broken case only lives in a
self-determined one. Filed as GAP-5; the fix is a `Builtin` × position matrix
driven off the enum, so a new builtin fails the build until classified.

## BUG-28/BUG-29 fixed — `extend()`/`abs()` self-determined-position miscompile

Branch `bug-28-29-self-determined-extend-abs`, off `develop`. Closes the review's
headline finding: `crates/mimz-core/src/emit_verilog/self_determined.rs`'s
`verilog_self_determined_kind` is now an exhaustive match over `Builtin` instead
of a `_ => None` catchall — a 14th builtin now fails the build until classified
here, per GAP-5's stated goal.

**Root cause went one layer deeper than the review's drafted patch.** `extend`
needed only the `self_determined.rs` edit (its other two gates,
`kind_is_inferrable` and `infer_call`, already classified `Builtin::Extend`).
`abs` needed three coordinated edits, because two upstream gates never knew
about it at all:

- `emit_verilog/expr.rs::kind_is_inferrable` — the pre-check every hoist call
  site runs before ever calling `hoist_if_needed`. Its `Call` arm only allowed
  `Extend|Trunc|SignedCast|UnsignedCast`; `Abs` fell to `_ => false`, so
  `hoist_if_needed` was **never invoked for `abs(...)` at all**, regardless of
  what `self_determined.rs` said. Added `Builtin::Abs` to the allow-list.
- `emit_verilog/kinds.rs::infer_call` — computes mimz's own `Kind` for the
  whole `abs(...)` expression; its `other => panic!(...)` catchall didn't
  handle `Abs` either (would have panicked once the gate above opened). Added
  `Builtin::Abs => Kind { width: infer_kind(&args[0], decls).width + 1, signed: true }`,
  matching the checker's own rule (`checker/widths/ops/builtins.rs`,
  `Ty::Signed(n) → Ty::Signed(n + 1)`).
- `self_determined.rs` — the drafted fix itself, extended to cover `Abs`:
  `Some(Kind { width: self_determined_operand_width(&args[0], decls), signed: … })`
  (Verilog's ternary self-determines at the operand's own width, not mimz's
  grown N+1).

Traced the full call chain by hand for `unsigned(abs(a))` inside a concat
(the review's Repro C) before touching any file, to confirm all three gates
actually compose — `Abs`'s own render arm (`expr.rs:922-927`) needed no change,
the wrap happens one level up in the caller.

**Test-first.** Added 3 regression tests to `tests/self_determined_regression.rs`
(the review's own filed repros, exact vectors): `bug_28_extend_in_concat_matches_icarus`,
`bug_28_extend_in_replication_matches_icarus`, `bug_29_abs_in_concat_matches_icarus`.
Watched all 3 fail against real `iverilog`/`vvp` first (kernel 2575/51/328 vs
Icarus 175/15/168 — matches the review's own ground truth), then the 3-file fix
turned them green. A 4th planned test (`abs` under a bare top-level `$unsigned`,
no concat) was dropped — it passed _before_ the fix, because `$unsigned`'s
argument self-determines correctly on its own; the mismatch only bites when the
result is embedded in a wider position, which the concat repro already covers.
Keeping a test that passes without the fix would have been testing existing
behavior, not the bug.
