## Site: `/learn` + `/handbook` beta sections - W1 plumbing, W3a generator, W3-R reconcile, W3 handbook

Executing `docs/plan/scratch/site-learn-handbook.local.md` (rev 8). Two new site
tabs, both beta: **Learn** (an on-ramp - what an HDL is, the field's history,
Verilog in a nutshell, then a curated path into the existing Guide) and

### W1 - plumbing (site only, 9 files)

- `content.config.ts`: four new collections (`learn`/`learnIndex`/
  `handbook`/`handbookIndex`). Unlike the repo-sourced guide/spec collections
  these are site-local originals and carry frontmatter behind a zod schema
  (`title`/`description`/`order`), which kills the filename-derived title
  mangling `docLabel()` would otherwise do ("02-history-of-hdls" -> "History of
  hdls") and gives each page a real meta description.
- `lib/docs.ts`: new `getNav()` builds the sidebar sections AND the pager
  sequence from one place, so the two can never disagree on ordering. The
  stdlib chapters are deliberately their own sequence - without that split the
  pager walks off `guide/13-hardware-emulation` straight into `stdlib/`, which
  is a different book. `getPager()` matches case-insensitively because some repo
  ids keep source casing (`stdlib/README`) while hub hrefs are lowercase.
- `components/Pager.astro` (new): prev/next at the foot of **every** doc page -
  guide and spec included, which had run 13 and 6 chapters respectively with no
  pager at all. `rel="prev"`/`rel="next"`, both flex cells always rendered so
  "next" stays right-aligned when "previous" is absent.
- `components/Nav.astro`: links defined once and rendered twice (desktop strip +
  mobile drawer) - duplicating the markup would guarantee drift. Below `md` the
  strip collapses into a native `<details>` drawer: no JS, keyboard-accessible
  for free, and safe only because the site is a plain MPA with no
  ViewTransitions (every navigation is a full reload, so it cannot stick open).
  This also fixes a pre-existing overflow - the nav was already tight at 375px
  with five links, before adding two more.
- `components/Sidebar.astro`: now renders from a `sections` prop instead of
  querying collections itself; contextual on `/learn/*` and `/handbook/*` (one
  section plus a cross-link), unchanged elsewhere.
- `layouts/Docs.astro`: the `isSpec` boolean became a prefix->section table
  covering guide/spec/learn/handbook; beta sections append "(Beta.)" to the meta
  description. Injects the author-honesty disclaimer for `/learn` - full box on
  the hub, one-line banner on every chapter - keyed off the section prefix
  alone, so a new chapter cannot ship without it. Banner carries
  `data-pagefind-ignore` so it does not pollute search results.
- `styles/global.css`: `.beta-pill` (outline, not filled; the word "beta" rather
  than a bare "B" glyph, which screen readers handle inconsistently), drawer
  rules, `.notice-strong`, `.notice-slim`.
- Four routes under `pages/{learn,handbook}/` + two content hubs.

Verified in `dist/`, not assumed: `/guide/13-hardware-emulation` has prev and

### W3a - keyword table generator

`site/src/lib/keywords.mjs` reads `lang/keywords.toml` at build time so the
Handbook's keyword chapter cannot drift from the compiler's real keyword set.
Asserts 44 keywords / 12 reserved and throws otherwise; deliberately asserts
**nothing** about the PROVISIONAL count, which shrinks as native review lands
and would otherwise turn linguistic progress into a red site build.

Written as `.mjs` (the pattern `rehype-doc-links.mjs` already sets in that
folder) so its test runs under bare `node` - no TS loader, no framework.
`npm run test:lib`.

The one genuinely tricky rule earns the one test: **a block comment describes
the table BELOW it**. Attributing it to the table above is the obvious reading
and it is wrong - that mistake produced two different wrong PROVISIONAL counts
in this project's own working notes before the parser settled it. Fixture
covers block-marked, trailing-marked, an unmarked table sitting above a marked
block (the trap), and a decoy block after a marked table.

### W3-R - PROVISIONAL set reconciled

The plan assumed `docs/guide/12-cheatsheet.md` over-claimed 5 keywords against
`lang/keywords.toml`. Checking the third reference reversed that:
`spec/03-keywords-trilingual.md` (normative) lists **16** in both its table
column and its prose sections, matching the cheatsheet exactly. `keywords.toml`
was the outlier at 11 - its per-entry markers for `loop`, `sync`, `sim`, `bind`,
`speed` were never added, even though the 2026-08-22 Q7/L7 fix had already
settled the header text on "16 pending spellings".

Fix went into the data file: trailing `# PROVISIONAL - pending native review` on
the `tanglish`/`tamil` lines of those five, matching the marker style already
used by `foreach`/`extern`/`return`. Ten lines, comments only. Nothing in the
compiler reads them (`PROVISIONAL` appears in `crates/` and `src/` only inside
Rust comments), so there is no behavioural surface. All three references now
read 16 and `loadKeywords()` reports 16.

Verification: `cargo test --test grammar_sync --test docs_sync` -> 12 passed.
`npm run test:lib` -> 44 keywords, 12 reserved, 16 provisional.

Lesson recorded in the plan: "which reference is wrong" was not answerable from
the two references the plan happened to name. Check `spec/` before fixing a doc
that disagrees with a data file.

### W3 - Handbook chapters (8)

Written from source, not from the existing docs: CLI surface from `mimz --help`
and each subcommand's own `--help`, the diagnostic catalog from
`mimz explain --list`, the precedence ladder verbatim from
`parser/expr.rs::bin_op`, quirk claims each grepped in `crates/` or `src/`
before being written down.

- 01 keywords - prose plus a build-time generated block. Markdown cannot import
  components, so the chapter opts in via a `generated: "keywords"` frontmatter
  field and `pages/handbook/[...slug].astro` renders `KeywordTable.astro` after
  the prose. Output verified in `dist/`: 44 body rows, exactly 16 daggered as
  provisional, Tamil cells carrying `lang="ta"`, alias and reserved sections
  present.
- 02 syntax, 03 operators, 04 types and widths, 05 diagnostics, 06 quirks,
  07 CLI reference, 08 debug recipes.

Three claims carried in the plan were wrong and were fixed before shipping:

- **E-code family map.** The plan said "E01xx lex ... E12xx imports". Actually
  E10xx is the lexer, E11xx the parser, E12xx the loader, and E0xxx/E13xx the
  checker. Real counts from `explain --list`: 100 E-codes + 3 W-codes.
- **`--emulate`.** The plan said sim blocks are skipped without it. They are
  not - `src/commands/test.rs` constructs the emulation host unconditionally so
  `bind` validation always runs. The flag gates live pacing/redraw, and only
  when stdout is a TTY, so `--emulate` in CI behaves like plain `test`.
- **"Tamil-twin port names".** Nothing of the sort. The twin naming is for
  standard-library MODULE names in `import std.<module>` (`fifo` /
  `varisai` / `<Tamil>`), per E1202. Rewritten as such.

"extern alias order" was dropped: nothing in the source supports it, and an
unverifiable claim has no place in the half of the site that promises accuracy.

**Gap found and documented rather than papered over:** `E1113` is emitted by the
parser (`parser/items/file.rs:195`) but has **no `explain` entry** - the catalog
jumps E1111 -> E1114. Recorded in both ch05 and ch06 with what the code actually
covers (expression nesting depth guard; empty parens on a tag-only enum
variant). Worth a follow-up: add the explain entry.

Build: 37 pages indexed (was 29). Handbook pager verified - `01-keywords` has
prev "Handbook" / next "Syntax", `08-debug-recipes` has prev only. Sidebar
renders Overview + 8 chapters + the "Learn ->" cross-link.

### W3-FIX - every Handbook example compiled, eight were wrong

Before writing the Learn chapters, every code snippet in the Handbook was run
through `mimz check`. Eight syntax claims in the just-shipped ch02 were wrong -
written from the existing docs and from memory of the grammar rather than from
the compiler:

| Wrong                                          | Actual                                                            |
| ---------------------------------------------- | ----------------------------------------------------------------- |
| `module M(clock clk, out y: bits[8])`          | parens hold **parameters**; ports go in the **body**              |
| `State::Idle`                                  | `State.Idle` - a dot                                              |
| match arms `A => B,`                           | newline-separated, no commas                                      |
| `enum Msg { Data(bits[8]) }`                   | payload fields are named: `Data(v: bits[8])`                      |
| `Point { x: 1, y: 2 }`                         | `{ x: 1, y: 2 }` - the type name is not repeated                  |
| `Adder(W = 8)(a: x, b: y)`                     | `Adder(WIDTH: 8) { a: x, b: y }` - braces for connections         |
| `test Counts for M { tick clk }`               | `test "name" for M { tick(clk) }` - quoted name, `tick` is a call |
| `repeat 4 { }`, top-level `sim { speed 1khz }` | `repeat i: 0..4 { }`; `sim` lives inside a test; `speed mhz(50)`  |

Two more things learned rather than assumed: `fn add3(a, b, c: bits[8])` returns
`bits[10]`, not `bits[8]` (`E0804`) - lossless growth applies to the declared
return type too; and `extern module` does support the alias form
`extern module Pll = "PLL_HARD_IP_v2" { ... }`, which had been dropped earlier as
unverifiable. It was real - only the shape guessed for it was wrong.

The `explain` gap also turned out bigger than first reported: **three** emitted
codes have no entry, not one - `E0904` (bundle destructure field rename),
`E1112` (`syntax` names an unknown grammar profile) and `E1113`. Each is covered
by a test in the compiler's suite. (`E9999` appears in a grep but is only a
negative-test sentinel asserting `explain` returns none.)

Rule for future content waves: compile the snippet, then write the sentence.
Prose about a grammar cannot be verified by reading other prose about it.

### W5 - Downloads restructure

Requested after the plan was otherwise closed. `/downloads` was a single page
stacking every release; it is now a small section of its own.

| Route                 | Shows                                                 |
| --------------------- | ----------------------------------------------------- |
| `/downloads`          | the latest release only - the "get the compiler" page |
| `/downloads/releases` | every release as a scannable list, newest first       |
| `/downloads/<tag>`    | one superseded release (generated for past tags only) |

The latest tag deliberately gets no `/downloads/<tag>` page - `/downloads` is
it, and the all-releases list routes the newest row there, so each release has
exactly one canonical URL.

- `lib/releases.ts` holds the hand-maintained array (still hermetic - no
  build-time GitHub API call) plus `latest`/`history`/`historyPreview` and URL
  helpers. Adding a release is now ~6 lines in one file rather than an edit
  inside page markup.
- `DownloadsSidebar.astro`: **Latest**, then **History** (3 most recent past
  releases) and "View all releases". Visible at every width - it is short, so it
  stacks above the content on mobile instead of disappearing the way the docs
  sidebar does.
- `ReleaseAssets.astro` carries the card grid + checksum link for all three
  pages, with a `variant` prop.

**The latest/history divergence** (specifically requested): a per-release page
is not the latest page with different numbers. The jobs differ, so the hierarchy
is inverted - on an old release the loudest element is the route back to
current, not the downloads.

|                 | `/downloads`                         | `/downloads/<tag>`                                  |
| --------------- | ------------------------------------ | --------------------------------------------------- |
| Pill            | filled accent `latest`               | outlined muted `superseded`                         |
| Loudest element | the download cards                   | the route back to current                           |
| Primary CTA     | -                                    | `Get <latest> instead` + `What changed since <tag>` |
| Asset cards     | `primary` - accent icons, hover lift | `archive` - neutral, flat                           |
| Heading         | "Downloads"                          | "Download `<tag>` anyway"                           |
| Install         | `cargo install --git ... mimz`       | `--tag <tag>` pinned, with the reason               |
| Extras          | install-from-source, history link    | breadcrumb, notes, GitHub compare                   |

The archive styling is the point: an old-version page must not _look_ like a
recommendation, while still delivering the binaries the visitor came for.

The old page's `is:global` `bg-bolt-400` helpers moved into `global.css` now
that three pages share them.

Learn ch04's install section now opens with the Downloads page (and the history
list, for pinning an older version) instead of sending first-timers to GitHub.

Verified in `dist/`: latest page has the filled pill, no superseded notice, an
unpinned install command and no v0.1.0 assets; the v0.1.0 page has the
superseded pill, the notice + `Get v0.2.0 instead` CTA,

### W5b - "What changed" renders the changelog, not a GitHub diff

The `What changed since <tag>` button used to navigate away to a GitHub compare
view. It now jumps to an on-page section rendering that release's `CHANGELOG.md`
entry, with the GitHub diff kept as a secondary link below it.

- `lib/changelog.ts` splits `CHANGELOG.md` on its `## [x.y.z] - ...` headings at
  build time. Tags are `v0.2.0` and headings are `[0.2.0]`, so the `v` is
  stripped on lookup; a missing file degrades to the GitHub links instead of
  failing the build.
- `Changelog.astro` renders with `createMarkdownProcessor` from
  `@astrojs/markdown-remark` - already a dependency, so no new package.
  Highlighting is off: the changelog has zero fenced code blocks, so enabling it
  would only add a second syntax theme fighting the site's own. `.prose` styles
  the output.
- Headings are demoted one level (`###` -> `####`) so the entry nests under the
  page's `h2`; verified one `h1` per page.
- On a superseded release, "what changed **since** v0.1.0" is the next release's
  entry, so that page renders the v0.2.0 section under that heading and offers
  `Compare v0.1.0 -> v0.2.0 on GitHub` beside it. The latest page shows its own
  entry with a plain release-notes link.

**Leading maintainer blockquote stripped from the rendering.** The v0.2.0 entry
opens with a `> **Tag pending** ...` aside aimed at whoever cuts the release,
which read as internal chatter on a public downloads page.
`stripLeadingNote()` drops a blockquote sitting at the very top of an entry.
`CHANGELOG.md` is deliberately not edited - the reminder stays where it is
useful and only the site's rendering changes.

Verified: `Tag pending` no longer appears on either page, both entries still
render in full (`sync.double_flop` present), compare link and label correct, CTA
is an in-page anchor, `astro check` 0 errors / 0 warnings.
