# 2026-09-05

## IR: `Shl` sizes exactly for a compile-time-constant shift amount (GAP-1 residual, task 1 of 6)

Follow-up to the 2026-09-04 GAP-1 fix round's own residual note: fixing
`Shl`'s truncation bug that day made `ir::lower` size `out` at worst-case
growth unconditionally, which is always safe but strictly wider than the
checker's own exact `a.width() + k` formula whenever the shift amount is a
compile-time constant — leaving `(a << 2) & c` failing `ir::validate` with a
`WidthMismatch` even though both sides type-check individually.

`lower_binop` gained a `shl_const_amount: Option<u128>` parameter (only
meaningful for `BinOp::Shl`). Its one call site (`ExprKind::Binary` in
`lower_expr`) const-evals the source `rhs` `Expr` via `crate::value::
const_eval` against `design.consts` when `op == BinOp::Shl`, converting a
successful non-negative result to `u128` (`try_from`, falling back to `None`
rather than panicking on the never-expected negative/overflow case) — the
same resolution `checker/widths/ops/mod.rs::shift_ty` and `value/binary.rs::
eval_shift_chain` already use. A genuinely runtime shift amount still passes
`None` and keeps the worst-case fallback unchanged (pinned by the existing
`shl_grows_the_output_to_the_worst_case_width_not_the_input_width` test,
untouched).

`ir::validate`'s independent `Shl` width formula (`expected_widths`) was
still hardcoded to `None` and would have started disagreeing with
`lower_binop`'s new exact sizing the moment a constant-shift program was
lowered — caught by actually running the new fixture before assuming the
brief's file list was complete. Added `shl_const_amount(module, driver, b)`:
when `b` is driven entirely by one `Const` cell (the shape `ir::lower`
produces for a literal/const-name shift amount), it reads that cell's value
back and passes it through the same `width_rules::shift_result` call, so the
two independently-computed formulas agree again. Anything else (a runtime
`b`, a constant reached only indirectly, or one too wide for `u128`) falls
back to `None` — the safe/wide side.

Corrected the stale `lower_binop`/`Shl`-arm comment and doc comments in
`ir/exec.rs`'s "v1 limitations" list that both claimed `lower_binop` "cannot
know" or has no access to the compile-time-constant fact — no longer true.

New tests (+2, both `crates/mimz-core/src/ir/tests/lower_binops.rs`):
`shl_with_a_compile_time_constant_amount_sizes_exactly_not_worst_case`
(`a: bits[2] << 2` sizes `y` at 4 bits, not the worst-case 5) and
`shl_result_feeding_a_matched_width_cell_validates_cleanly_when_amount_is_constant`
(`(a << 2) & c`, the exact repro from the gaps.md residual, now validates
clean). Test count 1404 → 1406 in `docs/code/10-test-map.md` and the README
