# 2026-09-01

## Phase 2 IR: Step 0 (elaborate/value/comb/diag promotion)

Documented the crate-boundary move landed by Tasks 1-2 of the Phase 2 IR
plan (`docs/plan/phase-2-ir-plan.local.md`): `docs/architecture.md`'s
component table, code-layout tree, and crate-boundary prose now reflect
`elaborate`/`value`/`comb` and the S0xxx runtime-diagnostic catalog
(`ALL_SIM_CODES`, `bridge_code`, `diag_from_bridged`) living in
`mimz-core` rather than `mimz-sim`. `mimz-core::diag` now holds both the
E-code checker catalog and the S0xxx catalog; `mimz-sim/src/sim/diag.rs`
is a thin re-export shim (the same pattern already used for `sim/wide.rs`
→ `mimz_core::wide`).

### Decision: promote elaborate/value/comb from mimz-sim to mimz-core

- **Context:** Phase 2 IR lowering needs the same AST-flattening
  (instance flatten, repeat unroll, enum encode) that `mimz-sim`'s
  `elaborate` module already does. Depending on `mimz-sim` from a new
  IR module would put a backend concern behind a simulator dependency
  (wrong direction); reimplementing flattening a second time would
  duplicate ~4000 lines.
- **Decision:** Move `elaborate/`, `value/`, `comb.rs` from
  `crates/mimz-sim/src/sim/` to `crates/mimz-core/src/`, with `mimz-sim`
  re-exporting them for zero caller churn.
- **Why:** `elaborate/` was already structurally pure (no fs/OS deps, no
  simulator-kernel deps) — it only touched `value`/`comb` for constant
  folding. Moving it makes both `mimz-sim`'s kernel and the new
  `mimz-core::ir` module consume the same `Design` type without either
  depending on the other.
- **Impact:** `crates/mimz-core/src/{elaborate,value,comb.rs}`,
  `crates/mimz-sim/src/sim/mod.rs`, `docs/architecture.md` (component
  table + code layout tree).

The S0xxx runtime-diagnostic catalog moved alongside `elaborate`/`value`/
`comb` in the same pass: `ALL_SIM_CODES`, `bridge_code`, and
`diag_from_bridged` moved from `mimz-sim/src/sim/diag.rs` into
`mimz-core/src/diag.rs`, which already held the E-code catalog
(`ALL_CHECKER_CODES`). `mimz-sim/src/sim/diag.rs` is now a thin
re-export shim.
