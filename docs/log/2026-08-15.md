### The central judgment: rule (a′) is a better rule aimed at the wrong object

Classified six arms independently before reading the codebase's own verdicts —
**disagreed on four**. `Ident`, `Bool` and `Encoding` all rest on facts about
what the **emitter renders**, which is exactly the question the module doc says
to ask and a category (a′-2)'s enumeration (checker rule / grammar restriction /
lowering pass) does not admit; applied literally the rule rejects the axiom
(a′-1) itself depends on. The two (a′-2) citations that _are_ code-named were
triggered and are genuine (E0407 for `clog2` in a value position, E0403 for an
enum in a concat; E0405 likewise for a bare literal).

An independent re-run of Task 5's own keyword grep surfaced one hit its
"every hit, not a sample" sweep missed: `builtin_self_determined_coverage`'s
`Trunc` arm — _"already exactly N bits regardless of position, so `None` needs no
recursion proof"_, cited to `trunc(a, 2)`, a bare identifier. It is also false:
`trunc(extend(x,8), 2)` inside a `fn` emits `(x)[(2)-1:0]`, an Icarus syntax
error.

Sorted by where the defect actually was, **10 of the 14 instances since round 3
are call-site or plumbing defects**; the last arm defect was BUG-52, two rounds
ago. Round 5's own BUG-60 fix says it: _"the classifier arms stay `None`,
unchanged … only the render call site needed the hoist."_ Filed as
[GAP-17](../audit/gaps.md).

### The seventh instance — the widest in the series

Filed as [BUG-62](../audit/bugs.md) (CRITICAL, 10 repros),
[BUG-63](../audit/bugs.md) (HIGH), [BUG-64](../audit/bugs.md) (HIGH), and
[GAP-16](../audit/gaps.md).

`cur_decls` is built once per module and is `infer_kind`'s only data source, and
every hoist site renders unchanged when `infer_kind` returns `None`. Three
emitter contexts therefore run the whole machinery blind — `fn` bodies (params
never inserted), testbench bodies (`cur_decls: Default::default()`), and any
`extend`/`trunc` whose width argument is a module `parameter`
(`const_fold(&args[1])?`). Consequences, all `mimz check` OK and `mimz compile`
exit 0:

```text
fn packit(x, b) -> bits[12] { { b, extend(x, 8) } }   mimz 2575  Icarus 175   ← BUG-28, live
fn allset(x) -> bit         { &extend(x, 8) }         mimz 0     Icarus 1     ← BUG-60, unfixed in fn scope
fn topbit(x) -> bit         { extend(x, 8)[7] }       syntax error
fn lowbits(x) -> bits[2]    { extend(x, 8)[1:0] }     syntax error
fn low2(x) -> bits[2]       { trunc(extend(x,8), 2) } syntax error
module Fuzz(W: int = 8)     { y = { b, extend(a, W) } } mimz 2575 Icarus 175
expect &extend(y, 8) == 0   (clocked test)            mimz test PASS, testbench FAIL
expect extend(y, 8)[7] == 0                           testbench does not parse
```

When a `fn` param _does_ collide with a module signal name the hoist fires at
module scope, reads the module's signal instead of the argument, and is emitted
after the function that references it — `Unable to bind wire/reg/memory
'__mimz_sub_1' in 'tb.dut.pack'` (BUG-63).

Separately (BUG-64): **3 of the 6 shipped examples with `test` blocks emit a
testbench that reports FAIL on a correct design** — `shift`, `tested_adder`,
`enum_encoding`, all combinational. BUG-51's fix made every stimulus drive
non-blocking; with no `tick` nothing advances time, so the `expect` reads the
pre-drive value. The suite never noticed because
`every_emitted_testbench_passes_iverilog` asserts only that the emitted testbench
**elaborates**. The vacuous-PASS variant of the same race is the more dangerous
one — a check that never observed the stimulus and printed PASS.

Why no instrument saw any of it: the fuzz generator emits exactly one trivial
`fn` per program (`fn identW(x) { x }`, `differential_fuzz.rs:1086`) and no
module parameters at all, so both regions are unreachable by the grammar at any
depth. Round 5's clean gate was value-blind; round 6's is **scope**-blind.

Two smaller findings: round-5 Task 4's reduction bias is unconditional, so
`nand(<bare port>)` — the shape all four flavours of `bitops.mimz` use — is now
unreachable by the generator; and BUG-60's filed prose ("no shipped example uses
a reduction") is false, four do.

## Round 6 plan — Tasks 1–3 done, Task 4 partial

Implemented same day as the plan was written.

- **Task 1 (GAP-16).** New `hoist_unresolved` (`emit_verilog/module/ports.rs`)
  is the single routing point every hoist call site's `None` arm now goes
  through instead of returning text unchanged — `debug_assert!`s
  unconditionally, and pushes a real `Diag` for the slice/bit-select/`trunc`-
  base positions whose grammar needs a named identifier. Two categories were
  deliberately exempted, each backed by a pre-existing code citation rather
  than routed through the loud path: comparison operands (Verilog's own
  auto-widening makes an unresolved parameter-driven operand harmless) and
  `hoist_width_effect_operand`'s own internal fallback (BUG-30's documented
  "over-growth is always safe" case). Both exemptions were found the hard way
  — the first pass asserted unconditionally and broke `shift.mimz`/
  `std/fifo.mimz`'s goldens; caught by a full workspace run before landing.
- **Task 2 (BUG-62(a)).** `render_fn_decl` and `emit_testbench` now build and
  install a real `cur_decls` instead of the enclosing module's map / an
  always-empty one. Verified against real Icarus: `fn packit`/`allset`/
  `nandit` now compute the correct value (`y = 2575`, not 175). Two follow-on
  bugs surfaced by this fix, both closed same-session:
  - A hoist that fires inside a `fn` body tries to declare a module-scope
    `wire`, which a `function automatic` cannot legally reference forward
    (confirmed against real `iverilog`) — this is BUG-63's own error,
    reached through a genuinely-needed hoist rather than a name collision.
    New `in_fn_body` flag on `Emitter`; both hoist functions diagnose instead
    of emitting invalid Verilog when it's set. Real fix (function-local
    `reg`-based hoisting) is follow-up work, filed under Task 4.
  - `emit_testbench` never flushed `self.hoisted_decls` into the emitted
    testbench text at all — every hoisted wire a `Drive`/`expect` needed was
    silently dropped. Confirmed against real Icarus that a wire referenced
    from an `initial` block before its own declaration is "declaration after
    use" even at plain module scope (not only inside a `function`, contrary
    to this plan's own working assumption) — fixed with the same
    `insert_str`-at-a-saved-position `module()` already uses, reset per test.
- **Task 3 (BUG-62(b)).** Option (b) from the plan: a new
  `try_widen_symbolic_extend` (`expr.rs`) renders `extend(x, W)` as an
  explicit `{{(W-N){fill}}, x}` when `W` doesn't const-fold, tried from each
  self-determined-position call site's own `None` arm before falling through
  to `hoist_unresolved`'s diagnostic. Verified against real Icarus at the
  default width, an override, and a signed variant (correct sign-extension).
  First attempt folded this into `Builtin::Extend`'s own render arm
  unconditionally, which fired even at ordinary context-determined positions
  where the old passthrough was already correct — rewrote `shift_register`'s
  golden with no correctness benefit; caught by the full suite, moved to the
  narrower call-site-scoped form.
