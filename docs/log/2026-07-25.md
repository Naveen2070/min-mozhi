# 2026-07-25

## BUG-13 layer 2 — arbitrary-width compile-time constants

`docs/superpowers/plans/2026-07-25-const-literal-wide-values.local.md`
(design: `docs/superpowers/specs/2026-07-25-const-literal-wide-values-design.local.md`),
all 10 tasks landed as `wip:` commits per-task (`bug-13-layer2` branch).
Closes the "Remaining gap (layer 2)" `bugs.md` explicitly left open when
layer 1 (2026-07-22) shipped wide *runtime* values but left compile-time
constants (literals, `const`, `Reg.reset`, `Mem.init`) capped at `i128`.

`Bits` and its limb arithmetic (`wide.rs`) relocated from `mimz-sim` into
`mimz-core` (Tasks 1-2) so the lexer/AST/checker could share the same
representation. `ExprKind::Int`/`Pattern::Int`/`TokKind::Int`'s literal
value became `Bits` (Task 3), with ~80 mechanical construction-site
fallouts across the codebase (Task 4). Signed shrink/grow helpers (Task
5) and a full `consteval.rs` rewrite around a new `ConstVal {bits, width,
signed}` (Task 6) followed — const-eval's arithmetic now grows to a safe
upper-bound width before shrinking to natural width and checking against
`width_rules::MAX_WIDTH` (1,000,000 bits), instead of `i128`'s ~127.

Tasks 7-9 turned out to be substantially larger than the plan estimated
(each documented in its own commit, same "scope grew" pattern the
original plan's own Task 4/6 commits already set precedent for):

- **Task 7** (`checker/widths/*`): `Ty::CtInt(i128)` → `Ty::CtInt(ConstVal)`
  meant `Ty` could no longer derive `Copy` (`ConstVal` may hold a
  `Vec<u64>`) — every `.copied()` became `.cloned()`, plus explicit
  `.clone()` at every value reused across loop iterations or after being
  passed to a sibling call.
- **Task 8** (`mimz-sim`): `Reg.reset`/`Mem.init` → `ConstVal`. Deviated
  from the plan's literal instruction to change the shared `const_eval`
  helper's signature/return type — that function is called from ~25 sites
  for widths/depths/indices/repeat-bounds, none of which need arbitrary
  width; kept its exact original signature (bridges to the checker's
  `Env` internally) and added a narrow sibling `const_eval_wide` used only
  at the two reset/init construction sites.
- **Task 9** (`emit_verilog`): the same `Env`/`ConstVal` type change from
  Task 6 broke ~20 *other* `consteval::eval` call sites across
  `emit_verilog/{mod,expr,module,testbench}.rs` that Task 6 explicitly
  deferred — bridged each the same way as Task 8. This is also the point
  `cargo test --workspace --all-targets` (not just `cargo build -p
  mimz-core`) finally ran clean again, which surfaced:
  - a **real, pre-existing arithmetic bug** in `consteval.rs`'s sign
    detection: `Add`/`Sub`'s `+1`-bit growth headroom (and `Mul`/`Shl`'s
    original *no* extra headroom) is only safe for already-signed n-bit
    inputs — an unsigned literal at its own tight width can produce a
    sum/product/shift whose own top bit is legitimately set without the
    true result being negative (e.g. `(2^127-1)+(2^127-1)` needs exactly
    128 bits). Surfaced as `examples/english/shift.mimz`'s `1 << 3`
    failing E0405. Fixed: `Add`/`Sub` now grow by `+2`, `Mul`/`Shl` by
    their tight magnitude bound `+1`.
  - the mirror bug in `emit_verilog`'s enum-payload masking (introduced
    in this same task): a negative payload value needs sign-extension to
    its field width before masking, not a zero-padding limb reshape.
  - ~20 more mechanical `Bits`/`ConstVal` construction-site fixes in
    test-only code across `ast/`, `emit_verilog/kinds.rs`,
    `lexer/tests.rs`, `parser/tests.rs`, and `mimz-sim`'s `value.rs`
    (including one more real bug: `eval_ctx`'s `ExprKind::Int` arm was
    still hard-truncating a runtime literal to `i128`).
  - 3 tests whose fixtures tested the *old* ~127-bit ceiling and needed
    updating now that it moved to 1,000,000 (`tests/eval.rs`'s two
    "does not panic" tests, `checker::tests::const_overflow_is_e0202`).

**Task 10** (this entry): `tests/differential_fuzz.rs`'s clocked-module
generator only ever synthesizes `= 0` register inits (confirmed via
source read, matching layer 1's own "Remaining gap" note) — no generator
change needed. Added one full-pipeline end-to-end test
(`tests/sim.rs::a_wide_const_folds_through_the_full_pipeline_and_matches_a_wide_reset`)
proving a >128-bit `const` folds identically as both a register reset
value and a runtime comparison operand. `docs/audit/bugs.md`'s BUG-13
entry updated: heading drops "— layer 1", new closing paragraph documents
the layer-2 fix and the headroom bug found along the way.

`cargo test --workspace --all-targets`: green (mimz-core 606+ tests,
mimz-sim 155, every integration suite). `cargo clippy --workspace
--all-targets`: clean. `cargo fmt`: applied.
