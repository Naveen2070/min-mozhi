# 2026-09-03

## Phase 2 IR — Task 16: IR executor (`ir/exec.rs`)

- **Context:** the IR (`mimz_core::ir`) could be lowered, printed, parsed
  and validated, but nothing could RUN it. Task 18's differential test
  needs an IR-level interpreter to compare against `mimz-sim`'s AST-level
  kernel, and each cell kind needs a unit-testable evaluator of its own.
- **Decision — reuse the AST evaluator's own operators instead of a second
  copy.** `crate::value::binary::{binary_ctx, unary}` already implement
  every `BinOp`/`UnOp`'s exact semantics (masking, lossless growth,
  wrapping, the fused shift rule, comparisons, reductions) plus
  X-propagation and wide-value arithmetic. Both were `pub(super)`; they are
  now `pub(crate)` and re-exported as `crate::value::{binary_ctx, unary}`
  (the `binary` module itself stays private). 25 of the 30 `CellKind`
  variants are therefore a one-line dispatch. A rejected operand pair means
  `lower` produced malformed IR, so `exec` panics rather than propagating a
  `Diag` — this is a test tool, not an end-user path.
- **`get_bits` returns a whole-value `Val::unknown` if ANY of a pin's nets
  is undriven.** `Val`'s taint is coarse (its own doc: "coarse whole-value
  taint"), and a per-bit reconstruction would silently turn an undriven net
  into a real `0`. The direct payoff: `CellKind::BlackBox` needs NO arm in
  `eval_comb_cell` at all — an extern instance's output nets are simply
  never written, so they read back as X, matching `mimz-sim`'s `Warn`-mode
  extern-output semantics with zero special-case code. `set_bits` is the
  mirror image: an X-state value REMOVES its nets rather than inventing a
  second representation of "unknown".
- **`get_output` falls back from ports to named nets.** `lower()` only
  pushes `design.inputs`/`outputs` into `module.ports`, so a plain wire
  (e.g. `adder_design`'s `sum`) is never a port. Missing name → collect
  every `NetInfo.name == name` net in `module.nets` order, which is
  LSB-to-MSB because `alloc_bits` always allocates one signal's bits as a
  single increasing run.
- **Memory storage is sparse (`HashMap<addr, Val>` per cell), not a
  `depth`-length `Vec`.** This mirrors `mimz-sim`'s kernel exactly
  (`mem_cells: BTreeMap<(String, u128), Val>` + "an unwritten or
  out-of-range cell reads the memory's init value"), which is what makes
  the differential baseline fair; it also means a large `depth` costs
  nothing to construct. Same observable semantics as a pre-seeded `Vec`.
  Writes commit only in `tick()` (captured after settling, applied after),
  and a write past the end is dropped — again matching the kernel. A ROM
  needs no special case: `lower` ties its `wen` to a constant 0.
- **`tick()` settles, commits, then settles again**, so everything
  downstream of the new register/memory contents is consistent on return.
  Documented v1 limits: unsigned-only (`ir::Bits` carries no signedness),
  one global tick (the IR has no module-level clock list; clock identity
  lives per-`Dff`/`Mem`), and `get_bits`/`set_bits` panic loudly above 128
  bits rather than truncating — `binary_ctx`/`unary` handle wide VALUES
  internally, so only per-bit net reconstruction is deferred.
- **`Concat`/`Slice` are never emitted by `lower()`** (both are pure `Bits`
  re-pointing at lowering time, Task 6 — verified directly). Their arms
  exist only so a hand-written / round-tripped IR text file using them
  still executes; `Concat` joins its non-`out` pins in `BTreeMap` key
  order, LSB pin first — this executor's own convention, since nothing
  produces such a cell yet.
- **Tests:** 8 new in `crates/mimz-core/src/ir/tests/exec.rs` — adder
  (also covers the wire-vs-port `get_output` fallback), `Const` + `Add`,
  unary `Not`, `Mux` on both selector values, a register across two ticks
  (Q unmoved by driving `d` alone), a memory write that commits only at the
  edge, a never-written ROM cell reading its `init` seed, and a `BlackBox`
  output reading as X. Fixtures reused from the lowering tests
  (`unary_design` promoted to `pub(super)`).
- **Docs sync:** `docs/code/10-test-map.md` and the README badge moved
  1364 → **1372**.

**Impact:** `crates/mimz-core/src/ir/exec.rs`,
`crates/mimz-core/src/ir/tests/{mod.rs,exec.rs (new),

## Phase 2 IR — Task 16 fix round 1

- **`Module::signals` (new field):** `BTreeMap<String, Bits>`, the exact
  source-name → `Bits` table, populated by `lower()` from its own
  `ctx.resolved` (plus `ctx.mem_read`'s read ports). `exec::get_output` now
  looks names up here instead of scanning `module.nets` by name.
- **Why a schema change rather than a guard.** Review asked for a
  contiguity assert on the old name scan. Traced it: it fails in BOTH
  directions. `wire w = {p, q + 1}` names only the `q + 1` half `w`, and
  those 9 nets ARE contiguous — the guard passes and the wrong half is
  still returned silently. `wire w = {p + 1, q + 1}` names all of `w`'s
  nets correctly, but the two `Const` nets sit between the halves — the
  guard would panic on a right answer. The name scan is unfixable because
  `lower` only stamps a wire's name onto its driver's still-UNNAMED nets;
  the width a signal should have simply isn't in `nets`. Recording the
  table `lower` already has removes the whole class instead of guarding one
  shape of it, and deletes the heuristic.
- Side effect: a wire whose driver is a bare `Ident` (no nets of its own,
  e.g. `u_clk_in` in the blackbox fixture) is now addressable, so that
  test's workaround came out.
- Text format still doesn't round-trip `signals` — same stated v1 boundary
  as `extern_decls`; a parsed IR module is addressable by port name only,
  and `get_output`'s panic says so.
- **Shl/Shr divergence documented durably** in `exec.rs`'s limitations block
  and as an open sub-gap under `docs/audit/gaps.md` GAP-1 (three-fold: pin
  truncation, structurally absent `const_amount`, and un-refusable fused
  chains). `Dff`'s ignored `edge` folded into the "one global clock" line.
- **Docs sync:** 1372 → **1373** (one new regression test).

**Impact:** `crates/mimz-core/src/ir/{mod.rs,lower.rs,parse_line.rs,exec.rs}`,
`crates/mimz-core/src/ir/tests/{exec.rs,validate.rs}`, `docs/audit/gaps.md`,

## Phase 2 IR — Task 18: IR-vs-kernel differential (invariant 5)

- **Goal:** a third leg for `tests/differential_fuzz.rs` — random programs
  evaluated by `ir::lower` + `ir::exec` and compared, cycle for cycle,
  against the values the existing kernel-vs-Icarus legs already produce.
- **Finding (measured, and it changed the plan): `ir::lower` cannot lower
  the existing generator's programs at all — 25 seeds out of 25 skipped.**
  `lower_expr` has no `ExprKind::Call` arm, so every builtin (`extend`,
  `trunc`, `signed`, `unsigned`, `abs`, `min`/`max`, `nand`/`nor`/`xnor`)
  hits its catch-all `unimplemented!("expression form not yet lowered by
Task 5/6")`. That is fatal for `gen_clocked_module` specifically, because
  `extend(x, N)` **is** its width machinery (`widen`, `clamp`'s fallback,
  every non-port leaf, `force_width`, `wrap_builtin`), and `extend(1, N)` is
  the only way to give a literal a width at all (`concat_ty`'s own E0405
  hint says so) — so there is no builtin-free way to write a sized constant
  either. Bolting the leg onto that generator would have been a leg that can
  only ever skip: green, and covering nothing.
- **Decision — a second, IR-scoped generator instead of narrowing the
  shared one.** `gen_ir_clocked_module` emits clocked programs at ONE width
  for the whole module (`w`, always even) and unsigned throughout, so every
  fragment is closed under composition with no `extend`/`signed`/`unsigned`
  anywhere. Reaches `And`/`Or`/`Xor`/`Not`, `AddWrap`/`SubWrap`/`MulWrap`,
  `Eq`/`Ne`/`Lt`/`Le`, `Mux` (via both `if` and `match`), `Concat`, `Slice`,
  `Const`, `Dff` + its reset mux, and `exec`'s two-phase `settle`/`tick`
  commit over 1-3 registers. Keeping it separate leaves the two Icarus legs
  and their seed spaces untouched.
- **Every exclusion is an already-ruled v1 limitation, enforced by
  construction:** `signed` (unsigned-only `ir::Bits`), `<<`/`>>`
  (`gaps.md` GAP-1 sub-gap), `>`/`>=`/`&&`/`||` (unlowered in
  `lower_binop`), lossless `+`/`-`/`*` (they grow), `mem` (one read port per
  memory, and `lower` compares LOWERED nets so even two textually identical
  `m[0]` reads trip it), and every builtin call. Because the subset is
  structural, the new test needs no `catch_unwind`, no skip counter and no
  "known divergence" escape hatch — every generated program must lower,
  validate, execute and agree, or it fails.
- `differential_fuzz_clocked_ir_matches_kernel` is deliberately NOT gated on
  `require_iverilog()`: the kernel's own `Timeline` is the oracle, so the
  axis keeps its coverage on a machine with no Icarus, where both existing
  legs skip outright. Depth knob `MIMZ_DIFF_FUZZ_IR_N` (default 20).
- `ir_fuzz_generator_reaches_every_lowerable_construct` guards the failure
  mode a narrowed grammar invites — degenerating to bare leaves and staying
  "green" while exercising no cell at all.
- **No divergence found.** The IR executor agreed with the AST kernel on
  every value of every cycle across the whole run; no product change was
  needed.
- **Bias found in the shared `Rng` while building this.**
  `Rng::next_range` reads the LCG's LOW bits; the update is
  `x * <odd> + <odd>`, so bit 0 strictly ALTERNATES and bit 1 has period 4.
  A 4-way `next_range(4)` comparison pick produced ZERO `<=` across 500
  programs — one arm of a four-arm choice was structurally unreachable.
  Caught by `ir_fuzz_generator_reaches_every_lowerable_construct`, which is
  exactly the failure it exists for. Fixed LOCALLY (a `pick()` helper taking
  the high bits) rather than in `Rng`: changing `next_range` would renumber
  every program the two Icarus generators emit and invalidate both
  fuzz-seed regression corpora (GAP-11's whole point). Worth its own task —
  the same bias is latent in every `next_range(2)`/`next_range(4)` call the
  older generators make.
- **Docs sync:** 1379 → **1381** (two new tests; the page and badge were
  also stale at 1373 — `docs_sync` re-derives the real number).

**Impact:** `tests/differential_fuzz.rs`, `docs/code/10-test-map.md`,
`README.md`.

## Phase 2 IR — Task 18 fix round 1

- **All three findings given a durable home in `docs/audit/gaps.md`**, per
  this repo's own convention (Task 16 put its Shl/Shr divergence there for
  the same reason). A dated log entry and an ephemeral task report are not
  where a finding of this weight lives.
  - **New GAP-1 sub-gap: `ir::lower` cannot lower a builtin call.**
    `lower_expr` has no `ExprKind::Call` arm; only `ExprKind::FnCall`
    (Task 9's user-`fn` inliner) is handled. Stated in the terms that
    matter: since `extend(1, N)` is the only way to size a literal at all
    (`concat_ty`'s own E0405 hint), **no sized constant survives lowering**,
    and neither does any width/kind conversion — which is why ~100% of the
    project's own existing clocked fuzz corpus is unlowerable (25/25
    measured) and why Task 18 needed a narrowed second generator. Records
    that `gen_ir_clocked_module` should be DELETED and the leg folded back
    into the clocked Icarus loop once this closes.
  - **Riding along in the same sub-gap:** Task 10's single-read-port memory
    limit is reachable by an EXISTING generator (`gen_clocked_module`
    already emits `mem`), and it compares lowered nets so two textually
    identical `m[0]` reads also trip it. Previously assumed hypothetical.
  - **New GAP-10c: the differential fuzzers' PRNG low-bit bias.** Named the
    mechanism (odd multiplier + odd increment ⇒ bit 0 alternates, bit 1 has
    period 4) and the cost of fixing it (renumbers
    `tests/fixtures/fuzz-seeds/{comb,clocked}.txt`), so the follow-up is
    understood as a deliberate hit, not a drive-by. Filed under GAP-10
    rather than GAP-11/13 — those are CLOSED, and this is a coverage hole no
    CI depth can close, which is GAP-10's own subject.
- **Three review-suggested generator improvements taken** (each closes a
  blind spot rather than adding surface):
  - Held input stimulus now draws from the high bits too — it was still
    using the very low-bit source `pick()` exists to avoid.
  - Reach guard is now **one marker per operator, never per family**: `&`,
    `|`, `^`, `==`, `!=`, `<`, `<=` are each checked separately. A
    family-level check cannot see one arm of a multi-way choice going
    unreachable, which is precisely the failure that produced zero `<=`.
    Markers are space-delimited so `" < "` cannot match inside `" <= "` or
    the `" <- "` of a register assign.
  - **Registers now reset to a RANDOM value, not a hardcoded `0`.** The
    reset constant is lowered by `lower_const` into its own
    `CellKind::Const`, separately from the reset-select `Mux` around it — an
    all-zero corpus exercised the mux while leaving a wrong constant
    invisible.
- Re-verified: `differential_fuzz` 8 passed, `docs_sync` 6 passed, clippy
  clean, and a 1000-seed deep run of the regenerated corpus.
- No product change; nothing under `crates/` touched by this task.

**Impact:** `docs/audit/gaps.md`, `tests/differential_fuzz.rs`,
`docs/log/2026-09-03.md`.
