# 2026-08-07

## GAP-7 closed — `encoding(e)` enum→bits cast

The last open language-surface item from `review-2026-08-02.md`'s v0.2
scope. Added `encoding(e)`, a builtin that reads out an enum value's
stable on-wire bit pattern (tag, or tag+max-payload for a tagged union)
as plain unsigned `bits[N]` — the gap's own Direction recommendation over
extending `unsigned(x)`, to keep "conversions are visible" honest.

`Builtin::Encoding` joins the existing plain-identifier builtin table
(`from_name`) — not a keyword, so unlike GAP-6 this needed no
`lang/keywords.toml` entry, no Tanglish/Tamil spelling, no native-speaker
review. The checker requires `Ty::Enum` and returns
`bits(en.inferred_total_width)`; everything else raises a brand-new
`E0418`. The emitter and simulator needed zero enum-specific logic at
all — an enum-typed signal is already tracked as a generic
`Kind{width, signed}` at that layer, so `encoding` reuses `unsigned(x)`'s
exact mechanism byte-for-byte in every exhaustive `Builtin` table it
joins (`self_determined.rs`, `kind_is_inferrable`, `infer_call`, codegen,
and `mimz-sim`'s `eval`).

### Decision: allocate `E0418` for `encoding()`'s type-mismatch rule

- **Context:** `encoding()`'s "argument must be an enum" rejection is a
  distinct rule from any existing code — the closest existing candidate,
  `E0407` ("builtin misuse"), covers width-shape misuse (`extend`
  narrowing, unary `-` on unsigned `bits`), not "wrong kind of value
  entirely." Reusing it would have been the smaller diff.
- **Decision:** minted a new code, `E0418` — the next free slot in the
  E04xx ("width & type rules") family, which runs `E0401`–`E0417` with no
  gaps.
- **Why:** this project's E-code catalog is append-only, one code per
  distinct rule (`docs/audit/README.md`'s own "73/74-code catalog"
  discipline) — the same reasoning `S0240`'s allocation used yesterday
  for the mixed-signedness runtime error (BUG-37). Two semantically
  unrelated diagnostics must never share one code.
- **Impact:** `crates/mimz-core/src/diag.rs` (`ALL_CHECKER_CODES`, now 74
  entries), `explain.rs`, `lang/messages.toml` (PROVISIONAL Tamil/
  Tanglish), `docs/code/11-checker.md` (code table row + reverse index),
  `tests/fixtures/errors/e0418_encoding_needs_enum.mimz`.

### Unplanned findings along the way

Two real, separate, narrow `mimz-sim` gaps surfaced while writing the
GAP-5 position-matrix's Icarus differential tests — neither fixed, both
noted inline in `tests/self_determined_regression.rs` and left for a
future branch:

- The combinational-only kernel (`comb::eval_outputs`) doesn't model any

## BUG-40: CI fuzz crash — `pattern_matches`'s `unreachable!()` on a raw `Pattern::Variant`

CI's `lex_parse_eval` fuzz job crashed ("deadly signal") on a
byte-mutated `examples/english/priority.mimz`. Reproduced locally (no
nightly libFuzzer toolchain on this box) by decoding the crash artifact
and replaying the fuzz harness's exact call sequence in a throwaway
`cargo test` — same panic, same line, every time.

Root cause: the mutated input still lexes and parses (the parser never
validates that an `EnumName.variant` pattern's `EnumName` is a real
declared enum — that's the checker's job), producing a `Pattern::Variant`
referencing a nonexistent enum. `mimz_sim::sim::comb::eval_outputs` — the
fuzz harness's own target, which deliberately bypasses the checker —
reaches `pattern_matches` with this raw, unlowered pattern.
`pattern_matches`'s `unreachable!()` for `Pattern::Variant` assumes the
clocked elaboration path's lowering (`elaborate/rewrite.rs`, which always
converts `Pattern::Variant` to `Pattern::IntMask` and validates the enum
name first) already ran — true on that path, never true on `comb.rs`'s
separate, lowering-free evaluator.

### Decision: fix by returning `false`, not by porting `comb.rs` a lowering pass

- **Context:** two ways to close the gap — teach `comb.rs` the same
  enum-pattern lowering `elaborate/rewrite.rs` has, or make
  `pattern_matches` fail closed (never match) instead of panicking.
- **Decision:** the latter — `Pattern::Variant { .. } => false` in
  `pattern_matches`.
- **Why:** `comb.rs` is a narrow, special-purpose comb-only evaluator
  (used by the fuzz harness and `tests/self_determined_regression.rs`'s
  `differential()`) never intended to support real enum matching — a
  full lowering port would be a feature addition nobody asked for, not a
  bug fix. `false` also matches this exact function's own pre-existing
  sibling error text one arm over (`S0202`: "enum patterns are not
  evaluated yet"), which already anticipated this case.
- **Impact:** `crates/mimz-sim/src/sim/value/mod.rs` (`pattern_matches`),
  two new regression tests (`crates/mimz-sim/src/sim/value/tests.rs`,
  `crates/mimz-sim/src/sim/comb.rs`), `docs/audit/bugs.md` (BUG-40).

Filed as [BUG-40](../audit/bugs/bug-31-40.md#bug-40-medium-fixed-2026-08-07--pattern_matchess-unreachable-fires-on-a-raw-patternvariant-crashing-cis-fuzz-job).
Full workspace green (1188/1188, `REQUIRE_IVERILOG=1`), `fmt`/`clippy -D
warnings` clean.

## v0.2 release-readiness review — do-not-ship

Full independent re-verification of
[`review-2026-08-02.md`](../audit/review-2026-08-02.md) at `ca61b55` (25 commits
past its base `bb79838`). Written up in
[`review-2026-08-07.md`](../audit/review-2026-08-07.md).

**Verdict: do not ship v0.2.** Three of the five release gates fail.

### What is genuinely done

- **F-1's two named instances (BUG-28/29) are fixed and differentially proven.**
  Repro A/B/C re-run through `mimz test` and real `iverilog 12.0`/`vvp`: all
  three now match. The emitter hoists (`wire [7:0] __mimz_sub_1; assign
__mimz_sub_1 = (a);`) where it previously emitted a bare `(a)`.
- **The regression tests are load-bearing, not decorative.** Verified by
  reverting `self_determined.rs`'s `Call` arm to `_ => None` and re-running:
  3 real Icarus differential failures (`kernel 2575 vs Icarus 175`, `51 vs 15`,
  `328 vs 168`), then restored. This was the specific thing the prior review
  asked to be checked rather than assumed.
- **F-2 (BUG-30) is properly resolved.** Growing shifts; the old repro no longer
  type-checks (correct), and its re-typed form gives `direct == named == 60` on
  both the simulator and Icarus. Referential transparency restored.
- **Repo is green** — 1188 passed / 0 failed, 35 suites, `REQUIRE_IVERILOG=1`,
  exit 0. `fmt`, `clippy -D warnings`, release build all clean. F-9 closed.
- **GAP-3 closed structurally**, not just behaviourally: `help` is a required
  parameter of `Parser::error`, so the decision cannot be skipped.

### Why it still does not ship

- **[BUG-41](../audit/bugs.md) (CRITICAL)** — the hoist **gate**
  (`kind_is_inferrable`, `emit_verilog/expr.rs:105`) was never made exhaustive
  alongside the classifier. Its `_ => false` swallows `FnCall`, `Field`,
  `IfExpr`, `Match`, `Index`, so the whole BUG-28/29 fix silently never runs for
  those shapes. Five reproduced miscompiles; `y = { b, extend(ident4(a), 8) }`
  emits `{b, (ident4(a))}` — byte-identical to Repro A's original wrong output.
  Pre-existing since before `bb79838`; missed by the prior review.
- **[BUG-42](../audit/bugs.md) (CRITICAL)** — `min`/`max` classified `None` in
  `verilog_self_determined_kind` on reasoning about mimz's widths rather than
  Verilog's rendered ones. Introduced **by the F-1 fix itself** (the prior
  review's recommended patch text, implemented verbatim). Found by our own
  differential fuzzer at `MIMZ_DIFF_FUZZ_N=400`, seed 12648675.
- **[BUG-43](../audit/bugs.md) (CRITICAL)** — `UnOp::Neg` negates a literal
  inside its own `natural_width`, so `-9` becomes `7` and `-1` becomes `1`. The
  emitter is right and the simulator is wrong, everywhere a negative constant
  appears. `max(-100, min(x, 100))` with `x = -1000` gives 28 in the simulator
  and −100 in Icarus. Broadest blast radius of anything open — it breaks a
  _value_, not a syntactic position.
- **[BUG-44](../audit/bugs.md) (HIGH)** — second fuzz divergence (clocked, seed
  202427830), unminimized. Recorded as distinct rather than assumed to be
  BUG-42.
- **[GAP-11](../audit/gaps.md)** — the width-conformance oracle added for GAP-5
  only checks top-level signal widths, which the kernel masks by construction;
  its own comment says it "should never fire today." It cannot catch the BUG-30
  class it was written for, nor BUG-43. Separately, CI fuzzes 20 seeds; 400
  seeds takes 55 seconds and found two live miscompiles.
- **[GAP-12](../audit/gaps.md)** — `mimz compile` is superlinear in module size
  (0.43 s / 1.00 s / 3.51 s / 10.57 s for 1k/2k/4k/8k registers). `check` stays
  linear, so it is the emitter: 22 per-expression `cur_decls.clone()` calls,
  each a full `HashMap` clone.

## BUG-43 fixed — negative literals (remediation task 1/4)

Branch `bug-41-42-43-self-determined-class-closure`, task 1 of the plan in
`docs/plan/v0.2-correctness-remediation.local.md`. Not committed yet.

Three sites, not one — the review pinned the first, the other two only showed
up once the first was fixed and the value stopped being wrong at the source.

### Decision: fold `-<literal>` at eval, don't negate in place

- **Context:** `value/binary.rs`'s `UnOp::Neg` negated inside the operand's own
  width. A literal's `Val` comes from `from_literal`, whose width is the
  magnitude's `natural_width` — 4 bits for `9`, which cannot hold `-9`. So `-9`
  wrapped to `+7` and `-1` to `+1`.
- **Decision:** match `Neg(Int)` in `value::eval` before the general `Unary` arm
  and fold it via a new `Val::negated_literal`, which builds the value at
  `natural_width(n) + 1` bits, signed.
- **Why:** `-n` is a constant, not an operation applied to `n`. One extra bit is
  exactly what a two's-complement negation needs, and it matches
  `Val::from_int`'s own `129 - leading_ones` rule — but computed over `Bits`, so
  an arbitrarily-wide literal (BUG-13 layer 2, past `i128`) is served too, which
  `from_int` cannot do. The runtime `-x` path is deliberately untouched:
  `signed[N] -> signed[N]` matches Verilog, and `abs`'s explicit `N -> N+1`
  growth shows the language already made that call.
- **Impact:** `crates/mimz-sim/src/sim/value/mod.rs`.

### Decision: one `resize_to_width`, replacing three copies

- **Context:** with the value now correctly a narrow SIGNED `Val`, the consumer
  dropped the sign — `wire w: signed[8] = -1` read back as 3 while the emitted
  Verilog said 255. `remask_to_width` existed three times (`comb.rs`,
  `kernel.rs`, `value/mod.rs`), each documented as _"a pure reinterpret, NOT a
  sign-extending resize"_.
- **Decision:** one `value::resize_to_width(v, w, signed)` — truncate when
  `w <= v.width`, otherwise fill from the SOURCE's signedness via
  `wide::extend`. Both duplicate copies deleted.
- **Why:** zero-padding was harmless only while every sub-width value reaching
  it was an unsigned literal. Fixing one copy would have left the other two
  wrong, and the checker enforces exact width matching everywhere except
  literals — so the widening path is exactly the literal path. Three copies of
  one resize rule is the drift surface GAP-1 describes.
- **Impact:** `value/mod.rs`, `comb.rs`, `kernel.rs`, `value/fn_eval.rs`.

### Decision: `Sim::set_val` for evaluated values, `Sim::set` for raw patterns

- **Context:** `mimz test` still drove the wrong stimulus after both fixes above
  — `p = -9` on a `signed[6]` port arrived as 23, not 55.
- **Decision:** `TestStmt::Drive` now calls a new `Sim::set_val(name, Val)`,
  which resizes through `resize_to_width`. `Sim::set` keeps its raw-`Bits`
  signature for peripherals and clock/reset toggles.
- **Why:** the harness evaluated the expression to a `Val` and then handed over
  `v.bits_masked()`, destroying the width and signedness before `set` could act
  on them. `set` cannot be fixed in place — with only a raw pattern there is no
  source width to extend from. Splitting the two is what makes the distinction
  visible at the call site rather than assumed.
- **Impact:** `crates/mimz-sim/src/sim/kernel.rs` (plus a shared `not_a_leaf`
  helper for the `S0239` both paths raise), `crates/mimz-sim/src/sim/harness/mod.rs`.

### Verification

The `signed[6]` table from BUG-43's filing, end to end through `mimz test`:

```text
p=-1  63   p=-3  61   p=-5  59   p=-9  55   p=-16 48   p=-17 47   p=-32 32
```

all matching two's complement, all previously wrong except `-32`.

- `max(-100, min(x, 100))` with `x = -1000`: `mimz eval` now `-100` (was 28),
  matching Icarus.
- `wire w: signed[8] = -1` -> `unsigned(w)` now 255 (was 1), matching Icarus.
- `q == -9` with `q = -9` now true (was false), matching Icarus.
