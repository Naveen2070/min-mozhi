## Round-8 plan Task 3 — BUG-71: `emit_testbench` must see the DUT's own file consts

### Summary

Fixed BUG-71 on branch `round8-class-closure`: `emit_testbench` never folded a DUT's file- or module-level consts into its own env, so a `const if` referencing one was unevaluable there even though `mimz check`/`mimz compile` (without `--emit-testbench`) resolve the identical design fine. `flatten_items` silently read the failure as `unwrap_or(0)` — false — dropping the port with no diagnostic.

### Fix

Two parts, plus a third call site found while wiring part (1) in.

1. `emit_testbench` (`crates/mimz-core/src/emit_verilog/testbench.rs`) gained a `files: &[File]` parameter (mirroring `emit()`'s own signature — `Project` never retained the raw file list; it discards `TopItem::Const` entirely building its module/enum/bundle/func tables). Seeds its env from the DUT's file consts, then module-level consts (`em.eval_consts_items(&dut.items, dut_file_consts)`, the same fold `module()` does for a directly-compiled module), before resolving test args/parameter defaults on top — overlay order matters, so an explicit test argument still wins on a name collision. Both call sites (`src/commands/compile.rs`, the crate's own test helper) updated.
2. `flatten_items` (`module/instances.rs`) now pushes `consteval::eval`'s own `Diag` (`Result<_, Diag>`, directly reusable) instead of `.unwrap_or(0)` — needed `&mut self` (was `&self`).
3. **Found while wiring (2) in**: `eval_consts_items` — module-level const folding, which `emit_testbench` now calls for the first time — had the identical `unwrap_or(0)`-is-silently-false gap, one function over. Fixed the same way, widened from `pub(super)` to `pub(in crate::emit_verilog)` so `testbench.rs` can call it. Deliberately did NOT extend this to `declare_instance_outputs`/`emit_instances`'s own copy of the same evaluation — they run after `flatten_items` on the same raw items and would only re-diagnose an already-reported failure (the same "don't double-report" reasoning `declare_instance_outputs`'s own doc comment already gives for unknown-module resolution).

## Round-8 plan Task 7 — narrow `initial #0` to the case that needs it

### Summary

Round-7 Task 3 added `#0` to every `mem`/`reg` power-on seed unconditionally — the sole content of all 33 golden diffs at the time. The reasoning (a hoisted operand is a continuous `assign` racing the `initial` block in time-0's active region) is sound only when the seed's own rendered value actually hoists a wire; for the entire shipped corpus, none does, so the guard was firing 33 times for a race that can only happen in a case none of them are.

### Fix

Both the `mem`-init loop and the `reg`-reset loop (`crates/mimz-core/src/emit_verilog/module/mod.rs`) now record `self.pre_decl_hoisted_decls.len()` immediately before rendering their own value (`self.expr(depth)`/`self.expr(init)` for `mem`, `self.expr(reset)` for `reg`) and compare the length after: growth means that render pushed a new hoisted `wire`/`assign` pair, so `#0` is still emitted; no growth means a bare `initial`. Reuses the existing hoist-buffer bookkeeping directly rather than re-scanning the rendered text, so the guard cannot be silently dropped by a text-matching false negative — only by nothing actually having hoisted.

### Verification

## Round-8 plan Task 10 — BUG-72: give symbolic-width `trunc` the same self-determined-position fallback `extend` already has

### Summary

`try_widen_symbolic_extend` (`expr.rs`) recovered a self-determined position from `infer_kind` returning `None` for a symbolic-width `extend(x, W)`, but had no equivalent for `trunc(x, W)` — a checker-accepted, `extend`-symmetric construct that instead fell through all 8 self-determined-position call sites to `hoist_unresolved`'s diagnostic. One `&` away from a shipped example (`shift_register.mimz`).

### Fix

Simpler than even the plan's own anticipated shape: no new hoist-base/part-select/signed-wrap logic was needed. Added a `Builtin::Trunc` arm to `try_widen_symbolic_extend` that just returns the caller's own already-rendered `text` unchanged — every one of the 8 call sites already computes it via `render_shift_ctx_operand`, which dispatches through the ORDINARY `Builtin::Trunc` render arm (`x[(n)-1:0]`), and that rendering is already correct at a self-determined position regardless of width symbolicness: a Verilog part-select's own width is always exactly `n` bits by construction, unlike `extend`'s ambient-context-dependent passthrough. Widened the function's signature to accept that pre-rendered text (threaded through all 8 call sites) rather than re-deriving it from `args[0]`/`args[1]`, which would have left the first hoist of a composite base dead and unreferenced.

### Verification
