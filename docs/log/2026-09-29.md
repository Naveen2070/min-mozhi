### Decision: route `a_parameter_select_folds_then_bypasses` through a wire

- **Context:** after the fold, `lower` removes the mux in
  `o = if MODE == 0 { a } else { b }` itself, so that mux-simplify test's
  precondition (one mux for R1 to bypass) failed.
- **Decision:** the source now reads `wire m: bit = MODE == 0` and
  `o = if m { a } else { b }`. `lower` cannot fold `if m` (`m` is a
  signal) but drives `m` from a `Const` cell, so R1 still fires.
- **Why:** keeps the test's purpose, R1 on a parameter-derived constant
  select. Flipping R1's select sense still fails it.
- **Impact:** `crates/mimz-core/src/ir/tests/opt_mux_simplify.rs`.

- Smaller ruling: `flatten_extern_instance` also declares its `ports` list
  with an explicit tuple type the plan did not list; the compiler required
  it to change too.
- Revisited the final-review ruling above ("extern output pins rewritten as
  readers ... revisit once extern designs validate"): it still holds.
  `simplify_muxes` only rewrites nets that are some mux's `out`, and a
  black-box output net that was also a mux's `out` now fails `validate` as
  `MultipleDrivers`, the pass's precondition.

## Final review: IR lowering and validate fixes (commit `43ad722`)

- Fresh opus reviewer over `25e63b5..43ad722`: ready to merge with fixes,
  1 Critical, 1 Important, 3 Minor. Both real findings reproduced by the
  reviewer as passing at base and failing at head.
- Critical, fixed: wrong hardware with no error. `LowerCtx::local_consts`
  was one map across nested inlined `fn` calls, so an outer fn's
  `let k = 0` decided an inner fn's `if` on its parameter `k`. The new fold
  in `lower_if` made the leak reachable from any `if`; the `FnStmt::Let`
  fold already leaked the same way before this branch.
  - Fix: the `FnCall` inline path takes `local_consts` for the callee body
    and restores the caller's afterwards (args are lowered first, in the
    caller's scope).
  - Tests `a_callers_let_constant_never_decides_a_callees_condition` and
    `a_callers_let_constant_never_folds_a_callees_let`, RED (0x3C and 0 for
    an expected 0x5A), then GREEN.
- Important, fixed: false `MultipleDrivers` for an extern with an
  `out q`/`out`/`rdata` port. Check 1's name rule and the new declared-`Out`
  loop both counted that pin. For a black box with a declared shape, only
  the declared directions count now; the name rule stays for hand-parsed
  IR. This also stops an extern _input_ named `out` from counting as a
  driver (already wrong before this branch).
  - Tests `a_declared_extern_output_named_q_is_driven_once` and
    `a_declared_extern_input_named_out_is_not_a_driver`, RED, then GREEN.
- Deliberate breakage: letting the callee inherit the caller's
  `local_consts`, or always applying the name rule, each fail exactly
  their two tests.
- Deferred minors (not fixed):
  - The fold's known limit is reachable from source in contexts with no
    target width (a concat part, a unary operand, a shift amount, an index
    base), not only in theory. gaps.md says no example has it.
  - `tests/ir_opt_corpus.rs` pins a total count, so an extern fixture
    regressing while an example starts passing would not fail it.
  - `lower_if` results reached through `lower_expr_sized` bypass
    `expr_memo`, as `lower_match` already does. Every traced call site
    lowers once, so no live bug.
- Rulings on points the reviewer declined to judge:
  - `ConstVal::is_zero` matches only `Bits::Small(0)`: the checker's own
    `IfExpr` evaluation uses the same test, so lowering and checking agree.
  - A constant taken branch sized to a target is built unsigned; every
    caller that passes a target stamps the declared sign afterwards, and
    the rest are sign-insensitive. No divergence.
  - Out-of-range constant memory addresses truncating to the address
    width, and emitter/simulator handling of the known-limit shape, predate
    this branch and stay out of scope.
