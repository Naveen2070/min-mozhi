### BUG-56/57/58 — literal sizing, array-literal index, signed negation growth (`54d78e6`)

- BUG-56: a bare integer literal rendered unsized, so Icarus refused any
  concat/replicate member that nested one (`{b, a & 15}` shape). New
  `verilog_literal_sized` helper sizes only the adapt-to-sibling `BinOp`
  literal operand (`BitAnd`/`BitOr`/`BitXor`/`Add`/…). 2 new differentials
  watched fail at the exact filed Icarus "indefinite width" error, pass
  post-fix.
- BUG-57: indexing an array literal (`[a,a,a][0]`) panicked —
  `unreachable!("Task 8 or Task 9 wires this up")` — instead of erroring;
  `mimz check` accepted it at any position. Fixed with a real checker
  diagnostic.
- BUG-58: the kernel's `UnOp::Neg` never grew by the checker's own promised
  carry bit, so negating a `signed[N]` MIN value silently overflowed instead
  of matching the checker's width promise.
- 14 showcase/example goldens regenerated; `mimz-wasm` pkg rebuilt to keep
  `wasm_parity` in sync. Workspace green, fmt/clippy clean.

### Task 8 — check/sim/emit split BUG-53 exposed, resolved via option (b) (`c0d69d7`)

Chose simulator support over checker rejection: the checker's own
`no_decls_in_repeat` (E0303, `checker/names/items.rs`) already documents
nested `repeat`/`const if` as legal hardware generation, so the three-way
`check`/`sim`/`compile` disagreement BUG-53 exposed was a simulator gap, not
an intentionally-unsupported shape.

`elaborate/module.rs`'s repeat-body loop carried the same "arm present, data
source under-populated" defect as BUG-53 itself, one layer below the
emitter: it named array-instances from the raw loop counter instead of
`inst.index` folded against the current env, and rejected anything but
`Inst`/`Drive` outright (S0125/S0126) instead of recursing. Replaced with
`elaborate_repeat`/`elaborate_repeat_body_item`, mirroring the emitter's own
already-fixed `inst_name` index fold and `run_worklist`'s own `ConstIf`
recursion — one shared walk, not a second hand-synced copy.

Sibling gap found fixing this: `collect_inst_names` recursed into a nested
`Repeat` but not a `ConstIf`, so an instance behind a `const if` inside a
`repeat` was never registered as a known instance name, breaking the read
side (`s[0].q`) with an unrelated error. Fixed alongside, same recursion
added there too.

All three of BUG-53's filed repros now elaborate correctly through the real
kernel — upgraded from `emitter_only_clocked_check` (deleted, dead) to real
`differential_clocked` in `self_determined_regression.rs`. **S0125
retired** from `sim/diag.rs`'s `ALL_SIM_CODES` (same precedent as S0101) —
nested `repeat` is genuinely supported now, so its only emission site is
gone; `s0125_nested_repeat_not_supported` replaced with the positive
`nested_repeat_elaborates`. S0126 stays reachable (a `Reg`/etc. inside
`repeat`, when the checker hasn't run).
