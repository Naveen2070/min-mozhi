## Test VCD cleanup and CWD isolation

### Summary

Fixed test execution in `tests/icarus.rs`, `tests/support/mod.rs`, and `tests/sim.rs` so running `cargo test --workspace` does not pollute the repository root directory with leftover `.vcd` waveform files or accumulate intermediate `.vvp`/`.v` simulation files.

### Context & Root Cause

1. `crates/mimz-core/src/emit_verilog/testbench.rs` emits `$dumpfile("{tb_name}.vcd");` for testbenches generated by `mimz compile --emit-testbench` (enabling GTKWave viewing for end users).
2. When `tests/icarus.rs` executed `vvp` on the emitted testbenches across all examples (via `every_emitted_testbench_reports_pass_under_vvp`, `emitted_testbench_reset_deassert_does_not_race_the_dut`, and `emitted_testbench_summarizes_covers_at_finish`), `vvp` ran in the default process CWD (the repository root).
3. As a result, ~37 `.vcd` files were dumped directly into the repo root during test runs and left uncleaned.
4. `tests/sim.rs` also left temporary `.vcd` and `.mimz` files in `temp_dir()` after assertion.

### Changes Made

- **`tests/icarus.rs`**:
  - Set `vvp` working directory to `std::env::temp_dir()` via `.current_dir(std::env::temp_dir())` across all testbench runner functions.
  - Added explicit post-run cleanup of `vvp_out` and `{name}.vcd` files.
  - Added a regression assertion to `every_emitted_testbench_reports_pass_under_vvp` checking that no `.vcd` files exist in `repo()`.
- **`tests/support/mod.rs`**:
  - Set `.current_dir(std::env::temp_dir())` on `vvp` in `run_vvp`.
  - Added cleanup of `tb_path` and `vvp_out` after execution.
- **`tests/sim.rs`**:
  - Cleaned up temp `.vcd` and `.mimz` files in `writes_a_gtkwave_vcd` and `a_combinational_module_writes_a_vcd`.

### Verification

- `cargo fmt --all -- --check`: clean.
- `cargo clippy --workspace --all-targets -- -D warnings`: clean.
- `cargo test --workspace`: all suites green, 0 `.vcd` files generated in repo root.
- `graphify update .`: knowledge graph updated.

## Round-7 plan Task 1 — hoist declaration-order invariant (GAP-18)

### Summary

This is the second scoping axis round 7's review found (GAP-18) alongside round 6's `hoist_unresolved` (GAP-16) — a hoist can resolve its `Kind` correctly and still land after its own use if the render site asking for it runs before the hoist buffer's flush point (`hoist_pos`). BUG-66 is exactly this, at three sites.

### Changes Made

Wired into `emit()`, called on each module's own output slice right after `Emitter::module` returns. Module doc updated to state the invariant next to `kinds.rs`'s existing GAP-16 wording.
- **`crates/mimz-core/src/emit_verilog/tests/hoist_declaration_order.rs`** (new, registered in `tests/mod.rs`): unit test for the name-scanning logic, and a `#[should_panic]` test proving the assert fires today on BUG-66 A2's own repro (a `reg`'s composite reset value hoists before `hoist_pos` is captured).

## Round-7 plan Task 11 — teach the fuzz generator nested `fn` calls

### Summary

Six of round 7's findings sit in shapes the fuzz generator cannot produce. The cheapest and highest-value one is the nested `fn` call: `gen_special_leaves` emitted exactly one `fn` per program, so BUG-67 — a `fn` calling another `fn`, where `render_fn_decl`'s fresh `decls` omitted the callee's `__mimz_fnret__` key — was structurally unreachable at any depth.

### Changes Made

- **`tests/differential_fuzz.rs`**: `gen_special_leaves` now generates a second `fn`, `inner{w}`, and hands `inner{w}(x)` to the outer `fn`'s body as an ordinary `special` leaf. That placement is the point — the call lands in whatever concat member / cast operand / `match` arm the tree builds around it, and BUG-67 needed a _self-determined position_ inside a `fn` body, not merely a call. The callee is declared only when the generated body actually kept the call (`clamp`/`force_width` can drop the leaf), so no program carries an unused `fn`.
