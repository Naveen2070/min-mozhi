### Decision: leave `struct` reserved, don't un-reserve

- **Context:** doc audit found `struct`'s spec/03 description ("bundles/interfaces,
  post-Phase 2") stale - that feature shipped as `bundle` on 2026-07-16, and
  `interface` is separately reserved for a distinct still-unshipped concept
  (named port bundles). `struct` itself has no feature attached to it anymore.
- **Decision:** reworded the description to state the truth (orphaned, no
  current owner) in both `lang/keywords.toml` and `spec/03-keywords-trilingual.md`,
  but did not release the reservation.
- **Why:** un-reserving a word is a "major design decision" (R11/R13) -
  releasing it now and regretting it later (a v0.1.0-frozen English column
  can't easily re-claim a word) costs more than leaving it reserved-but-idle
  costs today. Flagged for a deliberate maintainer call instead of guessing.
- **Impact:** `lang/keywords.toml`, `spec/03-keywords-trilingual.md`. No code
  change - the word was already rejected as an identifier before this session
  and still is.

**What's next:** two flags left open, both structural/account-level, not
doc-fixable - `Agents.md`/`AGENTS.md` byte-identical duplicate at repo root
(recommend deleting the stray-cased one), and the unprotected `master` branch
