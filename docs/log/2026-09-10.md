# 2026-09-10

## Decisions

### Decision: `ir::Bits` gains an explicit per-value `signed` flag

- **Context:** GAP-1's residual list (`docs/audit/gaps.md`) still has `min`/`max`/`abs`
  hard-panicking in `ir::lower` (`unimplemented!` at `ir/lower.rs:680`) and `extend`
  refusing any argument it can't prove unsigned (`ir/lower.rs:639`), both because
  `ir::Bits` (`ir/mod.rs:26`) carries no signedness at all. The workaround in place today
  — `arg_is_definitely_unsigned`/`expr_is_definitely_signed`/`unshadowed_signal_signed`
  (`ir/lower.rs:793-893`) — is an explicitly-scoped "best-effort proof" that only
  recognizes two expression shapes and documents two cases where it and the checker's own
  width rule diverge (`UnOp::Neg` growth, `BinOp::Mul` literal sizing) — the same
  three-consumers-one-rule failure class GAP-1 exists to close, now showing up a fourth
  time inside the IR itself.
- **Decision:** Change `pub struct Bits(pub Vec<NetId>)` to
  `pub struct Bits { pub nets: Vec<NetId>, pub signed: bool }`, with two constructors
  (`Bits::unsigned(nets)`, `Bits::signed(nets)`) replacing every bare tuple-literal call
  site. `signed` is computed once, at the point a `Bits` is produced (a cast, a binary op,
  a literal sized by `lower_expr_sized`), by the same rule the checker's `Ty::Signed(n)` /
  `Ty::Bits(n)` split already uses — never re-derived downstream by pattern-matching the
  source `Expr`. `min`/`max`/`abs` and `extend`'s ambiguous branch read `Bits::signed`
  directly instead of refusing to lower. The three heuristic helper functions above are
  deleted once every caller reads the field instead.
- **Why:** A per-value flag makes signedness exact by construction — the same reason the
  checker itself carries it on `Ty` rather than re-inferring it at each use. It removes
  the failure class instead of patching its Nth instance (BUG-11/18-24/28-30/34/47 in
  `docs/audit/bugs.md` are all this same "two implementations, one disagreement" shape).
  Considered and rejected: a `HashMap<NetId, bool>` side-table on `LowerCtx` — rejected
  because signedness belongs to a VALUE (a `Bits`), not a net; the same net can be reused
  by both a `signed(x)` cast and `x`'s own unsigned declaration, so a net-keyed table
  would need re-derivation at every cast anyway, with none of the type-safety win a field
  on `Bits` gives for free.
- **Impact:** `crates/mimz-core/src/ir/mod.rs` (`Bits` struct + `width()`),
  `crates/mimz-core/src/ir/lower.rs` (every `Bits` construction site, `Min`/`Max`/`Abs`,
  `extend`, `UnOp::Neg` width growth, `BinOp::Mul` literal sizing, the `cmp_signed`
  computation for `Lt`/`Le`/`Gt`/`Ge`), `crates/mimz-core/src/ir/exec.rs` (signed
  arithmetic must match), `docs/architecture.md` section 2 IR row, `docs/audit/gaps.md`
  GAP-1 (closes the `min`/`max`/`abs`/`extend` sub-items).

### Decision: const-var-substitution unrolling shared by `fn`-body and `on`-block lowering

- **Context:** `lower_fn_stmts`'s `FnStmt::Loop`/`FnStmt::ForEach` arm
  (`ir/lower.rs:942-948`) and `lower_seq_stmts`'s `SeqStmt::Loop`/`SeqStmt::ForEach` arm
  (`ir/lower.rs:1410-1415`) both `unimplemented!()` today. This blocks 10 of the coverage
  probe's 40 remaining failures (`fn_array_search.mimz`, `foreach_sum.mimz`, Tamil-pure
  `kootu.mimz`, and any `on`-block using `foreach`/`repeat`/`suzhal`), all five flavors.
- **Decision:** Both sites adopt the SAME strategy the AST-level evaluator
  (`crate::value::fn_eval`, which already runs `foreach`/`repeat` correctly for
  `mimz sim`/`mimz test`) already uses: const-eval the loop's source (an array literal or
  a bounded count) to its full list of element values, then for each value, extend the
  current binding map (`locals` for `lower_fn_stmts`, `env` for `lower_seq_stmts`) with
  the loop variable bound to that iteration's constant, and recursively re-lower the loop
  body once per iteration — the same threading `FnStmt::Let` already does for a single
  binding, just repeated N times with N different values instead of once.
- **Why:** This is a new lowering CAPABILITY (an iteration primitive `ir::lower` has never
  had), not a missing cell or a resize — the same gate the constitution requires for
  `min`/`max`/`abs`'s signed-values work (Task 1). Porting the AST evaluator's own
  already-correct, already-tested binding convention (rather than designing a second one)
  matches how the array-fn-param fix (GAP-1 residual Task 6) explicitly ported
  `emit_verilog`/`value::fn_eval`'s existing `"{name}_{i}"` scheme instead of inventing a
  new one. `expr_memo`'s own doc comment (`ir/lower.rs:99-104`) already flags that this
  mechanism must not let one iteration's memo answer leak into the next — recursive
  re-lowering per iteration satisfies that for free, since `expr_memo` is only
  read/written when `locals.is_none()` (module-level context), which no loop iteration
  ever is.
- **Impact:** `crates/mimz-core/src/ir/lower.rs` (`lower_fn_stmts`'s
  `FnStmt::Loop`/`FnStmt::ForEach` arm, `lower_seq_stmts`'s
  `SeqStmt::Loop`/`SeqStmt::ForEach` arm), new tests mirroring `foreach_sum.mimz` and an
  `on`-block loop fixture, `docs/architecture.md` IR row, `docs/audit/gaps.md` (closes
  both loop sub-gaps).
