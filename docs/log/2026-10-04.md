  `mimz_files` (moved from `ir_opt_corpus.rs`, unchanged), `clock_ports`,

  walks (not `support::corpus_files()`, which adds `demo/`).
- Result: 230 modules, 224 checked, 6 skipped, 0 backend bugs found.
- Skips: `dual_edge.mimz:DualEdge` in english, mixed, tamil and tanglish
  (rising register feeding a falling one; `ir::exec` ignores `edge`, so the
  traces differ by design; skipped by a mixed-edge test, GAP-1) and
  `tests/fixtures/extern/pll.mimz:ExternDemo`, `pll_alias.mimz:AliasDemo`
  (`BlackBox` cell, nothing to simulate).
- Run time: about 70 s for the test (under the 3 minute limit, so the full
  corpus runs everywhere; not gated).

  naming `examples/english/alu.mimz:Alu`; restored, green.
- Review (opus): approved, 0 Critical, 0 Important. The DualEdge skip is
  confirmed by analysis: rise sets `a = d`, fall sets `b = a` in the same
  tick in Icarus (`q_t = d_t`), while `ir::exec` updates both at once
  (`q_t = d_{t-1}`), a one-tick lag from the edge model, not a backend bug.
  The mixed-edge rule fires only on a module with both a rising and a
  falling `Dff`/`Adff`, and every skip still meets the pinned list.
- Review minors fixed: `run_iverilog` temp names carry the process id (Task
  7 shares the helper); test-map row for Task 3's `tests/ir_verilog_golden.rs`
  added.
- Deferred (recorded in the GAP-1 sub-gap "limits of the IR Verilog
  backend" in `docs/audit/gaps.md`, with the skip list): DualEdge could be
  checked against `ir::exec`'s trace shifted one tick instead of skipped, so
