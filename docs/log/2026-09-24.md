# 2026-09-24

## Added: `ir::opt::fold_constants` — first pass of the IR optimizer track

- New `ir::opt` module (`crates/mimz-core/src/ir/opt/`): `mod.rs` holds
  `net_consts` (every `Const`-driven net mapped to its bit) and
  `run_to_fixpoint` (repeats a pass until it reports no change) — plumbing
  the next two optimizer passes are meant to reuse. `const_fold.rs` holds
  `fold_constants`, which repeatedly folds every pure-combinational,
  non-`Mux` cell whose inputs are all compile-time constants into a
  `CellKind::Const` cell carrying the same value.
- Each candidate cell is cloned into a throwaway `Module` with one synthetic
  `Const` cell driving each input pin, then run through
  `ir::exec::Executor` (`new`/`tick`/`get_output`) — the fold uses exactly
  the semantics `exec.rs` already implements for simulation, rather than a
  second per-`CellKind` evaluator that could drift from it. The folded cell
  is rewritten in place and keeps its original `out` pin `Bits`, so
  downstream consumers need no rewiring.
- Two guards the design spec implied but didn't name, each logged as a
  Decision:

### Decision: skip fold candidates wider than 128 bits

- **Context:** `ir::exec::Executor`'s net reconstruction is `u128`-based
  and panics past 128 bits (`attempt to shift left with overflow`, or
  `exec`'s own "wide (>128-bit) net reconstruction not yet implemented" if
  that first panic is ever bypassed). `wire k: bits[200] = 1; o = k + 1` is
  checker-legal, so a naive fold crashes a valid program.
- **Decision:** leave any candidate with a pin wider than 128 bits unfolded.
- **Why:** extending `exec` to wide nets is out of scope for this pass.
  Leaving the cell unfolded is always sound — it's exactly the same
  cell `lower` already produced.
- **Impact:** `const_fold.rs`'s `is_candidate`, and the test
  `skips_a_candidate_too_wide_for_the_executor`.

### Decision: never fold a `Shl`'s exact shift-amount driver

- **Context:** `validate`'s `shl_const_amount` check sizes a `Shl` cell
  exactly once its `b` (amount) pin is one `Const` cell's `out`, but at
  worst case otherwise. `lower` already sizes `x << (k +% 1)` at worst
  case. Folding the `AddWrap` that drives `k +% 1` would make `validate`
  suddenly expect the exact (narrower) size, turning a module `lower` sized
  correctly into a `WidthMismatch`.
- **Decision:** leave that specific driver cell unfolded, via a new
  `feeds_a_shift_amount` guard in `is_candidate`.
- **Why:** the spec requires folding to never produce a structurally
  invalid module. Rejected alternatives: re-sizing the `Shl` after the fold
  (that's mux/dead-cell-elimination territory, not this pass), and
  relaxing `validate`'s own check (weakens a real invariant for everyone,
  not just this pass).
- **Impact:** `const_fold.rs`'s `is_candidate`/`feeds_a_shift_amount`, and
  the test `does_not_fold_a_shift_amount_that_lower_sized_as_runtime`.

- 11 new tests (`ir/tests/opt_const_fold.rs`), all pinned to real or
  hand-built module shapes and value-checked before/after via `Executor`,
  not just structurally: single-hop and multi-hop-chain folding, a
  partial-const negative, idempotence on a second call, signed-operand
  correctness, `Concat`/`Slice` bit-order correctness, `Dff`/`Mem` never
  folding even with fully-constant write pins, the 128-bit width guard, and
  the `Shl`-amount guard.
- One plan-text correction (Ruling, ledgered in
  `.superpowers/sdd/2026-09-24-ir-const-fold.local/progress.md`): the
  implementation plan's mutation-check for the `Dff`/`Mem`-never-folds
  pinning tests (Task 3, Step 3, mutation 3) predicted that adding
  `Dff`/`Mem` to `is_pure_comb` alone would make both tests fail. It
  doesn't — `Dff`'s `q` pin and `Mem`'s `clock` pin (neither named `"out"`)
  are already swept into `is_candidate`'s own "every non-`out` pin must be
  const" check and are never const-driven, an independent guard the plan
  missed. Used a corrected mutation (bypass `is_candidate` directly for
  those kinds) to actually reach the predicted `evaluate` panic on the
  missing `"out"` key; both tests confirmed FAIL, then fully reverted
  (`git diff` on `ir/opt/` empty).

## Next

Optimizer item 1 of 3 (constant folding/propagation) is done. Next up:
dead signal & dead cell elimination (it will remove the upstream cells this
pass now orphans — folding a cell never deletes what used to feed it), then
mux-tree simplification (the `Mux`-with-constant-`sel` case this pass
deliberately left alone), then wiring all three into the build path via
`ir::opt::run_to_fixpoint` once they compose.
