  `fold_constants`, `simplify_muxes` and `eliminate_dead_cells`, every pass

  `validate` -> `print_line` (or `print_sexpr` with `--sexpr`). Flags:
  `--module`, `--param`, `--no-opt`, `--sexpr`, `-o`, `--lang`, `--panic`.
  `mimz::ir` is now re-exported from the shell crate.
- New `ir::failure` (`crates/mimz-core/src/ir/failure.rs`): `catch` turns a
  panic inside `lower`/`optimize` into a `Failure` with stage, class
  (`Limitation` = `unimplemented!` or the `S0227` loop budget, everything
  else `Internal`), message, panic site, innermost source span and, with
  `-d`, a backtrace. Span guards sit in `lower_expr` and `lower_expr_sized`.

  class, the source line with the failing sub-expression underlined, a help
  line explaining the class, the panic message (cut at 240 chars unless
  `-d`) and the panic site. `--panic` re-raises an `Internal` failure
  (exit 101); an IR limitation stays a clean exit 1.

### Decision: one chaining panic hook, and a single-file span rule

- **Context:** `catch` must capture the panic site and the span stack
  before unwinding, which only a panic hook can do. Swapping the hook in
  and out per call races when two threads catch at once (parallel tests).
  `Span` has no file index, so a span from a flattened imported module can
  land inside the entry file's byte range and underline the wrong text.
- **Decision:** install one hook per process (`std::sync::Once`) that
  records only for a thread inside `catch` (thread-local flag) and hands
  every other panic to the hook it replaced. Underline a span only when the
  project is a single file; otherwise print the top module and "source
  location not shown".
- **Why:** no race, no change to panics outside `catch`; a missing
  underline is better than a wrong one.
- **Impact:** `crates/mimz-core/src/ir/failure.rs`, `src/commands/ir.rs`.
  Multi-file spans need `elaborate` to record a file index (gaps.md).
