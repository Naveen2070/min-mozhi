## Sim runtime diagnostics R2 closed — all 5 phases landed

All 5 phases of
`docs/superpowers/plans/2026-07-30-sim-runtime-diagnostics-r2.local.md`
(design: `docs/superpowers/specs/2026-07-30-sim-runtime-diagnostics-r2-design.local.md`)

the tamil-pure T1 gap. Every `mimz-sim` runtime error now carries a real

and WASM playground both render it with a real file:line:caret instead
of yesterday's flat `eprintln!("error: {e}")`.

**Phase 3 (`S03xx`, test-harness control flow)** — `sim/harness/mod.rs`'s
`Stop::Err(String)` → `Stop::Err(Box<Diag>)` (`73e3640`). Forced touching
every `Stop::Err` construction site at once (single Rust enum variant,
can't stay partially `String`), including the peripheral-bind ones that
are semantically Phase 4's own `S04xx` territory — left those uncoded

existing ad-hoc `fail_message`/`snippet(e)` teaching-message rendering

`render()`: it's a test-OUTCOME report (`TestResult::Fail`), not a
`Stop::Err` diagnostic, and replacing it would need threading a file
path through `run_test`'s public signature purely to reproduce output
it already produces correctly. 5 new codes (`S0301`-`S0305`).

**Phase 4 (`S04xx`, peripheral bind errors)** (`fb8610b`) — added the

`sim/host.rs`'s `EmulationHost` trait and the shell crate's real

**Phase 5 (CLI + WASM rendering — the payoff):**

  and found there's no JSON/structured shape at all — `check`/`compile`/
  `eval` already render fully to a plain caret-annotated string via
  `mimz_core::project::render_diags` INSIDE `mimz-sim` itself before
  ever returning, and `mimz-wasm`'s two exported functions are a pure
  passthrough (`JsError::new(&already_rendered_string)`). Confirmed on
  the consumer side too: the Astro playground's only `JSON.parse(...)`
  call is for the unrelated `"ports"` command's success payload, never
  diagnostics.
- Wired `src/commands/{sim,eval,test}.rs` (`50b26fb`): the 3 actual
  `Diag`-bearing sites (`elaborate_project_with_mode` in `sim.rs`,
  `comb::eval_outputs` in `eval.rs`, `run_test_with_mode` in `test.rs`)
  now render via `project::render_diags_lang`/`diag::render_lang`
  instead of a flat `.msg`. Manually spot-checked all three commands
  against deliberate runtime errors (a missing instance parameter, a

  a caret underline.
- Fixed the SAME gap inside `runner.rs`'s own `eval`/`sim`/`test`
  in-memory commands (`763b8d6`) — these are what `mimz-wasm`'s
  `run_command` actually calls, so this (not any change to
  `mimz-wasm/src/lib.rs`, which needed zero changes) was Task 5.3's real

- Added `crates/mimz-sim/tests/sim_errors.rs` (`ac9ea02`) — a new

  `tests/errors.rs`'s own `error_corpus_covers_every_checker_code`), 79

  purpose: the checker's contract spawns the real `mimz` binary per

**Two genuine pre-existing bugs surfaced while building the contract
test** — filed as BUG-26/BUG-27 in `docs/audit/bugs.md`, not fixed
inline (out of a test-writing task's own scope):

- **BUG-26**: `resolve_module`'s own "unknown module" `S0101` arm is
  dead code — its only caller (`resolve_target`) always pre-checks
  `reg.contains_key` before calling it, so a genuinely unknown bare
  module reference always reports through `S0105` instead (correct
  message, wrong of two codes meant to mean slightly different things).
- **BUG-27**: `Env::resolve`'s own combinational-cycle `S0238` Diag
  never survives to a caller intact — a cycle can only be detected on a
  re-entrant `resolve()` call, and every re-entrant call crosses the
  `Resolver::signal` trait boundary, which (Phase 2's own "leave the
  trait alone" design) bridges the result down to a flat `String`,
  losing the code; the outer `eval_ctx` Ident-read then re-wraps it as
  `S0201`. The condition and message are both correct; only the code is
  lost.
