# 2026-08-29

## Fuzzer regression: panic on two sibling modules sharing a local enum name

`lex_parse_compile` (fuzz target) found a crash: `build_decls: 'State' is
bundle-typed — nested bundle fields are not supported by build_decls`
(`crates/mimz-core/src/emit_verilog/module/ports.rs:506`), on a source
where two DIFFERENT modules in the same file each declare their own
module-local `enum State { .. }` — an ordinary FSM pattern, not a checker
error (module-local enum names are scoped to their own module, so reusing
one across sibling modules is legal).

Root cause: `Project::resolve_enum` (`emit_verilog/mod.rs`) resolves a bare
enum name against a FLAT per-file table (`enums: HashMap<String, Vec<(file,
&EnumDecl)>>`) - both modules' `State` land under the same key in the same
file, so it sees 2+ candidates and returns `None` ("ambiguous"), even though
each reference is completely unambiguous in its OWN module's scope. The
checker's own equivalent lookup (`Checker::lookup_enum`,
`checker/names/resolve.rs`) already does the right thing - module scope
first (via `Scope`), file-level table as fallback - but the emitter never
mirrored that algorithm; it only had the flat, checker-unaware table.
`resolved_kind`'s `None` branch then assumed "not an enum" implies "must be
a nested bundle" and panicked instead of erroring.

Fix: added `Emitter::cur_module_enums` (`emit_verilog/mod.rs`), the CURRENT
module's own `enum` items by name, populated in `module()`
(`module/mod.rs`) and `emit_testbench()`'s DUT setup (`testbench.rs`) -
mirroring `cur_decls`'s own "reset/installed per module" convention. New
`Emitter::resolve_enum` (`module/ports.rs`) checks it first, falling back to
`Project::resolve_enum`; the three `Type::Named` call sites
(`width_subst`, `scalar_kind_in_env`, `resolved_kind`) now go through it
instead of `self.project.resolve_enum` directly. Required threading an
explicit `'a` through `emit()`'s signature and `Emitter::module()`'s `m`
parameter (both previously let the compiler pick independent, shorter
elided lifetimes) so `cur_module_enums` can borrow `&'a EnumDecl` from the
module's own AST.

Regression test added:
`crates/mimz-core/src/emit_verilog/tests/module_scoped_enums.rs`'s
`sibling_modules_with_same_named_local_enum_do_not_panic` - two sibling
modules, each with its own `enum State`, run through the full check+emit
pipeline (a `compile_one`-equivalent, since `enum` width facts need the
checker's pass first). Also filed as
[BUG-76](../audit/bugs/bug-71-80.md#bug-76-medium-fixed-2026-08-29--two-sibling-modules-each-declaring-their-own-same-named-local-enum-panicked-the-emitter-misreporting-itself-as-an-unsupported-nested-bundle).

**Verification:** `cargo test -p mimz-core --lib` - 679/679 (was
678/678 plus this new one, all pass). `cargo test --workspace` - full
suite green (1321/1321, `docs/code/10-test-map.md` + README badge synced).
`cargo fmt`/`clippy -p mimz-core --lib -D warnings` clean.

## Fix musl cross-compilation for release

**Problem:** the `release.yml` job for `x86_64-unknown-linux-musl` failed:
`alsa-sys`'s build script panicked ("pkg-config has not been configured to
support cross-compilation"). `hw-emulation` (a default feature) pulls
`cpal`, which links against ALSA via `pkg-config` on Linux; the musl
sysroot has neither a cross-aware `pkg-config` nor ALSA's dev headers, so
the build script aborts before any Rust code compiles.

**Decision:** build the musl release target with `--no-default-features
--features lsp,bench,watch` - dropping only `hw-emulation`
(`ratatui`/`crossterm`/`cpal`) - rather than fixing the cross pkg-config
setup itself. `hw-emulation` is a real feature GAP for that one release
artifact (no `--emulate` terminal dashboard or audio peripheral on the
shipped musl binary), not merely a CI-internal difference: the other three
release targets (Windows MSVC, macOS x2) keep full default features.
Coarser than strictly necessary too - only `cpal`/ALSA is what's
cross-compile-broken; `ratatui`/`crossterm` have no such issue, but
`hw-emulation` bundles all three behind one feature flag
(`Cargo.toml`), so there was no finer-grained way to keep the
terminal dashboard while only dropping audio without splitting the feature.

**Fix.**

1. `.github/workflows/release.yml` - the musl target's build step now runs
   `--no-default-features --features lsp,bench,watch` (`if [ matrix.musl
== "true" ]`); every other target is unchanged. Explicit `shell: bash`
   added to that step so the conditional runs identically on the Windows
   runner too (its default shell is `pwsh`).
2. `src/commands/test.rs` - `mimz::emulate` is itself
   `#[cfg(feature = "hw-emulation")]`-gated (`src/lib.rs:68`), so
   `test_file`'s unconditional `mimz::emulate::host::EmulateHost::new(..)`
   would not compile at all without the feature. Now `#[cfg]`-split: the
   real host under `hw-emulation`, a new headless `NullHost` otherwise.
3. `crates/mimz-sim/src/sim/host.rs` - added `NullHost`, a trivial
   `EmulationHost` implementor that errors on `bind` ("hardware emulation
   is disabled in this build") and no-ops everything else. `mimz-sim` has
   zero optional/native deps already (`EmulationHost`'s own doc comment:
   "zero knowledge of ratatui/cpal") - the right home for a headless
   default implementation of its own trait, not a shell-crate duplicate.

**Verified.** `cargo build -p mimz --bin mimz --no-default-features
--features lsp,bench,watch` (native target - the actual musl
cross-compile can't run on this box) compiles clean, and
`cargo clippy ... -D warnings` on the same flag combination is clean too
(zero warnings, not just zero errors - confirms `live`/`step` still route
somewhere real under `NullHost`, no dead-code fallout). Default
(`hw-emulation`-on) build re-checked afterward, still compiles clean - the
`#[cfg]` split isn't one-sided.

**Not done, worth a follow-up if the dashboard is wanted on musl too:**
splitting `hw-emulation` into an audio-only (`cpal`) sub-feature and a
display-only (`ratatui`/`crossterm`) one, so the musl build could keep the
terminal dashboard and drop only what pkg-config can't cross-compile.
