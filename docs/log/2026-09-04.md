## Decision: Phase 2 IR complete — folded into committed docs

Tasks 1-19 of `docs/plan/phase-2-ir-plan.local.md` are done: `mimz_core::ir`
now exists as a real compiler stage between the checked AST and any future
synthesis backend.

**What shipped:**

- Data model: bit-addressable `NetId`/`Bits` (LSB-first), `Cell`/`CellKind`
  (30 variants: arithmetic, logic, compare, mux, concat, slice, `Dff`, `Mem`,
  `BlackBox`, `Const`), `Module` (ports, cells, nets, `signals` for named-net
  lookup, `extern_decls`).
- Lowering: `elaborate::Design` → `Module` (`ir/lower.rs`) — registers to
  `Dff`, memories to `Mem` with independent read/write address pins, `fn`
  calls inlined via continuation-splicing, `match`/`if` to mux trees, `extern
module` instances to `BlackBox` cells.
- Two text formats: line-based (printer + parser, round-trips, hand-writable
  fixtures) and s-expr (printer only, dump-format, no parser in v1).
- Validation pass (`ir/validate.rs`): 5 checks — multiple drivers, undriven
  nets, pin width/arity, combinational cycles, black-box port shape.
- IR executor (`ir/exec.rs`) and an IR-vs-kernel differential fuzz leg
  (`tests/differential_fuzz.rs`), satisfying the plan's simulation-equivalence
  exit criterion for everything the lowering pass reaches.
- Golden IR-text snapshots (`tests/golden/ir/`, 5 fixtures) and a
  validation-rejection fixture corpus (`tests/fixtures/ir_errors/`, 4
  fixtures — the 5th, black-box port mismatch, isn't constructible via the
  text format in v1, a documented gap, not an oversight).

**Known, documented v1 gaps** (`docs/audit/gaps.md` GAP-1), none blocking:
builtin function calls (e.g. `extend`) have no lowering path yet (real,
separate feature work); `Shl`/`Shr` diverge from the AST simulator in three
specific ways; memories support a single read port; the text format doesn't
round-trip `extern_decls`/`signals`; `validate.rs`'s driven-set seeding is
direction-blind, so an undriven `out` port can pass validation silently.

## IR: `extend`/`trunc` lowering (GAP-1, task 1 of 7)

`ir::lower` previously sent every `ExprKind::Call` to the catch-all
`unimplemented!()` — no builtin had a lowering path. `extend` and `trunc` now
lower for real:

- `trunc(x, N)` is a slice of the low `N` nets — no cell, same as `Slice`.
- `extend(x, N)` concatenates a `Const{0}` pad onto `x`'s own nets when it
  grows, and is the identity when `N <= width(x)`.

`extend` must choose between zero- and sign-extension, but `ir::Bits` carries
no signed bit in v1. Rather than guess, `LowerCtx::arg_is_definitely_unsigned`
proves the argument unsigned for exactly the shapes real programs use
(literals, `unsigned(x)`/`encoding(e)`, and plain unsigned module-level
signals via the new `LowerCtx::declared_signed`); anything it cannot prove is
refused with a loud `unimplemented!("...cannot prove...")`. Silently
zero-extending a signed value would be wrong hardware, so the refusal is the
feature.

Remaining builtins still hit a (now builtin-specific) catch-all — GAP-1 stays
OPEN; `signed`/`unsigned`/`encoding`, `nand`/`nor`/`xnor` and a loud refusal
for `min`/`max`/`abs` are later tasks in the same plan.

New tests: `crates/mimz-core/src/ir/tests/lower_builtins.rs` (4). Test count
1385 → 1389 in `docs/code/10-test-map.md` and the README badge.

## IR: `nand`/`nor`/`xnor` lowering (GAP-1, task 3 of 7)

No new `CellKind` needed: `Builtin::Nand | Builtin::Nor | Builtin::Xnor` lower
by composing an existing reduction cell (`RedAnd`/`RedOr`/`RedXor`) with the
existing `LogicNot` cell — `nand(x)` = `!(&x)`, `nor(x)` = `!(|x)`, `xnor(x)`
= `!(^x)`. A reduction's result is always 1 bit unsigned, so no signedness
question arises here (unlike `extend`).

Factored `LowerCtx::push_unary_cell` out of `ExprKind::Unary`'s own inline
cell-push (mirroring the existing `push_binary_cell`) so both the `Unary` arm
and this new composition share one 1-input/1-output cell constructor; no
behavior change to `Unary` itself (confirmed by the unchanged `ir::` suite).

New tests: `nand_composes_redand_then_logicnot`,
`nor_composes_redor_then_logicnot`, `xnor_composes_redxor_then_logicnot` (3)
in the same `lower_builtins.rs`. Test count 1390 → 1393 in
`docs/code/10-test-map.md` and the README badge; also corrected the
`crates/mimz-core/src/**` (lib unit) row from a stale 818 to the right
absolute value (819 + these 3 = 822), a pre-existing off-by-one a prior
task's review had flagged but left for whoever next touched that row.

Remaining builtins still hit the catch-all — GAP-1 stays OPEN; a loud refusal
for `min`/`max`/`abs` (and making the `match func` exhaustive) is task 4 of
the same plan.

## IR: `Shl`'s `out` pin now grows instead of truncating (GAP-1, task 5 of 7)

`ir::lower`'s `lower_binop` sized `CellKind::Shl`'s `out` pin at `a.width()`,
so a growing left shift silently truncated. It now calls the same shared rule
the AST side uses — `width_rules::shift_result(lhs, amount, None, true)` —
sizing `out` at the worst-case growth (`a.width() + 2^b.width() - 1`).
`const_amount` is always `None` here because `lower_binop` only ever sees
already-lowered `Bits`, never the source `Expr`; that matches
`value::binary`'s own fallback exactly, and over-growth is safe (the extra
high bits are zero, and comparisons happen at the source-declared width).
`Shr` is unchanged — `shift_result`'s `grows: false` rule keeps the left
operand's width, which `a.width()` already was. `ir::validate`'s
`expected_widths` gained a matching `CellKind::Shl` arm so lowering and
validation cross-check each other, and `ir::exec`'s "v1 limitations" doc
comment now lists only the remaining fused-shift-chain divergence. New tests:
`shl_grows_the_output_to_the_worst_case_width_not_the_input_width`
(`ir/tests/lower_binops.rs`) and
`rejects_a_shl_cell_whose_out_is_narrower_than_the_worst_case_growth`
(`ir/tests/validate.rs`). Test count 1396 → 1398 in
`docs/code/10-test-map.md` and the README badge (lib-unit row 825 → 827).

## IR: `validate.rs`'s driven-set seeding no longer direction-blind (GAP-1, task 6 of 7)

`ir::validate`'s driven-set seeding loop over `module.ports` destructured a
port's `Dir` into `_dir` and never read it, so BOTH input and output ports
got marked "driven" unconditionally — a module declaring an `out` port that
no cell's `out`/`q`/`rdata` pin ever actually wrote passed validation
silently instead of raising `UndrivenNet`, defeating the exact check that
exists to catch it. The loop now reads `dir` for real and only seeds the
driven-set from `Dir::In` ports; an `out` port's nets must be driven by some
cell like any other net. GAP-1's "driven-set seeding is direction-blind"
sub-gap is now CLOSED.

New tests: `rejects_an_output_port_never_driven_by_any_cell`
(`ir/tests/validate.rs`, hand-built module with an undriven `out` port) and
`undriven_output_port_fixture_is_rejected` (`tests/ir_validation.rs`, new
fixture `tests/fixtures/ir_errors/undriven_output_port.ir`). Confirmed no
regression: the full existing `ir::tests::validate` suite and
`differential_fuzz_clocked_ir_matches_kernel` (whose generator drives every
output port by construction) both still pass. Test count 1398 → 1400 in
`docs/code/10-test-map.md` and the README badge (lib-unit row 827 → 828,
`tests/ir_validation.rs` row 4 → 5).
