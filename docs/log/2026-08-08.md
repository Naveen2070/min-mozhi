# 2026-08-08

## BUG-41 + SEC-10 closed — self-determined hoist gate collapsed to one exhaustive match

Task 2 of `docs/plan/v0.2-correctness-remediation.local.md`. The gate
deciding whether `emit_verilog`'s hoist machinery runs at all
(`expr::kind_is_inferrable`) and the classifier it gated
(`kinds::infer_kind`) were two hand-synced matches over the same
`ExprKind`/`Builtin` enums — `self_determined.rs` had already been made
exhaustive (BUG-28/29), but the gate in front of it still ended in
`_ => false`, silently disabling the hoist for any expression containing a
`fn` call, an instance port, an `if`, a `match`, or a memory read. BUG-41
reopened BUG-28's exact defect through those shapes; the gate's own
`panic!`-on-unhandled-shape design was SEC-10's adjacent concern.

**Fix.** `kinds::infer_kind` now returns `Option<Kind>` directly —
`None` where the gate used to say `false` — so there is one function to
keep exhaustive, not two to keep in sync. Filled in the five previously
unclassified shapes: `FnCall` (the `fn`'s declared return type),
`Field` (an instance's output-port width), `Index` (a memory's element
width, or 1 bit for an ordinary bit-select), `IfExpr`/`Match` (either
branch/any arm — the checker guarantees they agree). All five resolve
through the same `decls: &HashMap<String, Kind>` map `infer_kind` already
took — `build_decls` (`module/ports.rs`) now also populates it with
instance-output-port kinds (keyed `{inst}_{port}`, matching `expr.rs`'s
own `Field` rendering), memory-element kinds (`mem_elem_decl_key`), and
`fn`-return kinds (`fn_ret_decl_key`), so `infer_kind`'s signature never
grew a second parameter. `hoist_if_needed` now takes the already-resolved
`Kind` from its caller instead of re-deriving (and potentially
re-failing to derive) it internally.

**Tests.** Five new Icarus differentials in
`tests/self_determined_regression.rs`, one per BUG-41 repro (fn-call
operand, instance-port operand, if-expr operand, memory-read operand,
`extend` through a `fn` call — the last reproduces BUG-28's original wrong
emission byte-for-byte through the new shape). Watched all five fail
against the pre-fix code before implementing.

## BUG-45 found and fixed — hoisted wires spliced in before the declarations they reference

Verifying BUG-41's fix (in an environment with Icarus Verilog 14.0,
vs. the audit's own 12.0 baseline) surfaced a second, unrelated,
pre-existing bug: hoisted `wire __mimz_sub_N`/`assign` pairs are spliced
into the module body right after the port list — before `wire`/`reg`/
`mem` declarations and before instances are emitted. Any hoist
referencing one of those forward-references a declaration that appears
later in the file, which Icarus 14.0 rejects ("declaration after use")
even though Verilog module items are order-independent by the language
spec — 12.0 evidently tolerated it. Confirmed pre-existing (not caused by
the BUG-41 work above) three ways: reproduced on a fully unmodified
checkout via `git stash`, hit an already-shipped example
(`examples/english/shift_register.mimz`) and an already-passing
regression test (`bug_23_wrap_under_sibling_add_inside_a_concat_matches_icarus`)
neither of which this session touched, and confirmed that manually
reordering the emitted Verilog (declarations before hoists) makes Icarus
accept it unchanged.

**Fix.** A second insertion point (`hoist_pos`) captured after
`emit_instances` runs, used for `self.hoisted_decls` specifically; the
`clog2`/user-`fn` injection stays at the original `fn_pos` (function
declarations aren't order-sensitive in Verilog — confirmed empirically,
nothing regressed). Full detail: `docs/audit/bugs.md` BUG-45.

Fixing this unmasked two independent, already-broken self-checking
testbenches that had simply never run to completion before in this
environment:

- `tests/icarus/sc_pid_controller_tb.v` — wrong hand-calculated expected
  `control` values at cycles 3–4; the comments assumed the PI controller's
  `integral` term stays constant across a held-input cycle, but it is
  (correctly) cumulative. Re-derived the true values from Icarus itself
  and corrected the comments and assertions.
- `tests/icarus/sc_vga_pattern_tb.v` — an off-by-one tick count
  (`repeat(655)` one short of the `h_cnt=656` the next check assumes).

Neither the PI controller nor the VGA pattern generator design was wrong;
only the hand-written testbenches' arithmetic was.

Also regenerated Verilog goldens (`MIMZ_UPDATE_GOLDENS=1`) and rebuilt
`crates/mimz-wasm/pkg` (`wasm-pack build crates/mimz-wasm --target web
--release`) — both were comparing against the old declaration order.

## BUG-46 found, filed, not fixed

Same verification pass surfaced a third, separate, genuinely open bug:
`showcase/english/melody_player.mimz` emits `((dur) * TICK)[(32)-1:0]` — a
part-select on a composite expression, which is a syntax error in any

(`self_checking_showcase_testbenches_pass`, `melody_player`); `fmt`/

## BUG-46 fixed — module parameter is just `Ty::CtInt` under another name

Revisited the same session: the "real width-rules design work" this bug
was filed against turned out to be the wrong framing. A module `int`
parameter never needs a symbolic-width hoisted wire — it needs to _adapt
to its sibling operand's `Kind`_, exactly like a bare integer literal
already does (the checker's own `ident_ty` types both as `Ty::CtInt`).

**Fix.** Two new helpers in `kinds.rs`: `adapts_to_sibling` (true for a
bare literal OR an `Ident` absent from `decls` — by this file's own
module-body-only domain, the latter can only be a module parameter) and
`adapted_lossless_operands` (resolves such an operand to its sibling's own
`Kind`, mirroring the checker's `adapt_lossless` growth rule for the
`Add`/`Sub`/`Mul` family). The pre-existing `is_bare_int`-only check in the
`AddWrap`/`BitAnd` family's arm widens to the same `adapts_to_sibling`,
matching `matched_ty`'s no-growth rule. `dur * TICK` now resolves to a
64-bit `Kind`, which is enough for `Trunc`'s base-hoist to fire.

**Verified** directly against Icarus (`wire [63:0] __mimz_sub_1; assign
__mimz_sub_1 = ((dur) * TICK); ... dur_cnt <= __mimz_sub_1[(32)-1:0];`),
then via `self_checking_showcase_testbenches_pass` (now passing) and the
full workspace suite (`REQUIRE_IVERILOG=1 cargo test --workspace
--release --no-fail-fast`) — one other showcase (`tamil-pure`'s `isai`,
same `TICK`-multiply shape) picked up the same hoist. Goldens regenerated
(`MIMZ_UPDATE_GOLDENS=1`) and `crates/mimz-wasm/pkg` rebuilt to match the
new (cosmetic-only) hoisted wire. New unit test:
`lossless_mul_with_a_module_parameter_adapts_to_the_sized_operand`
(`kinds.rs`). `docs/audit/bugs.md` BUG-46 and `docs/audit/security.md`
SEC-10 (closed by the same underlying `infer_kind` work back in Task 2,
but never updated from OPEN until now) both updated to FIXED. `fmt`/
`clippy -D warnings` clean.

## Task 3 (BUG-42) closed — `min`/`max` recurses into its own operands

`self_determined.rs` classified `Min | Max => None` on the reasoning that
both operands are same-width by the checker's own rule, so no mismatch is
possible — true of mimz's widths, false of Verilog's SELF-DETERMINED
widths. `min(extend(p, 11), extend(p, 11))` (`p: signed[6]`) renders as
`(((p) < (p)) ? ((p)) : ((p)))` — each `(p)` self-determines to 6 bits,
not mimz's 11, so the whole ternary self-determines to 6 bits and Verilog
zero-extends that into an 11-bit destination instead of sign-extending
mimz's own correct 11-bit result (2039 vs. 55).

**Fix.** `Min | Max` now recurses into both operands and takes `max` of
their own self-determined widths, the same shape `SignedCast`/
`UnsignedCast` already used. Re-audited every other arm under the
corrected question this bug exists to teach — "is this argument's
_rendered_ width necessarily its mimz width?", not "is this operator's
_result_ width necessarily its mimz width?" — all four survive unchanged
(`Trunc`, the three reductions, the three recursing casts/`Encoding`).
Recorded the corrected question in the file's own module doc comment.

**Tests.** `bug_42_min_max_mismatched_operand_matches_icarus`
(`tests/self_determined_regression.rs`), the bug's own filed repro,
watched fail pre-fix (kernel 2039, Icarus 55). Full workspace green
(1212 tests, `REQUIRE_IVERILOG=1`); `fmt`/`clippy -D warnings` clean.
