### Decision: the IR spec is a compiler contract, not language

- **Context:** exit criterion #1 asks for a spec addendum; `spec/` so far
  defines only the language and its simulator.
- **Decision:** `spec/07-ir.md` carries its own version (v0.1) and states up
  front that changing the IR never changes a program's meaning. It is not
  tied to the language edition.
- **Why:** the IR will change often during synthesis work (async reset,
  signed round-trip); tying it to editions would force edition bumps for
  internal changes. Rejected: folding it into `docs/architecture.md` alone,
  which the exit criterion names separately.
- **Impact:** `spec/07-ir.md`, `spec/README.md`.

## Fixed: constant-`if` fold panic on a dead branch that names nothing (task 3)

- Repro: `o[i] = !(if i == 0 { 0 } else { s[i - 1].y })` in a `repeat`
  (`tests/fixtures/ir_cli/internal.mimz`): `mimz ir` reported an internal
  error, `no driver recorded for signal s__-1_y` at `lower.rs:185`.
- Root cause: `elaborate` rewrites both branches of an `if` before anything
  folds (`rewrite.rs`, `arr[i].port` -> `arr__<n>_port`), so the dead branch
  can name a wire that was never created. `lower_if`'s
  `(constant taken, real dead, no target width)` case lowered both branches
  so the constant could borrow its sibling's width.
- Width evidence first (probe `n = ~(if K == 0 { 0 } else { a })`,
  `a: bits[8]`, `a = 0x05`): the checker types the `if` as both branches
  unified (8 bits); Verilog gives `0xFF`; the IR (both branches lowered)
  gives `0xFF`; `mimz sim` gives `1` (filed as BUG-77). So lowering the
  dead branch is right whenever it can be lowered.
- Fix: new `LowerCtx::names_resolve` (walks every `ExprKind`); the dead
  branch is lowered only when every name it reads exists, otherwise only the
  taken branch, at its natural width (what `mimz sim` does). A `match` on a
  constant is `E0405` and an out-of-range vector index is `E0406`, so `if`
  is the only route.
- 2 tests in `ir/tests/lower_if.rs`, RED first (the panic). Forcing
  `names_resolve` to `true` fails the phantom test; forcing it to `false`
  fails the width-guard test (`0x01` instead of `0xFF`).
- The fix removed the only internal-error reproducer for `mimz ir`'s CLI
  tests (3 failed, as gaps.md predicted). New real reproducer: a LIVE read of
  `s[i - 1].y` (`if a[3] { 0 } else { s[i - 1].y }`). The checker accepts
  it, `mimz compile` writes Verilog Icarus rejects (syntax error), and
  `mimz ir` hits the same missing-driver panic. Filed as BUG-78; fixture and
  `ir/tests/failure.rs`'s `INTERNAL` updated, all assertions unchanged.
- Still OPEN (gaps.md): with a phantom dead branch the constant keeps its
  natural width, which differs from the checker and Verilog in a
  width-sensitive position. Needs the instance-array port width carried
  through `elaborate`, or BUG-77/BUG-78 fixed together.
- Docs: gaps.md (sub-gap RESOLVED, narrower limit OPEN, CLI-fixture note),
  `bugs/bug-71-80.md` + index (BUG-77, BUG-78), test map + README badge
  1568 -> 1570.
- Verification: 1570/1570 workspace tests (`REQUIRE_IVERILOG=1`), clippy
  `-D warnings` clean, fmt clean, rustdoc `-D warnings` clean.

## Decided: synthesis backend format (task 4)

- Evidence: one test design (9-bit registered add, 8-bit mux, 16x8 memory
  with a combinational read) through Yosys 0.69 (OSS CAD Suite 20261001, via
  the shims). `write_json` gives cells with explicit width/sign parameters
  (`$add`: `A_WIDTH`, `A_SIGNED`, `Y_WIDTH`, ...) and bit-numbered
  connections, the same one-number-per-bit model as `ir::NetId`; the
  memory is `$mem_v2` with 21 parameters. `read_json` and `read_verilog` of
  the same design both run `synth_ice40 -noabc` to identical hardware:
  309 cells (164 `SB_LUT4`, 128 `SB_DFFE`, 9 `SB_DFF`, 8 `SB_CARRY`).
- The 128 `SB_DFFE` are the memory: a combinational read cannot use iCE40
  block RAM. Recorded as a known limit in the phase plan.

### Decision: synthesis v1 emits structural Verilog first, then a Yosys JSON netlist

- **Context:** the phase plan left "IR → structural Verilog **or** direct
  Yosys JSON netlist" open; synthesis v1 needs one before code.
- **Decision:** synthesis v1 has two phases, both emitting from the IR.
  Phase 1: IR → structural Verilog-2005 (one operation per line, explicit
  widths and signs) → `read_verilog` → `synth_ice40` → nextpnr → icepack.
  Phase 2: IR → Yosys JSON netlist (`read_json`), a second backend from the
  same IR, not a conversion of the Verilog.
- **Why:** Verilog first because one file serves Yosys, Icarus, vendor tools
  and people; Icarus gives an independent check of the IR → Verilog step
  with the differential harness that already exists; Yosys infers memories
  itself; and `architecture.md` already plans moving the Verilog emitter
  onto the IR. JSON second because it maps 1:1 onto the IR with no Verilog
  width/sign rules in between (the source of past emitter bugs), but only
  Yosys reads it and memories tie it to the internal `$mem_v2` cell, whose
  format has changed before. Rejected: JSON only (Yosys-only, no Icarus
  check without a Yosys round trip); Verilog only (the user asked for both).
- **Impact:** `docs/plan/phase-2-ir-synthesis.md` (Synthesis path),
  `ROADMAP.md` (IR/synthesis track, which still said "not started"),
  `docs/architecture.md`.
