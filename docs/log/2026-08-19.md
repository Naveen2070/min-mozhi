## Triaged a stale fuzz-crash report; filed BUG-72

### Summary

User pasted a `pretty_roundtrip` fuzz-job crash log (libFuzzer, `MS: 1 ChangeASCIIInt-`) showing `hoist_unresolved`'s `debug_assert!` panicking on a mutated `shift_register.mimz` — `&trunc(sr << 1, WIDTH)` inside a reduction. Verified whether this is still live at HEAD before filing anything.

### Investigation

- Traced the panic to `kinds::infer_call`'s shared `Extend | Trunc` arm (`kinds.rs:530-537`): it folds the width argument with `const_fold`, literal-only, so a module `int` parameter (`WIDTH`) makes `infer_kind` return `None` for both builtins alike.
- `try_widen_symbolic_extend` (`expr.rs`) is the round-6 recovery path for exactly this case at all 8 self-determined-position call sites (reduction operand, concat/replicate member, `$signed`/`$unsigned`/`encoding` operand, `nand`/`nor`/`xnor` operand) — but it matches `Builtin::Extend` explicitly and returns `None` immediately for `Builtin::Trunc`. No equivalent narrowing fallback exists for `Trunc`.
- Reproduced the exact mutated shape (`examples/english/shift_register.mimz` + a `&` before `trunc`) against both `target/debug/mimz` and `target/release/mimz` at HEAD (`a9e67d8` + bench commit). Neither panics: `mimz check` OK, `mimz compile` exits 1 with a clean `Diag`. Round-7 plan Task 2's `cfg!(test)` gate (BUG-67/68) holds in both binaries — the crash log's panic mode is not reproducible at HEAD, meaning the CI artifact predates commit `dfafccd`.
- What survives is real: a checker-accepted, `extend`-symmetric construct (`trunc(x, <module parameter>)` in a self-determined position) cannot be compiled at all, on any binary/profile. Not silent, not a crash — a hard compile failure for a design one `&` away from a shipped example.

### Filed

- **BUG-72** (MEDIUM, OPEN) — `docs/audit/bugs/bug-71-80.md`. Root cause, repro, and fix shape (mirror `Extend`'s `try_widen_symbolic_extend` arm with a `Trunc` narrowing arm — `x[(W)-1:0]` off `args[0]`'s own resolved `Kind`).
- Indexed in `docs/audit/bugs.md` (severity table + "Still open" table; range count `bug-71-80.md` 1 → 2).
- Added as **Task 10** to `docs/plan/v0.2-class-closure-round8.local.md` — not ship-blocking (round-8's four ship-blocking items are BUG-70/71/the invariant widening/docs, all pre-existing); folds into the same PR or the one after per the plan's own effort table.

### Verdict

Not a live crash. A real, separate compiler-limitation bug, now tracked. No code changed — round-8 Tasks 1–9 are still the next work.

## Round-8 plan Task 1 — BUG-70: two-pass `emit_instances`

### Summary

Created branch `round8-class-closure` off `develop` and implemented round-8 plan Task 1: fixed BUG-70 by splitting `emit_instances` (`crates/mimz-core/src/emit_verilog/module/instances.rs`) into two passes, restoring `pre_decl_hoist_pos`'s own safety argument instead of adding a fourth buffer (the plan's stated preference over the smaller buffering alternative).

### Root cause (recap)

BUG-66's fix (round-7 Task 3) captures `pre_decl_hoist_pos` once, before the `mem`-init/`reg`-reset/instance render window, on the argument "every signal these sites can reference is already declared by then." True for ports/parameters, false for an instance's own output wire — `emit_instances` used to declare that wire INLINE, interleaved with the next instance's connection rendering, so a hoist raised by instance N's connection (reading instance N-1's output, e.g. `u1.q`) got spliced ahead of `u1`'s own wire.

### Fix

- New `declare_instance_outputs`/`declare_one_instance_outputs` (`module/instances.rs`): a pure declaration walk (same `Inst`/`Repeat`/`ForEach`/`ConstIf` traversal as `emit_instances`) that declares every instance's output wire — bundle fields included — using only `width_subst`/`width_resolved`, neither of which can hoist.
- Called from `module()` (`module/mod.rs`) right after the module's own "Declarations" loop, before `pre_decl_hoist_pos` is captured — so every instance output this module can ever reference already exists in `self.out` at a position earlier than the splice point, restoring the safety argument for real.
- `emit_instances`'s own `Dir::Out` arm no longer writes the `wire` line (the pre-pass already did) — it only names the wire for `port_conns`.
- Resolution failures (unknown module) are deliberately not diagnosed in the new pre-pass — `instance()`'s own connections pass still does, avoiding a double-reported error; emit only ever runs on already-checked programs so this path is untaken in practice.

### Verification

- Both filed BUG-70 reproductions (instance-port hoist, `mem`-init hoist) plus a third repeat-unrolled-array variant added as permanent regressions in `tests/self_determined_regression.rs`: `bug_70_instance_port_hoist_reading_an_earlier_instance_output_matches_icarus`, `bug_70_mem_init_hoist_reading_an_instance_output_matches_icarus`, `bug_70_repeat_unrolled_instance_array_variant_matches_icarus`.
- Watch-fail-first: stashed the two changed files, reran the three new tests — all three fail with the exact "declaration after use" on `u1_q` the bug describes; unstashed and reran — all three pass.
- Four goldens regenerated (`MIMZ_UPDATE_GOLDENS=1`): `chained.v`, `ripple_adder.v`, `showcase_uart_echo.v`, `showcase_tamil_pure_edhiroli.v` — all four diffs are pure reordering (instance output wires now grouped before all instantiation lines), zero value/connection changes, confirmed by hand.

## Round-8 plan Task 2 — widen the declaration-order invariant to every declared identifier

### Summary

Widened `assert_hoists_declared_before_use` (`crates/mimz-core/src/emit_verilog/mod.rs`) from scanning only `__mimz_sub_N`/`__mimz_fn_sub_N` hoisted names to every `wire`/`reg` declared in the module body — the actual axis GAP-18 describes. This is the change the round's "ship `v0.2.0` without an RC" call hinges on.

### What changed

- New `identifiers_in` (generic whole-word identifier tokenizer, replacing the two-fixed-prefix `hoisted_names_in`), `strip_instance_port_names`, `strip_string_literals`, `declared_name_of_wire_or_reg_line`, and `FunctionSkipState` (tracks `function ... endfunction` nesting) in `emit_verilog/mod.rs`.
- `assert_hoists_declared_before_use` rewritten around these: collects every `wire`/`reg` declaration's name (skipping injected `function` blocks, comments, and the module header), then scans every other line (with instance-port names and string-literal contents stripped) for references to those names, asserting none appears before its own declaration line.

### The four traps the plan named, all handled

Declaration self-reference, string-literal contents, `.portname(signal)`'s port half, and the module header's port names — implemented per the plan's own guidance.

### Two more traps found only empirically (re-running the full suite after each change, not by inspection)

1. **`function`-scope collision**: `CLOG2_FN` (injected at `fn_pos`, before every module-level declaration) declares its own `input integer value;` — a real shipped example (`examples/english/counter.mimz`) separately declares `reg value: bits[WIDTH]`. Without excluding injected function bodies from the scan, this is a false positive the moment a design uses both `clog2()` and a wire/reg named `value`. Fixed by skipping `function ... endfunction` blocks entirely (a separate Verilog scope).
2. **`last-identifier-before-`;`` is wrong for two shapes**: a `mem` declaration (`reg [W-1:0] name [0:(depth)-1];`) puts the depth bound's own identifier LAST in the line, not the name (`std/fifo.mimz`'s `DEPTH`, `examples/tamil-pure/varisai.mimz`'s `aazham` both hit this); and a keyword like `reg` is a character-suffix of a real name that happens to end in those letters (`reg filter_out_reg;` naively "ends with" `reg;`). Fixed by taking the FIRST identifier after the width bracket closes instead of the last token before `;`.

### A third, previously-unknown defect found and filed (not fixed — out of scope)

Excluding the module header from the usage scan (needed for the reasons above) surfaced that bundle-typed `wire` flattening (`{wire_name}_{field_name}`, `module/mod.rs:252`) never checks the generated name against existing ports/wires/regs. `wire a: HasUART = { tx: a_tx, rx: a_rx }` in a module that also has ports `a_tx`/`a_rx` produces `wire a_tx; assign a_tx = a_tx;` — a duplicate declaration AND a self-referential tautology, losing the real binding entirely. Confirmed with real Icarus: `'a_tx' has already been declared in this scope`. Filed as **BUG-73** (HIGH, OPEN, `docs/audit/bugs/bug-71-80.md`) — a different subsystem (bundle flattening) than round-8's own scope (hoisting), not fixed here.

## BUG-73 — fixed on request

### Summary

Fixed BUG-73 (bundle-typed `wire` flattening colliding with an existing port/wire/reg) at the user's request. Not part of round-8's own scope (a bundle-flattening naming defect, not hoisting), but small and well-isolated.

### Fix

Same shape as BUG-4's own fix (colliding sanitized testbench names) — diagnose, don't rename. New `Emitter::declared_signal_names: HashSet<String>` (reset per module) and `declare_signal_name(&mut self, name, span) -> bool` (`crates/mimz-core/src/emit_verilog/mod.rs`): records a name the first time it's declared; on a repeat, pushes a `Diag` naming the collision instead of silently emitting a second declaration. Wired into all three sites that compute a name for something about to be declared, in emission order: the header port loop (ports, clock, reset, bundle-flattened port fields), the "Declarations" loop (`Wire`/`Reg`/`Mem`, bundle-flattened `Wire` fields), and `declare_instance_outputs` (round-8 Task 1's own pre-pass — instance auto-wires, bundle-flattened fields included). `fn`-body-local declarations are deliberately excluded (a separate Verilog scope, matching Task 2's own `FunctionSkipState` reasoning).

### Verification

- The bug's own repro: `mimz check` OK, `mimz compile` now exits 1 with a clean diagnostic instead of emitting `wire a_tx; assign a_tx = a_tx;`.
- Also confirmed the same check catches an instance auto-wire colliding with an unrelated port (two genuinely distinct mimz names — the checker's own duplicate-identifier rule, E0003, doesn't apply) — the "do instance outputs share the same exposure" question the bug's own fix-shape note had left open.
- 3 tests added to `crates/mimz-core/src/emit_verilog/tests/bundle_flatten.rs`: the two collision repros plus a control proving non-colliding bundle wires still flatten normally (no false-positive trap).
- 4 pre-existing test fixtures (`bundle_flatten.rs`, `structural_match.rs`) had this exact incidental collision baked into their own sources (reused matching names for readability) — renamed the colliding wire (`a`/`b` → `wa`/`wb`/`hu`/`hs`) rather than touching what those tests assert.
