# 2026-09-23

## Fixed: GAP-1's last open sub-gap — 24 examples' `Mux` `WidthMismatch`

- Closed the sub-gap Task 8 of the 2026-09-10 plan filed OPEN yesterday:
  `enum_encoding.mimz`, `priority.mimz`, `seg7.mimz`/`ennkaatti.mimz`,
  `sync_loop_search.mimz`, `traffic_light.mimz`/`saalaivilakku.mimz` (all
  flavors) failed `ir::validate` with a real `Mux` `WidthMismatch` — not a
  probe artifact like the 12 cross-file `import` failures.
- Root cause 1: `push_mux_cell` computed `out_width = a.width().max(b.width())`
  but never widened the narrower operand before wiring it into the `Mux`
  cell — `out`'s width was a label, not something the pins were made to
  agree with. `lower_match`'s "every arm constant, no sibling" fallback is
  the one caller that can hand it two really-different-width operands (an
  enum variant's own natural width). Fixed with a new `widen_to` helper
  (zero/sign-extends per the operand's `signed` flag, mirrors
  `Builtin::Extend`'s existing inline logic as a separate copy).
- Root cause 2, independent, found only by chasing the probe past the enum
  repro: `sync_loop_lower.rs`'s desugared `sync loop` counter increment used
  plain `BinOp::Add` (grows one bit) instead of `BinOp::AddWrap` — a `Dff`
  whose `d` pin was wider than its own `q`. One-token fix, matching the
  checker's own E0401 message for the identical hand-written shape. Only
  alters emitted Verilog cosmetically (`4'd1` instead of bare `1`),
  confirmed via `MIMZ_UPDATE_GOLDENS=1` and reading every touched diff.
- Residual gap confirmed and closed: fixing `push_mux_cell` alone only
  equalizes a `match`'s arms against each other, not against whatever
  DECLARED width the whole match feeds — a hand-built regression
  (`match x {0=>10 1=>20 _=>30}` into a declared `bits[8]`) still produced
  `PortWidthMismatch` after that fix alone (no real example hits this; each
  one's widest arm happens to already need the full declared width).
  Threaded `target_width: Option<u32>` into `lower_match`, sourced from a
  new `ExprKind::Match` arm in `lower_expr_sized` — the same "declared type
  stamps directly" rule Task 6 round 3 already established elsewhere,
  applied here for the first time.
- 4 new tests (`lower_mux.rs` × 3, new `lower_sync_loop_width.rs` × 1); one
  pre-existing test's assertion corrected (it was unknowingly asserting the
  pre-fix exact-net-identity behavior); one more pre-existing test needed no
  edit at all — passes now by construction.
- Coverage probe: 188/224 → **212/224**. Every real example now clears
  `ir::validate`; only the 12 documented cross-file artifacts remain.
- `cargo test --workspace` clean (1484/1484), `cargo clippy --workspace
--all-targets -- -D warnings` clean, `cargo fmt --all --check` clean,

  has no semantic divergence). `wasm-pack build crates/mimz-wasm --target
web --release` rebuilt (pkg existed locally); `wasm_parity` clean. Test-count

- Executed inline (`superpowers:executing-plans`) from
