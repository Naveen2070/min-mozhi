### BUG-59 — a fused shift chain inside an `if`/`match` branch, un-hoisted as an outer growing shift's own LHS, sees the wrong ambient width

Minimized to nine lines. `mimz eval` says y=3072; real `iverilog`+`vvp` say
y=-1024 (15360 unsigned). Distinct from both prior members of this specific
family: BUG-52 was a width MISMATCH the classifier's wildcard hid; BUG-55 was
a signed `>>` escaping its branch. Here `infer_kind` (GATE) and
`verilog_self_determined_kind` (CLASSIFIER, BUG-52's own fix) **agree** — both
say the whole `if`-expression is `signed[11]` — so BUG-52's mismatch-gated
`hoist_if_needed` never fires. The VALUE still differs.

Root-caused by hand, step by step, cross-checking mimz-sim's kernel and real
Icarus at each step rather than trusting either:

1. The bare fused shift chain alone (`(a << b) >> c`) — kernel and Icarus
   agree: 384.
2. Wrapped in the `if`, no outer shift — still agree: 384.
3. The identical ternary TEXT assigned directly to a wider (14-bit) wire,
   no shift involved — Icarus alone gives 3968, not 384. This is the
   diagnosis: Verilog's ternary is context-PROPAGATING, and once it sits at
   wider context, its own inner `>>` (a bottom-up, truncating operator)
   recomputes at that width and keeps more bits.
4. The full repro (`if` as the outer `<<`'s own un-hoisted LHS) — kernel
   3072, Icarus -1024. `3968 << 3` wraps mod 2^14 to exactly -1024; mimz-sim's
   `eval_shift_chain` (BUG-34) resolves the branch bottom-up, in ISOLATION,
   with no ambient context at all, giving 384, then `384 << 3 = 3072`.
5. The same ternary manually hoisted into its own 11-bit wire FIRST, then
   `<< 3` on the wire — both sides agree at 3072. Confirms the fix shape.

**Cause**: `hoist_width_effect_operand` (`emit_verilog/expr.rs`) only checks
whether `child`'s own top-level kind is a width-effect binop or (when
`allow_shift`) a shift binop — neither pattern matches `IfExpr`/`Match`, so
one reaching this function as a `Shl`/`Shr`'s own un-hoisted LHS
(`allow_shift: false`) is never isolated, and Verilog's context-propagating
ternary rule reaches straight through it.

**Fix, in two passes — the first one broke goldens, caught before landing.**
First attempt added the check inside `hoist_width_effect_operand` itself,
gated on `!allow_shift`. Ran the full workspace suite before declaring done
(not just the one new test) and found 2 broken showcase goldens
(`vga_pattern`, `tamil-pure/vga_kuri`) — that function is ALSO called from
`if_expr_subst`/`match_subst`'s own branch rendering with `allow_shift: false`
for the ordinary, already-correct NESTED-ternary case (BUG-24's own
established behavior), a different meaning of the same flag at a different
call site the check couldn't tell apart from the real bug position.
Rescoped to `render_shift_ctx_operand` instead — the ONE call site
`!allow_shift` genuinely means "this is a `Shl`/`Shr`'s own LHS" (confirmed
by grepping every call site of `render_shift_ctx_operand`: only one passes a
non-`true` `allow_shift`, and it's exactly this position). Re-verified:
`self_determined_regression` + `showcase` 72/72 (goldens back to matching),
shift-family regression guards (`bug_24_regression_shift_in_if_branch_stays_
unhoisted` etc.) stay green, full workspace **1248/1248**, `fmt`/`clippy -D
warnings` clean.

New differential `bug_59_fused_shift_chain_inside_an_if_branch_as_the_lhs_of_
a_growing_shift_matches_icarus` watched fail at the exact filed values
(kernel 3072, Icarus 15360) before either fix attempt.

## Fuzz generator hardened against BUG-60's class (round-5 plan Task 4)

Value bias alone was NOT enough — verified before committing to it: with
BUG-60's fix disabled, both a 400-seed and a 5000-seed biased run stayed
clean. Root cause was a second, independent gap: `wrap_builtin`'s
`Nand`/`Nor`/`Xnor` candidate wraps whatever fragment it's handed as-is,
reaching BUG-60's shape (a reduction over an `extend`) only when two
separate random picks happened to chain — 0 of 10,000 generated programs
did, checked by grepping the temp `.mimz` corpus directly. Two fixes
together: `support::gen_vectors` reserves its first 3 of 8 vector slots per
port to all-ones/all-zeros/sign-boundary instead of pure scramble; `wrap_
builtin`'s reduction candidate forces an `extend` wrap when the fed
fragment is `atomic` (a bare port/literal), guaranteeing the shape whenever
a reduction is picked. With both: BUG-60 disabled → seed `12648489` fails
at N=400 in 8.26s (`nand(extend(p1[HI:0], 12))`, kernel 1 vs Icarus 0);
real fix restored → same run clean. Workspace 1256/1256, fmt/clippy clean.
`bugs.md` BUG-60 gets a "Fuzz-hardened" addendum; round-5 plan Task 4 marked
done. Not committed.
