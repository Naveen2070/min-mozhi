## GAP-11(b) closed — fuzz depth moved to CI, regression corpus added

Task 5a of `docs/plan/v0.2-correctness-remediation.local.md`. GAP-11 stays OPEN
on its (a) half (the vacuous width-conformance oracle, `assert_bits_fit_width`);
only (b) is done.

### What was wrong

`MIMZ_DIFF_FUZZ_N` and `MIMZ_DIFF_FUZZ_CLOCKED_N` defaulted to 20 and `ci.yml`
never raised them. Both of the last two silent miscompiles sat past that depth —
BUG-42 at i=245, BUG-44 at i=201 — so the fuzzers were running at a depth that
structurally could not find what they had already proven they could find.

### Three seed tiers

| where                              | seeds each | cost                |
| ---------------------------------- | ---------- | ------------------- |
| in-source `DEFAULT_FUZZ_N`         | 20         | 5.8 s (with corpus) |
| `ci.yml` → `check` (per-PR)        | 400        | 76.9 s, debug       |
| `ci.yml` → `fuzz-nightly` (weekly) | 5000       | release             |

`fuzz-nightly` previously ran libFuzzer targets only and had no `iverilog`; it
needed the install step and the ALSA headers before it could carry this.

### The correction worth recording

I first raised the **in-source** default to 400, on the plan's phrase "raise the
per-PR default to a few hundred". That is not what per-PR means. Every seed
shells out to `mimz compile` plus `iverilog` plus `vvp` — depth is paid in ~3
process spawns per seed per generator — so an in-source default charges CI's
depth to every unrelated local `cargo test`, taking a plain run from 5.8 s to
76.9 s. Depth is a discovery tool and belongs where a long run is free. The
constant is now documented as explicitly _not_ the depth that finds bugs.

### The corpus is the half that actually protects

`tests/fixtures/fuzz-seeds/comb.txt` and `clocked.txt` hold every seed that has
ever failed, one decimal per line, `#` comments, each annotated with its bug:

- comb: 12648432 (BUG-18), 12648435 (BUG-23), 12648451 (BUG-19), 12648521
  (BUG-34), 12648524 (BUG-19), 12648537 (BUG-24), 12648675 (BUG-42)
- clocked: 202427630 (BUG-23), 202427830 (BUG-44), 202428133 (BUG-21)

Replayed **before** the fresh seeds, at every depth including `N=0`. This is the
structural point, not a convenience: fresh seeds are `base + i`, so without a
corpus the depth number silently decides which historical bugs remain covered,
and lowering it drops them with no signal. Four of the ten are past the per-PR
depth and are reachable only from the corpus.

`corpus_seeds` asserts on an empty or all-commented file rather than returning
an empty vec — silent coverage loss is precisely the failure a corpus exists to
prevent, and it would otherwise pass green forever.

Implementation is one `fuzz_seeds(kind, env_var, base)` helper feeding both
`for` loops; no per-seed extraction was needed, so the diff stays small.

### Verified

Corpus-only (`N=0`) replays all 10 historical seeds green in 3.6 s. Default
depth: 4 tests, 5.8 s. 400 each: 76.9 s debug. Full workspace **1213 passed, 0
failed** — same count as the pre-change baseline. `fmt` and
`clippy --workspace --all-targets -- -D warnings` both exit 0.

### Local-run hazard found the hard way

`cargo test --workspace --all-targets` OOM-crashed a 16 GB Windows machine

## GAP-12 half-closed — `cur_decls` behind an `Rc`, 27x at 4,000 registers

Task 7. The `Rc` half is done; the multi-size `mimz-bench` half is not.

### The change

`Emitter::cur_decls` went from `HashMap<String, Kind>` to
`Rc<HashMap<String, Kind>>`. The 22 snapshot sites in `expr.rs` became
`Rc::clone(&self.cur_decls)` — kept explicit rather than left as `.clone()`,
which would still have compiled and still been O(1) but reads as a deep copy,
which is the exact misreading that let 22 of them accumulate. Three constructor
sites and the single writer (`Rc::new(self.build_decls(&flat))`) followed.
`&decls` deref-coerces to `&HashMap`, so no consumer signature changed.

The `Rc` is for a borrow reason, not a sharing one: every hoist site needs
`&self.cur_decls` live across a `&mut self` call, which the borrow checker
forbids. Semantics are identical — the map is replaced wholesale per module and
never mutated in place, so a snapshot could not observe a later write under
either type. Every golden is byte-identical; 1213 passed.

### Measured

Built the release binary twice on this machine, from the stashed and unstashed
tree, best of 3 per point:

| regs  | before | after  | speedup |
| ----- | ------ | ------ | ------- |
| 500   | 0.14 s | 0.04 s | 3.5x    |
| 1,000 | 0.37 s | 0.07 s | 5.3x    |
| 2,000 | 1.46 s | 0.13 s | 11x     |
| 4,000 | 7.59 s | 0.28 s | 27x     |

Per-doubling cost **2.71 / 3.90 / 5.20 → 1.63 / 1.85 / 2.09**: superlinear —
worse than quadratic and degrading — to linear. Speedup growing with size is the
signature of removing a per-node O(declarations) copy, which is the confirmation
that the diagnosis was right and not a coincidence of constants.

### GAP-12's own workload does not reproduce GAP-12

Worth recording because it nearly produced a wrong conclusion. The entry
describes "one module of N 8-bit registers". Built exactly that — `r_i <-
r_{i-1}` — and before/after were identical: 0.36 s vs 0.33 s at N=8,000, no
effect whatsoever. Nothing about the fix was wrong; the benchmark never reached
the code. A bare `Ident` right-hand side never enters a hoist path, so it never
takes a `cur_decls` snapshot.

The curve only appears once the drives carry hoisting expressions
(`trunc(extend(r_i, 16) * extend(3, 16), 8)`), so that both declaration count
and hoist-site count scale with N. Note also that the entry's original absolute
figures (0.43 → 10.57 s) did not reproduce here at any shape — the plain
reg-chain runs 29x faster than its 8,000-reg row claims. Treat that table as
unverified.

The general lesson: a perf fix verified against a workload that does not execute
the changed code reads exactly like a perf fix that does not work.

### Task 7 second half — the size axis (same day)

`mimz-bench` sampled one module size, so no trend it recorded could separate a
complexity regression from a slower runner. That is what let GAP-12 ship.

`metrics/scaling.rs` emits one synthetic module at 250 / 500 / 1,000 registers
and records the **cost ratio per doubling**. The ratio is the metric that
trends — ~2.0 means linear on any hardware, where an absolute millisecond
figure means nothing without knowing the machine. It appears in
`bench-history.jsonl` as `worst_doubling_ratio` (with `scaling_ms` for the raw
points, so a regression can be read as "which size did it start at"), as one
console line, and as its own trend chart in the HTML report.

Times check+emit only; lex and parse happen once per size outside the timer,
since the cost this exists to catch lives in the emitter. Iterations are capped
at 5 regardless of `--iterations` — the perf batch passes 500, which here would
cost minutes for no extra signal.

**Validated against the pre-`Rc` emitter**, because shipping a detector without
firing it once is the same mistake one level up:

| emitter         | 250     | 500     | 1,000    | worst ratio |
| --------------- | ------- | ------- | -------- | ----------- |
| before (GAP-12) | 22.8 ms | 82.3 ms | 372.2 ms | **x4.52**   |
| after (`Rc`)    | 3.6 ms  | 7.7 ms  | 18.0 ms  | **x2.33**   |

Three runs of the same binary gave 2.36 / 2.35 / 2.66, so run-to-run spread is
~±0.3 against a 2.2 separation. Reported, never gated — `MIMZ_PERF_GATE`
reasoning (BUG-33): a hard threshold on a shared CI runner would flap.

The workload is the same hoist-heavy shape, for the same reason as before: the
plain reg chain does not execute the code being measured. That constraint is now
written into `scaling.rs`'s own module docs so the next person to touch it does
not "simplify" the generator back into measuring nothing.

**GAP-12 → CLOSED.** Cost removed, and the instrument that would have caught it
now exists.

## GAP-11(a) closed — the width oracle now walks sub-expressions

Task 5b, the last of the plan's correctness work.

### Why the plan's literal instruction was not followable

It said to compare against the checker's `Ty` via `checker::infer_ty`. Neither
that nor the emitter's equivalent is reachable from `tests/`: `Ty` and
`infer_ty` are private to the width pass, whose own doc says _"Lives only inside
this pass — the AST stays untyped"_, and `infer_kind` is `pub(crate)`. Getting
either would mean a new public compiler API built solely for a test, and built
with nothing to validate its answers against.

### What was done instead

The generator already knows every fragment's width and kind by construction
(`Frag { text, width, signed, atomic }`) and throws that away for all but the
root. Now each internal node is **materialized** as its own `out` port, declared
at the generator's width, capped at `MAX_SUB_OUTPUTS = 8` per module, in both
the combinational and clocked generators. Two independent authorities fall out:

- the **checker** endorses every declared width by accepting the program — the
  generator is checker-clean by construction, so a bad width fails the
  1,000-seed validity test on the spot;
- **simulator** and **Icarus** each produce a value per intermediate, compared
  against each other and against the declaration.

Strictly additive. `y` and every `<-` still render the whole expression inline,
because BUG-30 was "naming an intermediate changes the result" — rewriting the
root to read these ports would quietly test a different program.

### The A/B that justifies it

With BUG-44's fix reverted, 400 combinational seeds:

| configuration                  | result                                 |
| ------------------------------ | -------------------------------------- |
| sub-expression outputs **on**  | **FAILS** — seed 12648671, output `y3` |
| sub-expression outputs **off** | passes in 92 s — blind                 |

The old oracle cannot see a real shipped miscompile the new one catches, and it
catches it in the **combinational** generator, which had never found BUG-44 —
that took the clocked generator at i=201. Seed 12648671 (a fresh seed, not in
the corpus at the time, so the result is not corpus-driven) is now pinned.

The clocked half was A/B'd too, corpus bypassed: fresh seeds 0..149 pass with
subs on, so it does not catch BUG-44 _earlier_ than its own i=201. Recorded as
measured rather than claimed — the combinational A/B is what carries the
strength argument.

### Notes

`assert_bits_fit_width` stays, now paired with an explicit "generator declared W,
simulator resolved W'" assertion. On its own it is still tautological (the kernel
masks to its own resolved width by construction) — that was the original finding
and it has not changed; what changed is that it is no longer the only check.

A `MIMZ_FUZZ_SKIP_CORPUS` escape hatch was added to run the clocked A/B and then
**removed**: an env var that silently disables regression coverage is precisely
the failure GAP-11(b) exists to prevent.

`gen_expr` collapsed into `gen_expr_collecting` (every caller collects now), and
`Subs`' `enabled` flag went with it.

**GAP-11 → CLOSED.** Full workspace green; both fuzzers green at the CI depth of
400 each, now in 65 s versus 77 s before — the generated programs are larger, but
`mimz compile` dominates per-seed cost and the `Rc` fix made it 27x faster.

## Task 4(b) — built it, measured it, did not ship it

The last open item. Written as specified it is a **no-op**, and I only know that
because I built it and tried to make it fail.

### The property cannot fail

The plan asked for, at every rendered self-determined sub-expression:

```rust
// verilog_self_determined_kind(e) == infer_kind(e)   OR   it was hoisted
debug_assert!(…);
```

All **seven** `hoist_if_needed` call sites pass `k = infer_kind(expr, &decls)`
as `mimz_kind`, so `mimz_kind == infer_kind(e)` compares a value against the
expression that produced it. The other half is already the literal `if` inside
`hoist_if_needed` — enforced by construction, not by assertion. Task 6 moved
kind derivation to the caller deliberately, so re-deriving it inside purely to
have something to compare against would undo that on purpose.

### Measured rather than argued

Added the assert, reintroduced BUG-42 (`Builtin::Min | Builtin::Max => None`),
ran the suite:

| detector                  | with BUG-42 reintroduced  |
| ------------------------- | ------------------------- |
| Task 4(b) `debug_assert!` | **silent**                |
| GAP-11(a) differential    | **fails** — seed 12648675 |

Both edits reverted; nothing from the experiment is in the tree.

### Why no assert can cover this

BUG-42 and BUG-44 were both a classifier arm returning `None` — a claim that no
Verilog-specific rule differs at this node. Nothing inside the emitter can
falsify that claim, because falsifying it means rendering the text and executing
it. Only an external oracle can, and GAP-11(a) now does exactly that at every
intermediate rather than only at the root.

Task 4's stated intent — _"every existing test becomes a position-matrix test
for free"_ — is met, by that route instead of this one. What carries it:
Task 2's wildcard-free match (a new `Builtin` must be classified consciously),
Task 3's corrected question in `self_determined.rs`'s module docs, and the
per-intermediate differential.

Shipping the assert anyway would have added a detector that can never fire —
the third instance of that exact failure diagnosed today, after GAP-12's own
benchmark and the vacuous width oracle. Recording the negative result is the
deliverable.

### Plan bookkeeping fixed

Tasks 5 and 7 had `Outcome ✅ DONE` blocks in their bodies but their headings
and the execution-order table still read as open. Both corrected, along with
Task 4's marker.

**All seven tasks of the v0.2 correctness remediation are now closed.**

## BUG-47 fixed — release gate now 5 of 5

### Diagnosis before code

A 21-case matrix over operator x signedness x context width, each run through
both `mimz eval` and Icarus, before touching anything. Result: **only `Shr` with
a signed left operand diverges.** `+%`, `-%`, `*%`, `^`, `&`, `+`, `*`, unsigned
`>>` and `<<` all match. That killed my worry that this was a general "any
narrow operand under a wider context" refactor needing the GAP-1 IR.

One matrix cell lied. `(p1 ^ p2) >> 2` first read as passing — because for the
inputs I picked `p1 ^ p2` was **positive**, so sign extension added zeros and
both sides agreed. It diverges once the operand is negative. Pinned as its own
regression test. A differential that passes on one input vector proves nothing.

### The cause is a guard that outlived its reason

`Builtin::Extend` passed `allow_shift: false` to `hoist_width_effect_operand`,
suppressing the hoist for a shift argument, justified by the simulator threading
extend's target width into that argument via `eval_ctx(r, &args[0], Some(n))`.

**`eval_ctx` does not exist.** BUG-34's fused-shift rework deleted it — shifts
now go through `binary::eval_shift_chain`, which uses the chain's own bottom-up
width and never consults an ambient width. The justification was removed and the
guard was left behind, at which point it stopped protecting anything and started
hiding a divergence.

Fix: one boolean, `false` -> `true`.

### The false start is the more useful half

My first fix hoisted any signed `>>` from inside the `Binary` arm,
unconditionally. **All 43 regression tests passed** — including every BUG-24 and
BUG-34 shift test — and it was still wrong. The fuzzer caught it at comb seed
12648749: `(p0 >> 10) << 1`, a shift as the direct left operand of another
shift, which fused-chain semantics require stay un-hoisted. Confirmed by
reverting only that change and re-running comb clean at `N=1000`.

A fix rendered from inside a node cannot see the position the node occupies.
Position is the parent's knowledge — which is precisely why `allow_shift` is a
parameter rather than a property of the shift. I had read that in the comments
and implemented against it anyway.

Also worth noting: the regression suite could not catch this, but the fuzzer
could. Two hours after GAP-11(a) landed, it had caught both the bug and my bad
fix for it.

### Verification

Two goldens changed — `shift.v` and `tamil_pure_nakartthi.v`, the only shipped
examples with a shift under `extend()`. BUG-6's own guard holds through the new
hoist: `extend(1 << 3, 8)` emits `wire [3:0] __mimz_sub_1; assign __mimz_sub_1 =
(1 << 3);` = 8 in 4 bits, not the 0 that bug was about, and its self-checking
test still passes.

Full workspace exit 0, `fmt`/`clippy -D warnings` clean, both fuzzers green at
`N=1000` each plus corpus (155 s). Seed 202428271 now in the corpus.
