# 2026-09-27

## Added: `ir::opt::eliminate_dead_cells` — second pass of the IR optimizer track

- New `crates/mimz-core/src/ir/opt/dead_cell_elim.rs`:
  `eliminate_dead_cells` removes every combinational cell whose output
  reaches no output port and no `Dff`/`Mem`/`BlackBox` input, directly or
  through other cells. One backward mark-and-sweep from those roots, not a
  fixpoint loop. `Dff`/`Mem`/`BlackBox` cells are never removed.
- New shared helper `driving_cell` in `ir/opt/mod.rs`: every net some cell's
  `out` pin drives, mapped to that cell's index. Meant to be reused by
  mux-tree simplification the same way `const_fold.rs` uses `net_consts`.
- After a removal the pass compacts `Module::nets` (see the Decision below).
- Optimizer item 2 of 3 checked off in `docs/plan/phase-2-ir-synthesis.md`.
- Three decisions the spec did not make:

### Decision: compact `Module::nets` after a removal

- **Context:** the spec said to leave `nets` untouched, and also required
  `validate` to stay clean after the pass. `validate`'s Check 1 flags every
  allocated net without a driver, whether anything reads it or not, so a
  removed cell's `out` nets become `UndrivenNet` errors.
- **Decision:** drop every net no surviving port or cell mentions, renumber
  the rest in order, and drop `signals` entries that pointed at dropped nets
  (option A, user-approved). When nothing is removed, nothing is touched.
- **Why:** the rejected alternatives were relaxing `validate` (it weakens a
  check that catches orphaned-net lowering bugs) and giving up
  `validate`-clean output. Cost: `NetId`s are not stable across a removal.
  No caller holds them across the call today.
- **Impact:** `dead_cell_elim.rs` (`compact_nets`), and the tests
  `a_removal_leaves_no_undriven_net`,
  `drops_the_signals_entry_of_an_unread_named_wire` and
  `keeps_every_out_net_of_a_partly_read_cell`.

### Decision: treat `Dff` clock and `Mem` read addresses as liveness roots

- **Context:** both are stateful-cell inputs stored in `CellKind`, not in
  `Cell::pins`, so a pins-only root set sweeps their drivers. Without it,
  `o = m[i +% 1]` loses its `AddWrap` and reads the wrong word.
- **Decision:** `roots` also reads `Dff::clock` and every `Mem::read_ports`
  address.
- **Why:** the spec's root rule is "every input of a `Dff`/`Mem`/`BlackBox`".
  This is that rule applied to inputs stored outside `pins`.
- **Impact:** the tests `keeps_a_cell_that_only_feeds_a_mem_read_address`
  and `keeps_the_driver_of_a_register_clock`.

### Decision: every `BlackBox` pin is a root

- **Context:** `BlackBox` pins mix inputs and outputs under extern port
  names.
- **Decision:** root all of them. An output-pin root just ends the walk,
  since no cell's `out` drives it.
- **Why:** separating them needs `extern_decls`, which a hand-parsed module
  lacks.
- **Impact:** the test `keeps_the_driver_of_a_blackbox_pin`.

- Observation: `lower` itself leaves unread `Const` cells in the `Mem`
  write-port path (three in the
  `keeps_a_cell_that_only_feeds_a_mem_read_address` source), so this pass
  already shrinks unoptimized lowered modules, not only `fold_constants`
  output.
- 13 new tests (`ir/tests/opt_dead_cell_elim.rs`), every positive case

## Final review: `ir::opt::eliminate_dead_cells` (commit `05a0b99`)

- Fresh opus reviewer over `1324ca5..05a0b99`: ready to merge, 0 Critical,
  0 Important, 3 Minor. No fix pass needed.
- Reviewer's throwaway corpus probe (deleted afterwards): all 192 examples
  that lower `validate`-clean were run through `fold_constants` then
  `eliminate_dead_cells`. All stayed `validate`-clean, outputs were
  identical over 4 ticks, and a second call changed nothing. 19 modules
  shrank. Suggested follow-up: keep this as a permanent corpus test.
- Deferred minors (not fixed; tracked in `docs/audit/gaps.md`, GAP-1 sub-gap
  "known limits of `ir::opt::eliminate_dead_cells`"):
  - `driving_cell` treats a black-box pin named `out` as a driver.
    Unreachable from `validate`-clean modules and `out` is reserved, but
    skip `BlackBox` there before mux-tree simplification reuses it.
  - Stray unreferenced nets are dropped only when a cell was removed. Only
    `validate`-dirty modules have them.
  - No test pins that a partly-dead named wire loses its `signals` entry
    whole. The behavior is correct.
- Rulings on points the reviewer declined to judge:
  - Dead registers, memories and black boxes are kept. Spec non-goal. Cost:
    larger netlists until a full-liveness pass.
  - Unread named wires lose their `signals` entry, so
    `Executor::get_output` on them panics after the pass. No current caller
    asks. Cost: a future debug or trace tool must read them before the pass.
  - Every module with an extern instance fails `validate` (extern output
    pins are never counted as driven, `validate.rs` Check 1). Predates this
    branch, but it blocks the optimizer on extern designs. Filed as a new
    OPEN GAP-1 sub-gap in `docs/audit/gaps.md`.
  - An out-of-range `NetId` panics in `compact_nets` instead of erroring.
    Only hand-built modules can have one.
  - Not wired into the build or CLI. Spec non-goal.
