# 2026-09-02

## Phase 2 IR — Task 10: lower `mem` to `Mem` cells

- **Context:** `ir::lower` covered comb (Tasks 5-7), registers (Task 8) and
  `fn` inlining (Task 9), but memories were still unlowered. `elaborate::Mem`
  reads/writes reuse the SAME AST nodes as bit-selects (`ExprKind::Index` for
  `m[addr]`, `LValue { index: Some(..) }` for `m[addr] <- v`) — the parser
  can't distinguish them, and neither could `lower`.
- **Decision:** Disambiguate by name at lowering time (does `base` name a
  `design.mems` entry?), exactly as `checker/widths/expr` already does when it
  branches on `Ty::Memory` vs. a plain bit-vector. Memory forms lower; genuine
  bit-selects keep their loud `unimplemented!`.
- **Schema:** `CellKind::Mem` gained `init: ConstVal`, completing the pin/
  metadata shape `docs/plan/phase-2-ir-design.local.md` (line 155) always
  specified ("seeded init value carried as cell metadata"). Same class of
  correction as `CellKind::Const { value }` in an earlier task.
- **Pin set:** `raddr` / `rdata` / `waddr` / `wdata` / `wen`, plus `clock`
  only when the memory actually has a writing `on` block. A ROM has no clock
  signal, and `Mem` (unlike `Dff`) keeps its clock in `pins` rather than as a
  struct field, so absence is expressible — no fake `NetId` is invented.
- **Independent read and write addresses.** The read address and the write
  address are separate pins, never reconciled against each other. This
  matches the simulator kernel, which reads combinationally from the
  **pre-tick** `self.mems` while a write lands in `next_mems` — "a same-cycle
  read of the cell still sees the old value". Sharing one address bus
  (muxing on `wen`) would make the read follow the write address whenever
  `wen` is high, diverging from the kernel on the canonical register-file
  shape `rd = ram[ra]` + `on rise(clk) { if we { ram[wa] <- din } }` — exactly
  what Phase 2's differential testing exists to catch.
- **Two-pass emission.** Every memory's writing process is walked first, and
  only then are the cells emitted. A write process's own body can itself
  contain reads (`ram[wa] <- ram[ra]`, or a read of another memory), and the
  register pass never reaches them — its `env.contains_key` guard skips every
  `MemWrite` statement — so the writer walk is the first and only place such
  a read is lowered. Emitting cells in the same pass would leave that read's
  address on the floor.
- **Single read port (acknowledged ceiling):** `LowerCtx::mem_read` holds one
  `(raddr, rdata)` pair per memory. A read at a **different** address panics,
  the way every other out-of-scope form in `lower.rs` does, rather than
  silently reading the wrong word. Multiple read ports need a
  `raddr0`/`rdata0`/... pin set the design doc does not have yet.
- **Top-level expressions are memoized by AST node address**
  (`LowerCtx::expr_memo`, checked and populated at the very top of
  `lower_expr`). The read-address check above compares lowered nets, so
  without memoization a read whose index isn't a bare signal (`m[0]`)
  allocates fresh nets on every lowering. Since `lower_seq_stmts` walks one
  shared process body once per target, and `SeqStmt::If` lowers its condition
  on every one of those walks, one source-level read would otherwise be
  mistaken for two rival ones. `design` is borrowed immutably for the whole
  pass, so an AST node's address is a stable identity for "this exact
  expression site"; re-encountering one returns its `Bits` with no
  re-lowering, so nothing inside it — an inlined `fn` body included — gets a
  second chance to allocate. Only applied at top level (`locals.is_none()`):
  inside an inlined `fn` body the same node genuinely can mean different
  values on different calls, so that path still reaches the strict check. Two
  **distinct** read sites whose indices are textually identical still trip
  the panic; a loud false positive is the safe direction, and real structural
  dedup is CSE/optimizer territory. Anything added later that re-walks a body
  at `locals: None` with per-iteration semantics — `on`-block
  `Loop`/`ForEach` unrolling, still `unimplemented!` — must bypass or scope
  this memo per iteration.

## Fix: `lower_seq_stmts` only tracks pre-seeded targets

- **Context:** the `Default` and `Assign` arms inserted into `env`
  unconditionally. `lower_seq_stmts` walks the WHOLE process body once per
  target, so a target the caller did not pre-seed could appear in `then_env`
  but not in the pre-`if` `env` — and the branch merge's `env[&name]`
  (a panicking index) would panic.
- **Why it never bit before:** Task 8 only ever ran one walk per register,
  and no test had a process assigning a second target asymmetrically across
  an `if`. Task 10 makes the pattern ordinary (one process drives both a
  register and a memory's write port).
- **Fix:** both arms now guard on `env.contains_key(..)`, so a walk leaves
  `env`'s key set untouched and `changed` is always a subset of it.
- **Regression test:** in `ir::tests::lower_regs` —
  `a_second_register_assigned_only_inside_an_if_does_not_disturb_the_first`.
  Two registers on one clock in one process, the second assigned only inside
  an `if`. It panicked at `lower.rs:487` before the fix.
