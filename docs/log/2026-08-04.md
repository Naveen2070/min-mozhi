# 2026-08-04

## BUG-35/BUG-36 fixed - incomplete `Builtin` case tables in the emitter's kind-inference/hoist machinery

Branch `bug-34-35-36-self-determined-shift-hoist`, continuing the same day's
BUG-34 work. Both were filed OPEN by the 2026-08-03 GAP-5 direction-2 fuzzer
run (`tests/differential_fuzz.rs`'s new `wrap_builtin`) and left for a later
pickup - this is that pickup.

**BUG-35** (a shift whose left operand is a builtin call isn't hoisted in a
self-determined/concat position): root cause traced to `kind_is_inferrable`
(`crates/mimz-core/src/emit_verilog/expr.rs`) and `infer_call`
(`crates/mimz-core/src/emit_verilog/kinds.rs`) - both had no arms for
`Nand`/`Nor`/`Xnor`/`Min`/`Max`, falling to `_ => false` / `panic!`
respectively. Any expression containing one of these five as a sub-part
(e.g. `nand(p1) << extend(5, 3)`) was therefore treated as "can't analyze,"
so the whole containing expression skipped the hoist machinery entirely -
not because the hoist itself was wrong, but because it never ran.
`self_determined.rs`'s exhaustive `Builtin` match already classified all
five correctly (`None` - no Verilog-specific mismatch risk from the
builtins themselves); only the mimz-side inference was missing. Added real
arms to both functions (reductions → `Kind{width:1,signed:false}`;
`min`/`max` → the checker's own `matched_ty` literal-adapts rule). This
alone unblocked the pre-existing, already-correct
`hoist_width_effect_operand`/`hoist_if_needed` mechanism for the shift.

Fixing `min`/`max`'s literal-adapts check surfaced a second, real bug along
the way: reusing `infer_binary`'s existing `is_bare_int` helper (which
deliberately does not recognize a negated literal - see its own doc
comment) broke `showcase/pid_controller.mimz`'s real
`max(-128, min(total, 127))`, panicking on a `Kind` mismatch the checker
never considered one. Added `is_ct_int_like` (recognizes `-N` too) and
scoped it to the `Min`/`Max` arm only, leaving `AddWrap`/`BitAnd`'s narrower
helper untouched.

**BUG-36** (`trunc()` of a non-identifier expression emits an invalid
Verilog part-select): `Builtin::Trunc`'s codegen only called
`hoist_width_effect_operand`, which hoists a width-effect-binop/shift base
(BUG-23/24's value-correctness concern) - it never hoisted a base of any
OTHER non-identifier shape (a concat, in the filed repro). This is BUG-20's
own grammar constraint (a Verilog part-select only accepts a plain
identifier) reached through a different call site: `ExprKind::Slice` got
BUG-20's fix, `Builtin::Trunc`'s own separate part-select render never did.
Added the same unconditional-on-shape `hoist_slice_base_if_needed` call
`ExprKind::Slice` already uses.

Both fixes verified against real `iverilog`/`vvp`: watched the two new
regression tests (`tests/self_determined_regression.rs`,
`bug_35_shift_with_a_builtin_call_left_operand_in_a_concat_matches_icarus`,
`bug_36_trunc_of_a_concat_hoists_the_base_first`) fail first - BUG-35's
matching the filed kernel-vs-Icarus divergence (1 vs 0), BUG-36's matching
the filed `iverilog` syntax error - then pass after the fix, via a
temporary `git stash` of just the fix commits.

**Side effect, not a regression.** The BUG-36 fix also corrected a
previously-undetected instance of the SAME invalid-Verilog class in two
shipped showcase examples: `pid_controller.mimz`/`pid_kattu.mimz`'s
`trunc(max(-128, min(total, 127)), 8)` was already emitting a bare ternary
directly under a part-select (`(cond ? a : b)[7:0]`) - confirmed with a
standalone repro that real `iverilog` already rejected this shape before
today's fix too; it had simply never been caught, since neither example is
in the Icarus-differential-tested list, only the checker-clean/compiles-ok
one. `tests/golden/showcase_pid_controller.v` and
`tests/golden/showcase_tamil_pure_pid_kattu.v` regenerated
(`MIMZ_UPDATE_GOLDENS=1`); diff is exactly the expected extra hoist wire,
verified to elaborate clean under `iverilog -t null`.

Full workspace green (`cargo test --workspace --all-targets --no-fail-fast`,
`REQUIRE_IVERILOG=1`) except the pre-existing `wasm_parity` failure
(`all_showcase_work_in_wasm`, `all_examples_work_in_wasm`) - confirmed via
`git stash` to already fail identically at the branch's pre-fix baseline
(`e963b84`), on unrelated examples (`uart_echo.mimz`, `shift_register.mimz`)
showing the same "wasm build lacks a hoist the native build has" pattern -
a stale WASM build artifact, out of scope for this branch. `fmt`/`clippy -D
warnings` clean.

With this, GAP-5 (`docs/audit/gaps.md`) is fully closed - both directions'
infrastructure landed 2026-08-03, and everything that infrastructure found
(BUG-34, BUG-35, BUG-36) is now fixed.

## GAP-3/BUG-31 fixed - parser mandatory-help contract, E0403's mis-targeted help

Branch `gap-3-bug-31-parser-help-contract`, v0.2 roadmap item 6 (top-10
priority #6, `docs/audit/review-2026-08-02.md`). Not committed yet - pending
user go-ahead.

**GAP-3** (parser violated its own mandatory-help contract: `self.error()`
took no `help`, so 46/60 sites shipped none - 77% of syntax errors, the
highest-traffic diagnostic surface). Test-first: added
`every_parse_error_carries_a_help_line`
(`crates/mimz-core/src/parser/tests/safety_and_precedence.rs`), a broken-source
sweep across all 16 `E11xx` codes (`docs/code/06-diagnostics.md`) mirroring the
existing `every_parse_error_carries_a_code` structural test - watched it fail
(`garbage here` / E1102 had no help), then fixed it structurally: changed
`Parser::error`'s signature to require `help: impl Into<String>` (mirrors
`Checker::err`'s established discipline exactly), which broke all 60 call
sites at compile time - filled every one with a real teaching help line (the
14 that had a separate opt-in `self.help(...)` call got it folded in; `help()`
itself deleted, no longer reachable). Spans `parser/mod.rs`, `parser/expr.rs`,
and all 8 `parser/items/*.rs` files. Full workspace green (1136/1136 incl. the
new test), `fmt`/`clippy -D warnings` clean.

**BUG-31** (`E0403`'s inline help hardcoded "clocks and resets only appear
in..." even when the offending value was an enum, memory, array, or bundle -
actively misdirecting a learner). Test-first: added
`enum_in_concat_is_e0403_with_enum_specific_help`
(`crates/mimz-core/src/checker/tests/widths.rs`) plus a help-content assertion
on the existing `clock_in_a_data_expression_is_e0403` (locking the clock/reset
case doesn't regress) - watched the new test fail on the wrong help text, then
branched `Checker::not_data`'s help by `Ty` variant (`checker/widths/mod.rs`):
enum → "symbolic state, not a number"; memory/array → "index it to get one
element"; bundle → "access one field to get data"; clock/reset → the original
text, now scoped to its actual case. 1137/1137, `fmt`/`clippy -D warnings`
clean.

Both together close v0.2 priority #6. Remaining before v0.2: priority #7
(`assert`/`assume`/`cover`, GAP-6) and the enum↔bits cast (GAP-7).
