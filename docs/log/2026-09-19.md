# 2026-09-19

## Fixed: GAP-1 closure Task 6 review round — `Bits::signed` on DERIVED values

- Root cause of all four blocking review findings: `Bits::signed` was
  stamped only at allocation (input ports, reg Qs, extern-instance
  outputs) and flipped by `signed(x)`/`unsigned(x)`, but never COMPUTED
  for a derived value. Every `lower_binop` result came back
  `signed: false`, so all of Task 6's features silently reverted to their
  unsigned reading the moment an operand was an expression rather than a
  bare signed port.
- `lower_binop` now gives its result the signedness the checker's own
  rules give it: `a.signed || b.signed` for `+`/`-`/`*`, the `+%` family
  and bitwise (`width_rules::lossless_result`/`matched_result` both
  return the shared operand `Kind`, and the checker has already forced
  the two to agree — `||` not `&&` because a re-sized literal's
  `ConstVal` is always built unsigned); `a.signed` for `<<`/`>>`
  (`shift_result` keeps the left operand's kind); always unsigned for
  comparisons and `&&`/`||`.
- `min`/`max` now give a literal operand the same `lower_expr_sized`
  resize + sign-inheritance `ExprKind::Binary`'s comparison path already
  had — the checker routes both builtins through `matched_ty`, so a
  literal adapts to the sized side. Without it `min(x, 3)` fed a 2-bit
  `Const` to an 8-bit `Lt` pin (`WidthMismatch`) and the `max(x, 0)`
  clamp idiom could not lower at all. `cmp_signed` there is `||` for the
  same reason.
- `abs`'s result is now `signed` when its operand is, matching the
  checker's `Signed(n) -> Signed(n+1)`. The invariant is "`Bits::signed`
  equals the checker's own `Ty` signedness", not "this value could be
  negative" (it can't — `|x|`'s top bit is always 0 in n+1 bits, so a
  downstream sign-extend and zero-extend agree anyway).
- `~x` inherits its operand's flag — the checker's `UnOp::BitNot` arm
  returns the operand's `Ty` unchanged, so `extend(~a, 16)` over a
  `signed[8]` was the same class of silent zero-extension as finding 1,
  just not named in the review.
- Four new Executor-level regression tests in
  `crates/mimz-core/src/ir/tests/lower_builtins.rs`, all over COMPUTED
  operands (the gap every original Task 6 test missed — each used a bare
  signed port). All four confirmed RED against `2af7cc5` first:
  `extend_of_a_computed_signed_expression_sign_extends` (got `0x01FF`,
  wanted `0xFFFF`), `min_over_a_computed_signed_operand_compares_signed`
  (unsigned `Lt`, picked `3` over `-5`),
  `min_max_with_a_literal_operand_size_and_sign_the_literal_to_its_sibling`
  (two `WidthMismatch`es), and
  `abs_and_neg_over_a_computed_signed_operand_grow_by_one_bit` (two
  `PortWidthMismatch`es, 9 bits found where 10 declared).
- Moved `elaborate_src`/`lower_ok` out of `lower_binops.rs` into
  `ir/tests/mod.rs` so the new tests reuse them rather than re-declaring
  a third copy; added `lower_valid` (lower + assert `validate` clean)
  alongside, since finding 3 is a validation failure and findings 1/2/4
  are value failures.
- Docs: corrected `docs/audit/gaps.md`'s three stale claims (min/max/abs
  "refused loudly", "`ir::Bits` is UNCHANGED — it still carries no sign
  bit", arithmetic "remain unsigned in the IR"), marked the `UnOp::Neg`
  growth sub-gap RESOLVED, and added a dedicated "`ir::Bits` has no
  signed bit in v1" sub-gap recording what the flag is computed from and
  what stays out of scope (`Concat`/`Replicate` default unsigned,
  `lower_const` stays unsigned, `CellKind::Mul` still has no `signed`
  field). Corrected `tests/differential_fuzz.rs`'s generator comment,
  which still claimed `min`/`max`/`abs` hit `unimplemented!()`.
- `cargo test --workspace` 1446/1446, `cargo clippy --workspace
--all-targets -- -D warnings` clean, `cargo fmt --all --check` clean,
  `cargo test -p mimz --test differential_fuzz` 8/8 at defaults and at
  `MIMZ_DIFF_FUZZ_N=300`/`MIMZ_DIFF_FUZZ_CLOCKED_N=150`. Test-count docs
  and README badge updated 1442 -> 1446.

## Fixed: GAP-1 closure Task 6 review round 2 — slices, bit-selects and `if`/`match` results

Round 1 fixed `Bits::signed` for binop-derived values; the re-review found
the same disease at three more `Bits`-producing sites, each one guessing
instead of following the checker's rule for that expression kind. All three
fixed in `crates/mimz-core/src/ir/lower.rs`:

- **B1 (new regression from round 1).** A runtime-indexed bit-select
  (`a[i]`) lowers as `Shr` + take net 0, and round 1's new
  `Shl|Shr => a.signed` rule made that 1-bit result inherit the base's sign.
  The shift rule itself is right (`width_rules::shift_result` keeps the left
  operand's kind); the bit-select on top of it has to drop the flag. Now
  `Bits::unsigned(vec![shifted.nets[0]])`.
- **B2 (pre-existing).** `ExprKind::Slice` and the constant-index
  bit-select both inherited `base_bits.signed`. A slice or bit-select is
  UNCONDITIONALLY unsigned — `width_rules::slice_result` returns
  `signed: false` whatever the base was (the shared rule that makes BUG-21
  unreintroducible), and `checker/widths/expr/lvalue.rs` types a bit-select
  as `Ty::Bit`. Both now build `Bits::unsigned(...)`. The bit-select-WRITE
  sites are untouched: they carry the whole base value, not a read result.
- **B3 (pre-existing).** `ExprKind::IfExpr` and `lower_match`'s mux chain
  built their results straight from `Module::alloc_bits` (always unsigned).
  The checker unifies every branch/arm to one `Ty`, so there is exactly one
  flag to take; all three remaining inline `Mux` literals (if-expr, match
  fold, array runtime-index chain) now go through the existing
  `push_mux_cell`, whose `a.signed && b.signed` is that shared flag. Net
  deletion, not addition.
- **N-b.** `min`/`max` no longer lower a foldable operand twice (naturally,
  then re-sized), which used to orphan a natural-width `Const` cell in every
  `min(a, 3)`/`max(a, 0)`. The foldable side is lowered once, already at its
  sibling's width; two literals of differing natural width still widen the
  narrower one. Pinned by a Const-cell count assertion.
- Five new Executor-level regression tests in
  `crates/mimz-core/src/ir/tests/lower_builtins.rs`, all confirmed RED
  first: `a_runtime_bit_select_is_unsigned_even_over_a_signed_base` (got
  `0xFF`, wanted `0x01`),
  `a_slice_and_a_constant_bit_select_are_unsigned_even_over_a_signed_base`
  (got `0xFF`, wanted `0x0F`),
  `min_over_two_slices_of_signed_bases_compares_unsigned` (signed `Lt` over
  two slices), `an_if_expressions_result_inherits_its_branches_signedness`
  (two `PortWidthMismatch`es) and
  `a_match_expressions_result_inherits_its_arms_signedness` (got `0x00FF`,
  wanted `0xFFFF`).
- Docs: `docs/audit/gaps.md`'s `ir::Bits` sub-gap now states the invariant
  precisely ("a value's `Bits::signed` equals the signedness of the `Ty` the
  checker gives that same expression") and no longer claims slices,
  bit-selects or constant indexes inherit it; added a round-2 section for
  the three sites. Corrected the stale "`ir::Bits` itself still has no
  signed bit" comment on `CellKind`'s ordering comparisons.
- `cargo test --workspace` 1451/1451, `cargo clippy --workspace
--all-targets -- -D warnings` clean, `cargo fmt --all --check` clean,
  `cargo test -p mimz --test differential_fuzz` 8/8 at defaults and at
  `MIMZ_DIFF_FUZZ_N=300`/`MIMZ_DIFF_FUZZ_CLOCKED_N=150`. Test-count docs and
  README badge updated 1446 -> 1451.
- Not committed — controller batches commits.

## Fixed: GAP-1 closure Task 6 review round 3 — the constant-operand family

- Round 3's five findings were one disease in five places: a value whose
  checker `Ty` is signed lost the flag because one side/branch/operand was a
  compile-time constant. `Ty::CtInt` has no signedness of its own (it becomes
  its context's `Ty`), so `lower_const` builds every constant unsigned — and
  every merge that asked BOTH sides to be signed (`&&`) let that constant veto
  a genuinely signed sibling.
- **One rule, two forms**, instead of five independent patches. Context from a
  SIBLING: merge with `||`. Context from a DECLARED type: stamp it directly.
- `||` rather than `&&` for `cmp_signed` (F1) and `push_mux_cell` (F2). Safe
  because `width_rules::matched_result`/`lossless_result` force two real
  operands to the identical `Kind` (E0403) and the checker unifies every mux
  branch to one `Ty`, so `||` and `&&` agree everywhere except a constant
  operand — where `||` is exactly "the sibling's sign wins". It cannot invent
  a sign either: a positive literal that `fit`s in `signed[N]` always has
  natural width `< N`, so it takes the resize-and-stamp path instead.
- Declared-type stamps: a `fn` call's result is its declared return type (F3),
  a `fn` argument is its parameter's declared type (F8, found by probing), and
  a memory read is the memory's element type (F4, both `alloc_bits` sites).
- **F6** fixed too, because F3's own repro needs it: `lower_expr_sized`'s
  blanket `locals.is_none()` gate refused to const-fold any compound constant
  inside an inlined `fn` body, so `return -1` in a `-> signed[8]` fn lowered
  at its operand's 1-bit natural width and returned `1`. Replaced with
  `visible_consts(locals)`, which hides only the design-level constants a
  local name actually shadows — the real hazard the gate existed for.
- **F7** done: `lower_seq_stmts`'s branch merge, the fourth and last inline
  `Cell { kind: CellKind::Mux, .. }` literal, now calls `push_mux_cell`.
- Nine new Executor-level regression tests in
  `crates/mimz-core/src/ir/tests/lower_builtins.rs`. The five named repros
  were confirmed RED first: `a < -128` over `signed[8]` read `0 < 128` and
  answered `1`; `extend(if s { a } else { 0 }, 16)`, the `match` twin and the
  signed memory read all gave `0x00FF` instead of `0xFFFF`; the signed fn
  returning `-1` gave `1`. Four more probes covered shapes no review had
  named — the F8 fn-argument bug is one of them; a nested literal-branch mux,
  an array-element read of a signed-element array param and the
  `min`/`max` clamp idiom were checked and are correct. `{a, a}` over a
  `signed` operand needs no probe at all: the checker rejects it (E0403).
- `crates/mimz-core/src/ir/tests/lower_binops.rs`'s
  `a_signed_cast_over_an_identifier_makes_the_comparison_signed` had a second
  half asserting `signed(a +% b) < 200` stays UNSIGNED — a claim about the
  deleted `expr_is_definitely_signed` heuristic, over a hand-built `Design`
  the checker itself rejects (`fit` gives `200` an effective `signed` width of
  9, E0405 against a `signed[8]` sibling). Retargeted to the uncast shape,
  which pins the direction that still matters: `||` never invents a sign.
- Docs: `docs/audit/gaps.md`'s `ir::Bits` sub-gap gains a round-3 section, and
  its "deliberately out of scope" paragraph no longer claims a constant only
  reaches a signedness-sensitive position through `lower_expr_sized`'s resize
  — F1/F2/F3 each refuted that. The sub-gap stays RESOLVED.
- `cargo test --workspace` 1460/1460, `cargo clippy --workspace
--all-targets -- -D warnings` clean, `cargo fmt --all --check` clean,
  `cargo test -p mimz --test differential_fuzz` 8/8 at defaults and at
  `MIMZ_DIFF_FUZZ_N=300`/`MIMZ_DIFF_FUZZ_CLOCKED_N=150`. Test-count docs and
  README badge updated 1451 -> 1460.
