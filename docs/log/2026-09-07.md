**Task 6.** `ir::lower`'s single memory read port was the last open GAP-1
residual: a second read at a different address panicked. `CellKind::Mem`
now carries `read_ports: Vec<(Bits, Bits)>` — one `(raddr, rdata)` per
DISTINCT lowered read address — instead of the single pair the old
`raddr`/`rdata` pins held. A new read at an existing address reuses that
port; a genuinely different one grows a new entry.

Every consumer updated: `LowerCtx::mem_read` becomes
`HashMap<String, Vec<(Bits, Bits)>>`; `exec.rs`'s `Mem` arm loops all read
ports each settle pass; `validate.rs`'s driven-net check explicitly
registers each port's `rdata` (no longer visible via the generic pin scan);
`print_line`/`parse_line`/`print_sexpr` round-trip ports as numbered
`raddrN`/`rdataN` text entries (parsed generically then pulled back out of
`pins` into `read_ports`).

Resolved the plan's flagged open design question: is a memory's read side
combinational or sequential for cycle-detection purposes? `exec.rs`'s own
`Mem` arm reads `rdata` as a pure function of `raddr` and the pre-tick
array — genuinely combinational (unlike `Dff`'s `d`->`q`, broken by the
clock edge). So `find_combinational_cycle` now models each read port's
`raddr`->`rdata` edge for real; the write side stays excluded, same as
`Dff`.

`Module::signals`'s per-memory entry (keyed by name, no way to pick a
port) is only populated for a single-read-port memory — the only
unambiguous case, and the only one anything today needs.

New tests replace the old `#[should_panic]` one:
`a_second_read_at_a_different_address_grows_a_second_port` and
`a_second_read_at_the_same_address_reuses_the_port`
(`crates/mimz-core/src/ir/tests/lower_mem.rs`). `tests/golden/ir/regfile.ir`
regenerated for the new `raddrN`/`rdataN` syntax. Test count 1417 → 1418
(`docs/code/10-test-map.md`, README badge).
