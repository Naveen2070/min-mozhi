### F-1 re-reproduction (the gate the release was tied to)

Repros A, B and C, re-run verbatim on current HEAD:

```text
Repro A  y = { b, extend(a, 8) }
  emitted   wire [7:0] __mimz_sub_1;  assign __mimz_sub_1 = (a);
            assign y = {b, __mimz_sub_1};
  mimz test ok (1 passed)
  iverilog  y=101000001111  expected=101000001111   PASS

Repro B  y = {2{ extend(a, 4) }}
  emitted   wire [3:0] __mimz_sub_1;  assign y = {2{__mimz_sub_1}};
  mimz test ok (1 passed)
  iverilog  y=00110011      expected=00110011       PASS

Repro C  y = { b, unsigned(abs(a)) }
  emitted   wire signed [4:0] __mimz_sub_1;  wire [4:0] __mimz_sub_2;
  mimz test ok (1 passed)
  iverilog  y=101001000     expected=101001000      PASS
```

**Is the fix exhaustive?** In `self_determined.rs`, yes - the `Builtin` match has
no wildcard, all 14 variants are classified, and the doc comment states the
intent. In `tests/self_determined_regression.rs`, `matrix_shape` is likewise
wildcard-free and `ALL_BUILTINS.len() == 14` is asserted. A 15th builtin fails
the build in both places.

**Do the regression tests actually fail on the old code?** Yes - verified, not
assumed. Reverting `self_determined.rs`'s `Call` arm to `_ => None` and re-running:

```text
test result: FAILED. 25 passed; 3 failed
  bug_28_extend_in_concat_matches_icarus       kernel 2575 vs Icarus 175
  bug_28_extend_in_replication_matches_icarus  kernel   51 vs Icarus  15
  bug_29_abs_in_concat_matches_icarus          kernel  328 vs Icarus 168
```

These are real Icarus differentials, not shape assertions. Good tests.

**Where the fix was scoped narrower than recommended.** The prior review asked
for every `Builtin` × each of the five self-determined positions. What landed is
one differential test per testable builtin at the **concat** position only, with
an explicit written argument that the three functions involved
(`verilog_self_determined_kind`, `kind_is_inferrable`, `hoist_if_needed`) are
shared across all five positions, so position coverage is redundant. The
argument is correct as far as it goes - but it is precisely the assumption that
lets [BUG-41](bugs.md) hide, because the shared **gate**
(`kind_is_inferrable`) was never made exhaustive alongside the shared
**classifier**.

### F-2 re-reproduction

The original repro no longer type-checks, which is the correct outcome for the
chosen fix (option (b), growing shifts): `din << 2` is now `bits[6]`, and the
checker says so with a teaching diagnostic. Re-written to the new type:

```text
wire w: bits[6] = din << 2
direct = extend(din << 2, 8)
named  = extend(w, 8)

mimz test  → ok (2 checks): direct == named, direct == 60
iverilog   → direct=60 named=60   MATCH
```

Referential transparency restored, and the declared width now bounds the value.
This one is properly done.

**Cost, worth recording.** Dynamic shifts grow by their operand's worst case, so
`bits[4] << bits[8]` is `bits[259]`, and `bits[4] << bits[32]` is a hard error:

```text
error[E0405]: shifting bits[4] wider by 4294967295 bits exceeds the 1000000-bit width limit
   = help: narrow the operand, or shift by a smaller amount
```

That is a clean, non-crashing diagnostic (checked at `bits[32]` and `bits[64]` -
no overflow panic). But a barrel shifter with a runtime amount now needs an
explicit `trunc` at every use, and ten shipped examples/showcases had to be
edited. This is the predicted cost of option (b); it is acceptable, but it
should be called out in the release notes and the guide, and it is not currently
in either.

## Part 3 - New defects

### 🔴 BUG-41 (CRITICAL) - The self-determined hoist gate is not exhaustive: F-1 reopens through `fn` calls, instance ports, `if`, `match`, and `mem` reads

**Filed as [BUG-41](bugs.md).**

`emit_verilog/expr.rs:59` `kind_is_inferrable` is the gate that decides whether
`hoist_if_needed` - and therefore the whole exhaustive `self_determined.rs`
classifier - runs at all. It ends in two wildcards:

```rust
        ExprKind::Call { func, args } => match func {
            …
            _ => false,          // expr.rs:103
        },
        _ => false,              // expr.rs:105
    }
```

The second wildcard swallows `FnCall`, `Field` (instance port / bundle field),
`IfExpr`, `Match`, `Index` (`mem` read), `BundleLit`, `ArrayLit`, and
`EnumConstruct`. Any expression **containing** one of those is declared
non-inferrable, the hoist never fires, and the emitter falls back to exactly the
pre-BUG-28 output.

Five reproductions, all `mimz test` green and all wrong under Icarus:

```text
① fn call as an operand
   y = { b, ident4(a) + a }                     a=1111 b=1010
   emitted   assign y = {b, (ident4(a) + a)};
   mimz test ok        iverilog 010101110   sim 101011110   ✗

② instance port as an operand
   y = { b, s.q + a }
   emitted   assign y = {b, (s_q + a)};
   mimz test ok        iverilog 010101110   sim 101011110   ✗

③ if-expression as an operand
   y = { b, (if s { a } else { b }) + a }
   emitted   assign y = {b, (((s) ? (a) : (b)) + a)};
   mimz test ok        iverilog 010101110   sim 101011110   ✗

④ mem read as an operand
   y = { b, m[raddr] + m[raddr] }
   emitted   assign y = {b, (m[raddr] + m[raddr])};
   mimz test ok        iverilog 010101110   sim 101011110   ✗

⑤ BUG-28 itself, verbatim, through a fn call
   y = { b, extend(ident4(a), 8) }
   emitted   assign y = {b, (ident4(a))};          ← the exact BUG-28 emission
   mimz test ok        iverilog 000010101111  sim 101000001111  ✗
```

⑤ produces **byte-identical wrong output to the prior review's Repro A**
(`000010101111`). The same holds for `extend` of an instance port, and for
`abs` of an `if` expression (`010101000`, identical to Repro C's wrong output).
A shift in the same position (`{ b, ident4(a) << 1 }`) is equally broken.

Comparison operands and `$signed`/`$unsigned` arguments happen to survive,
because Verilog's context-determination leaks a width in from the sibling or the
assignment target. The damage is concentrated in **concat member** and
**replication body** - the two positions with no context to leak.

**This is pre-existing, not a regression.** `git show bb79838:…/expr.rs` has the
same two wildcards. The prior review missed it; BUG-35's fix narrowed the
_builtin_ wildcard on line 103 without touching line 105. So the F-1 class was
never closed - only the two instances whose operands happened to be inferrable.

**Blast radius.** A `fn` call or a module instance inside an arithmetic
expression inside a concat is ordinary RTL, not a corner case. The reason no
shipped example trips it is that no shipped example happens to write that
combination - not that the combination is unusual.

**Fix.** Make `kind_is_inferrable` exhaustive over `ExprKind` and over `Builtin`
(no wildcards), the same way `self_determined.rs` now is. The correct answer for
a non-analyzable shape is not "skip the hoist" - it is "hoist conservatively,"
which is always safe (an extra `__mimz_sub_N` wire never changes meaning). That
is the same change [SEC-10](security.md) already asks for (`infer_kind` →
`Option<Kind>`), and doing both at once removes the class rather than the
instances. Add the position matrix's missing axis: every `ExprKind` shape, not
just every `Builtin`.

### 🔴 BUG-42 (CRITICAL) - `min`/`max` are misclassified as "no mismatch possible"; found by the project's own fuzzer

**Filed as [BUG-42](bugs.md).**

`self_determined.rs:72` classifies `Min | Max => None` with the reasoning:

> `min`/`max` render to a ternary whose operands are same-width by the checker's
> own rule, so `max(operand widths) == N`. No mismatch possible.

That reasoning holds for **mimz's** widths and fails for **Verilog's**
self-determined widths - exactly the distinction the file exists to model. If an
operand is itself a mismatched sub-expression (`extend(p, 11)`, which renders as
the bare `(p)`), the ternary self-determines at the _rendered_ operand width, not
at N. The `SignedCast`/`UnsignedCast` arm handles this correctly by recursing;
`Min`/`Max` does not.

Minimal reproduction:

```mimz
module MM {
  in p: signed[6]
  out y: bits[11]
  y = unsigned(min(extend(p, 11), extend(p, 11)))
}
```

```text
emitted    assign y = $unsigned((((p) < (p)) ? ((p)) : ((p))));
mimz eval  y = 2039        (0b11111110111 - sign-extended, correct)
iverilog   y = 55          (0b00000110111 - zero-extended, wrong)
```

The same expression inside a concat is wrong the same way.

**How found.** The project's own differential fuzzer, run at
`MIMZ_DIFF_FUZZ_N=400` (CI default is 20):

```text
differential_fuzz_matches_icarus FAILED
  seed 12648675, vector 0: kernel y=82574208, Icarus y=2579328
```

This is the third instance of the exact class BUG-28/BUG-29 belong to, and it
was introduced **by the fix for them** - the prior review's recommended patch
listed `Min | Max` under the "no mismatch possible" arm, and the team
implemented it verbatim, comment and all.

**Fix.** Recurse, like `Binary` and the casts already do:

```rust
Builtin::Min | Builtin::Max => Some(Kind {
    width: self_determined_operand_width(&args[0], decls)
        .max(self_determined_operand_width(&args[1], decls)),
    signed: infer_kind(expr, decls).signed,
}),
```

Then re-audit `Trunc`, `Nand`, `Nor`, `Xnor` and `Encoding` under the same
question - "is this argument's _rendered_ width necessarily its mimz width?" -
rather than under "is this operator's result width necessarily its mimz width?"
`Trunc` survives (an explicit part-select is exactly N bits regardless of the
base, and BUG-36 already hoists the base). The reductions survive (1 bit both
sides). `Encoding` survives by recursion.

### 🔴 BUG-43 (CRITICAL) - A negative literal is evaluated at its own natural width, so the simulator disagrees with the hardware for almost every `-N`

**Filed as [BUG-43](bugs.md).**

`crates/mimz-sim/src/sim/value/binary.rs:55`:

```rust
UnOp::Neg => {
    let bits = v.as_i128().wrapping_neg() as u128;
    Val::new(bits, v.width, true)      // v.width = the LITERAL's natural width
}
```

`Val::from_int(9)` has `width = 4`, so `-9` is negated inside 4 bits and becomes
`0b0111 = 7`. The result is then a small **positive** value that zero-extends
into whatever signed slot it lands in. Measured on a `signed[6]` port:

| source | simulator | correct |
| ------ | --------- | ------- |
| `-1`   | 1         | 63      |
| `-3`   | 1         | 61      |
| `-5`   | 3         | 59      |
| `-9`   | 7         | 55      |
| `-16`  | 16        | 48      |
| `-17`  | 15        | 47      |

The rule is `-n → 2^natural_width(n) − n`. It is correct only when
`natural_width(n)` equals the target width - which is why the prior review's
Repro C (`a = -8` on `signed[4]`) passed by coincidence.

The **emitter is right**; only the simulator is wrong, so this is a straight
sim-vs-hardware divergence in the direction that makes `mimz test` lie:

```mimz
wire w: signed[8] = -1
b = unsigned(w)
```

```text
emitted   assign w = (-1);  assign b = $unsigned(w);
mimz test FAIL: b = 1
iverilog  b = 255                     ← correct
```

And on the realistic clamp idiom (the shape `showcase/pid_controller.mimz`
already ships, with different constants):

```mimz
y = max(-100, min(x, 100))      // x = -1000
```

```text
mimz eval  y = 28        ✗
iverilog   y = -100      ✓
```

A comparison against a negative literal is silently false:
`q == -9` with `q = -9` evaluates to `0` in the simulator and `1` in Verilog.

**Why it matters more than F-1 did.** F-1 broke a specific syntactic position.
This breaks a _value_, everywhere it appears: wire initializers, comparisons,
`min`/`max` bounds, `fn` arguments, test stimulus. `reg` reset values happen to
be correct (they take a width-aware path), which is exactly why it has gone
unnoticed - the most visible use of a negative constant is the one that works.

**Fix.** A negated integer literal must stay unsized (the checker's own
`Ty::CtInt` treatment - its `Unary::Neg` arm already negates a `CtInt` in place
without promoting it) and adopt the context width, or at minimum be widened by
one bit before negation. The simulator's `Val` has no unsized representation
today, which is the root of it; the narrow fix is for the literal-negation path
in `elaborate` to size the constant from its destination rather than from
`natural_width`. Add the case to the width-conformance oracle once it is made
non-vacuous (GAP-11).

### 🟡 GAP-11 (MEDIUM, testing) - The width-conformance oracle is vacuous, and CI fuzzes at a depth that finds nothing

**Filed as [GAP-11](gaps.md).**

Two separate holes in the oracle work that GAP-5 closed on paper.

**(a) The oracle is nearly tautological.** The prior review asked for: _"after
every simulator evaluation, assert the produced `Val` fits the checker's declared
width **for that expression**."_ What shipped (`assert_bits_fit_width`,
`tests/differential_fuzz.rs:97`) checks only top-level **signals** - ports,
registers, `Timeline::signals`. Its own doc comment is candid about the
consequence:

> `mimz-sim`'s kernel already masks every stored value to its signal's width by
> construction, so this should never fire today

It cannot catch the F-2 class it was written for. F-2's defect was an
_intermediate_ (`din << 2` typed `bits[4]`, valued 60); the value lands in an
`bits[8]` output and fits. Nor can it catch BUG-43, whose wrong value also fits.
The oracle needs to run at every sub-expression, comparing against the
**checker's** `Ty`, not the kernel's own resolved signal width - two independent
authorities, which is the whole point.

**(b) CI fuzzes 20 seeds.** `MIMZ_DIFF_FUZZ_N` and `MIMZ_DIFF_FUZZ_CLOCKED_N`
default to 20 and CI does not raise them. At 400 each, the run takes **55
seconds** and finds two live miscompiles (BUG-42, BUG-44). The single
highest-value change available to this project's CI is one environment variable.

Recommend: raise the per-PR default to a few hundred, add a nightly run in the
thousands with the seed printed on failure, and keep a `regressions/` seed corpus
that is always replayed.

### 🟡 GAP-12 (MEDIUM, performance) - `mimz compile` is superlinear in module size

**Filed as [GAP-12](gaps.md).**

Measured on this machine, release build, one module of N 8-bit registers:

| regs  | source lines | `mimz compile` |
| ----- | ------------ | -------------- |
| 1,000 | 2,010        | 0.43 s         |
| 2,000 | 4,010        | 1.00 s         |
| 4,000 | 8,010        | 3.51 s         |
| 8,000 | 16,010       | 10.57 s        |

4× the input costs **~10×** the time. `mimz check` on the same inputs stays
linear (0.35 s → 0.87 s for 4× input), so this is the **emitter**, not the
checker - which revises the prior review's "scaling is roughly linear" finding
for the compile path specifically.

Proximate cause is visible in the source: `emit_verilog/expr.rs` contains **22**
`self.cur_decls.clone()` calls, each a full `HashMap<String, Kind>` clone of
every declaration in the module, executed **per expression node visited**. With
8,000 declarations and 8,000 assignments that is ~64M entry clones. The hoisting
work (BUG-19 → BUG-36) added most of these call sites.

Fix is local and does not need the IR: hold `cur_decls` behind an `Rc`, or
restructure the borrow so the map is passed by reference. This bundles naturally
with [GAP-4](gaps.md) (interning) but does not depend on it.

### 🔵 Notes on the new `assert` / `cover` implementation (GAP-6)

The feature is real, well-scoped, guarded by `` `ifndef SYNTHESIS ``, and
elaborates cleanly under Icarus. Four observations, none blocking:

1. **`assert` is unqualified combinational** - `always @(*) if (!(cond)) $fatal(1)`.
   It has no clock or reset qualification, so an assertion over registers will
   fire during the reset window and during any combinational settling glitch.
   SystemVerilog's `assert property (@(posedge clk) disable iff (rst) …)` exists
   for exactly this. At minimum, document that `assert` is immediate and
   unclocked; better, allow `assert` inside an `on rise(clk)` block.
2. **`cover` misses time zero** - `always @(__cover_N_cond) if (__cover_N_cond)`
   triggers on a _change_ of the condition. A condition true from time 0 that
   never toggles is never counted.
3. **Cover counts are unreadable from the Verilog side** - `__cover_N_count` is
   incremented and never printed. Add a `$display` summary under
   `` `ifndef SYNTHESIS `` at `$finish`, or the counters are sim-side only.
4. **Hoisted wires for assertion conditions are emitted outside the
   `` `ifndef SYNTHESIS `` guard**, so `__mimz_sub_N` wires that only feed an
   assertion become dead logic in the synthesized netlist. Synthesizers prune
   it; it is still noise in the generated file.

Also worth recording: hoisting **does** fire correctly inside `assert`/`cover`
conditions (verified - `{ b, a + a } == z` produced a properly sized
`wire [4:0] __mimz_sub_2`). The new feature was wired into the existing
machinery correctly.

## Part 4 - Assessment by area

Only deltas against the prior review are recorded; unchanged assessments stand.

### Language design - unchanged strengths, two real additions

`assert`/`cover` and `encoding(e)` both landed, both are the shapes the prior
review recommended, and both are integrated into the checker, emitter and
simulator rather than bolted on. Static CDC and the trilingual front-end remain
the two genuinely unoccupied positions and the right things to lead with.

The growing-shift decision (BUG-30) is defensible and correctly implemented, but
it moved a cost onto the user that is not yet documented anywhere a user will
find it.

### Compiler architecture - the case for the IR is now stronger, not weaker

Every finding in this review is a width/kind rule disagreeing with itself across
two of the three implementations, or a guard-by-convention that a fourth call
site did not honour. BUG-41 is "the classifier is exhaustive but the gate is
not." BUG-42 is "the classifier's reasoning was about the wrong widths." BUG-43
is "the simulator sizes a constant differently from the emitter." These are not
independent bugs; they are the same structural fact reported three times.

The count of "two implementations of one width rule disagreed" bugs is now
BUG-11, 18–24, 28, 29, 30, 34, 35, 36, and 41–43. That is fifteen. The prior
review called GAP-1 the highest-leverage change available; this review would
move it **ahead of** the remaining v0.2 polish, because the v0.2 fixes are
themselves now generating instances of the family they were meant to close.

### HDL correctness - worse than the prior review measured

Three confirmed silent miscompiles at HEAD, one of which (BUG-43) affects a
value rather than a position and reaches ordinary code. The prior review's
5/10 assumed F-1 was the only such defect.

### Testing - the machinery is excellent and the settings are wrong

The position matrix is a genuinely good test (proven by reverting the fix). The
Icarus two-layer differential is the right design. The fuzzer generator is good
enough to find real bugs - it found two in 55 seconds when asked to. The
problems are that the oracle added to it is vacuous, that CI asks it for 20
seeds, and that the position matrix covers one axis of a two-axis space.

### Security & reliability

- `#![forbid(unsafe_code)]` now on `mimz-core`, `mimz-sim`, `mimz-wasm`.
  **Missing on the shell crate** - that is where `emulate/`, `cpal`, `notify`
  and the LSP live, i.e. the crate with the most native surface.
- `cargo audit` gate present in CI. `hardening.md` still records HARD-8 as OPEN.
- SEC-10's `panic!` remains, alongside three more in the same file. BUG-41 is
  the practical argument for fixing it: the pre-check that keeps the panic
  unreachable is the same function whose wildcard causes the miscompile. One
  change (`Option<Kind>` + conservative hoist) closes both.
