## Verdict

> **DO NOT SHIP v0.2.**

Round 5's remediation is, task for task, real. BUG-60's five reproductions and
BUG-61's two are fixed and I could not break any of them; the bare-identifier
control stays unhoisted. `tools/gate.sh` runs 5000/5000, prints the depth, and
propagates its exit code — I saw both its CLEAN and its FAILED banner. The
`--release` drop is in `ci.yml` and in the script, and the debug-mode deep fuzz
came in **faster** than round 5's release run, so the timing claim scales. The
fuzzer bias works: with BUG-60's fix reverted I reproduced a failure at the
**per-PR** depth from scratch, on the recorded seed **and on a second, clocked
seed round 5 never recorded**. The `debug_assert!` fires; I triggered it with my
own injection in a different arm from the one round 5 used.

**And the class is still open, for the sixth round running — this time wider
than any prior round.**

Rule (a′) governs the **arms of four `match`es**. Every instance since round 3
has been at a **hoist call site**, not in an arm's answer. This round's sweep
went to the call sites and found that the entire hoist machinery is **inert
outside a module body**:

```text
fn packit(x: bits[4], b: bits[4]) -> bits[12] { { b, extend(x, 8) } }
  emitted     packit = {b, (x)};
  mimz eval   y = 2575          iverilog   y = 175        ✗
```

That is **BUG-28** — the founding bug of this family, round 1 — alive at HEAD,
inside a `fn` body, because `cur_decls` is built per module and a `fn`'s own
parameters are never in it, so `infer_kind` returns `None` and **every** hoist
call site takes its silent `None => text` fallback. The same hole gives:

- `&extend(x, 8)` in a `fn` → mimz 0, Icarus 1 — **BUG-60, unfixed in `fn` scope
  by the fix that closed it at module scope one commit ago**;
- `extend(x,8)[7]`, `extend(x,8)[1:0]`, `trunc(extend(x,8),2)` in a `fn` →
  **unparseable Verilog**, `mimz check` OK, `mimz compile` exit 0 (BUG-20/49/61's
  class);
- `y = { b, extend(a, W) }` with `W` a **module parameter** → mimz 2575, Icarus
  175, at module scope, no `fn` needed;
- an `expect` in a `test` block → the testbench emitter runs with an **empty**
  `cur_decls`, so `expect &extend(y,8) == 0` renders `(&(y))`: `mimz test` PASS,
  the emitted testbench FAIL, on the same design.

And when a `fn` parameter happens to share a name with a module signal, the hoist
does fire — at **module scope**, reading the module's signal instead of the
argument, emitted **after** the function that references it:

```text
iverilog  error: Unable to bind wire/reg/memory `__mimz_sub_1' in `tb.dut.pack'
```

Separately, and not part of that cluster: **3 of the 6 shipped examples that have
`test` blocks emit a testbench that reports `FAIL` on a correct design.** The
combinational ones (`shift`, `tested_adder`, `enum_encoding`) drive stimulus with
`<=` (BUG-51's fix) and then check in the same time step, so every combinational
`expect` reads the pre-stimulus value. `every_emitted_testbench_passes_iverilog`
never noticed because it only checks that the testbench **elaborates**.

Filed here as **BUG-62 (CRITICAL)**, **BUG-63 (HIGH)** and **BUG-64 (HIGH)**.

**On rule (a′) itself — the round's central judgment.** It is a real
improvement, correctly aimed at the two arms that produced BUG-60, and it is
**mis-scoped and not reliably applicable**:

- **Scope.** It audits what the classifier _answers_. Every live defect in this
  series since round 3 has been about what a _call site does with that answer_ —
  including all three filed here, none of which any arm's text could have
  prevented.
- **Applicability.** I classified six arms independently before reading the
  codebase's verdicts. On **four** I disagree: `Ident`, `Bool`, `Encoding` and
  `Match` all rest on facts about **rendered text** or **emitter behaviour** —
  the actually-correct category, and one (a′-2)'s enumeration (checker rule /
  grammar restriction / lowering pass) does not contain. Applied literally, (a′)
  rejects its own axiom (`Ident`'s "a signal's declared width IS its
  self-determined width").
- **Under-application.** My own grep for Task 5's own keyword list surfaced
  `Builtin::Trunc`'s arm — _"already exactly N bits **regardless of position**,
  so `None` needs no recursion proof"_, cited to a **bare-identifier**
  differential (`trunc(a, 2)`). That is BUG-60's signature, verbatim, in an arm
  Task 5's "every hit, not a sample" sweep did not flag. And it is **false as
  written**: `trunc(extend(x,8), 2)` inside a `fn` emits `(x)[(2)-1:0]`, a syntax
  error.

## Part 3 — Rule (a′): is it enforceable, or is it round 4's audit reworded?

This is the round's central question, so it gets the most space.

### 3.1 Where the rule lives, and what it says

Verified present, in full, in both module docs
(`emit_verilog/self_determined.rs:23-50`, `emit_verilog/kinds.rs:42-56`) and as a
header pointer in all five coverage docs in
`tests/self_determined_regression.rs`. The text is the one GAP-15 records:
an arm returning `None`/`NotApplicable` must carry either **(a′-1)** a
differential whose operand _renders narrower than its mimz width_ — never a bare
identifier — or **(a′-2)** a reason naming a _checker rule, grammar restriction,
or lowering pass by code_, never a property of the operator.

Task 2 is **done as specified**. The rest of this part is about what that buys.

### 3.2 Six arms classified independently — the codebase and I disagree on four

Method: I picked the arms, wrote down my own (a′) verdict, and only then read the
codebase's own text and Task 5's disposition.

| arm                                  | my verdict under (a′), literally                                                                                   | codebase | agree?                      |
| ------------------------------------ | ------------------------------------------------------------------------------------------------------------------ | -------- | --------------------------- |
| CLASSIFIER `ExprKind::Ident`         | **FAIL** — no differential; "a signal's declared width IS its self-determined width, by definition" names no code  | accepted | ❌                          |
| CLASSIFIER `ExprKind::Bool`          | **FAIL** — cites `expr.rs`'s own rendering (a SIZED `1'b1`); an _emitter_ fact is not in (a′-2)'s three categories | accepted | ❌                          |
| CLASSIFIER `Builtin::Trunc`          | **FAIL** — "exactly N bits **regardless of position**", cited by `trunc(a,2)`, a **bare identifier**               | accepted | ❌ (and it is _wrong_, 3.3) |
| CLASSIFIER `Builtin::Encoding`       | **FAIL** — "no enum-typed sub-expression can render narrower"; a type-system argument, no code named               | accepted | ❌                          |
| CLASSIFIER `Builtin::Clog2`          | **PASS** — names E0407, and E0407 really does reject `clog2` in a value position (triggered, below)                | accepted | ✅                          |

Triggered, not read — the three (a′-2) citations I could execute:

```console
$ mimz check  'y = extend(clog2(a), 8)'
error[E0407]: `clog2` is a compile-time built-in and has no value here
$ mimz check  'y = { b, Light.Red }'

$ mimz check  'y = { a, 15 }'

```

All three are real, fire on the exact shape their arm claims, and are **not**
circular — the cited rule genuinely makes the position unreachable. That is the
good news about (a′-2): where it is used as designed, it works.

**The bad news is the disagreement rate.** Four of six, and in three of those
four the arm is _substantively sound_ and the **rule is wrong to reject it**:
`Ident`, `Bool` and `Encoding` all rest on facts about **what the emitter
renders**, which is precisely the question `self_determined.rs`'s own module doc
says to ask ("is this argument's RENDERED width necessarily its mimz width?").
(a′-2)'s enumeration — checker rule, grammar restriction, lowering pass — omits
that category entirely, so the rule as written rejects the answers that are
_most_ on-target, including the axiom (a′-1) itself depends on. Two readers
applying (a′) literally will not classify these arms the same way, and the
codebase's own author did not apply it literally either.

A rule that its author does not apply to four of six arms is not a mechanical
substitute for a second reader. It is a well-aimed reminder.

### 3.3 GAP-15's "every hit, not a sample" sweep missed a hit — and that hit is false

Task 5 states it grepped both matches and all five coverage docs for
"regardless", "always", "in both models", "no mismatch", "no test needed" and
paraphrases, exhaustively. I ran my own sweep over the same file with the same
keyword set plus "by definition", "impossible", "needs no". It surfaces
`builtin_self_determined_coverage`'s `Trunc` arm
(`tests/self_determined_regression.rs:1919-1924`):

> "covered by `matrix_trunc_in_concat_matches_icarus` — direct concat member;
> `trunc` renders an explicit `x[N-1:0]` part-select, already exactly N bits
> **regardless of position**, so `None` **needs no** recursion proof the way
> `Min`/`Max` did"

Two of Task 5's own keywords, on a `None` arm, whose citation is `trunc(a, 2)` —
**a bare identifier**, the exact discriminating failure the `Nand`/`Nor`/`Xnor`
arm was corrected for one screen above. It was not flagged.

It is also not merely non-compliant. It is **false**:

```text
fn low2(x: bits[4]) -> bits[2] { trunc(extend(x, 8), 2) }
  emitted   low2 = (x)[(2)-1:0];
  iverilog  syntax error / Malformed statement
```

"Already exactly N bits regardless of position" holds only where BUG-36's
base-hoist fires, and that hoist is gated on `infer_kind` — the fail-open Part 7
documents. The arm's reason is a property of the operator standing in for a
property of a _hoist_ that does not always happen. This is the round's fourth
watched failure mode — **an (a′-2)-shaped citation that does not establish what
it claims** — and it is live in an arm that a sweep written to find exactly this
shape had just declared clean.

### 4.2 The diversity cost is real, and it is a strict loss, not a trade

`wrap_builtin`'s reduction branch (`tests/differential_fuzz.rs:842-868`):

```rust
let arg = if f.atomic {
    format!("extend({}, {target})", f.text)   // unconditional
} else { f.text };
```

This is deterministic, not probabilistic. `f.atomic` is true for exactly the
bare-port/literal leaves, and reductions are generated **only** here — so
`nand(<bare port>)`, `nor(<bare port>)`, `xnor(<bare port>)` are now
**unreachable by the generator at any depth**. That is the shape
`matrix_nand_in_concat_matches_icarus` pins, and the shape all four flavours of
the shipped `bitops.mimz` example actually use. The fuzz no longer covers it.

I did not need to sample 10,000 programs to establish that — the branch is
straight-line code with no randomness on the `atomic` path, which is stronger
evidence than a sample. The fix is one token: make the wrap probabilistic
(`rng.next_range(2) == 0`), keeping both shapes reachable. Minor, but it is a
coverage **swap** presented as a coverage addition.

### 4.3 A factual error in the filed prose

BUG-60's entry states: _"No shipped example uses a reduction, which is why the
golden suite never saw it."_ Not so:

```text
examples/{english,tanglish,tamil,mixed}/bitops.mimz:21-23
  nd = nand(a)   nr = nor(a)   xn = xnor(a)
```

Four shipped examples use all three reductions. What they do not use is a
**narrow-rendering operand** — which is the real reason the goldens were clean,
and a sharper statement of the same point. Round 5 spot-checked three filed
claims and found 3/3 accurate; this is the first inaccurate one in two rounds,
and it is in the one sentence that explains why the instruments were silent.

assert. It failed as a plain value mismatch (kernel 350, Icarus 158). The assert
only fires when the _rendered text_ is a plain identifier and its declared `Kind`
disagrees.

Reading the second `debug_assert!` (`ports.rs:587`) against its twelve call
sites: every one computes `mimz_kind` as `infer_kind(expr, decls, env)`
immediately before calling `hoist_if_needed(expr, …)`, so the assert compares
`infer_kind(expr)` against `infer_kind(expr)`. It is **tautological as currently
called** — it can only fire if some future caller threads a `Kind` from a
different expression. That is a reasonable tripwire for a future refactor, but it
should not be counted as coverage today, and it is not the instrument that would
have caught anything in Parts 2 or 7.

## Part 7 — New defects

### 7.1 BUG-62 (CRITICAL) — the hoist machinery is inert outside a module body

**Status: OPEN at `1bd8b81`.**

`cur_decls` is built once per module (`module/mod.rs:127`, from that module's own
flattened signals) and is the _only_ source `infer_kind` has. Three emitter
contexts therefore see a `decls` map that cannot resolve the names in front of
them:

1. **`fn` bodies.** `render_fn_decl` (`module/funcs.rs:22`) renders the body with
   the enclosing module's `cur_decls`; a `fn`'s own parameters and `let`s are
   never inserted. `infer_kind` → `None`.
2. **Testbench bodies.** `emit_testbench` (`testbench.rs:151`) constructs its
   `Emitter` with `cur_decls: Default::default()` — **empty**.
3. **Parameter-valued width arguments**, even inside a module body:
   `infer_call`'s `Extend`/`Trunc` arm is `const_fold(&args[1])?`, which is
   `None` for a module `parameter`.

Every hoist call site reacts to `None` identically — render the text unchanged:

```rust
match crate::emit_verilog::kinds::infer_kind(inner, &decls, &self.env) {
    Some(k) => self.hoist_if_needed(inner, x, k, &decls),
    None => x,                    // ← twelve call sites, same fallback
}
```

`hoist_width_effect_operand`'s own comment calls this _"the same, already-correct
fallback these shapes had before this task"_, naming these exact shapes ("a
`fn`-body local, a module `parameter`, a testbench signal, or a symbolic
parametric width"). It is not correct. It is silent.

Ten reproductions, all `mimz check` **OK**, all `mimz compile` **exit 0**,
`a = 0b1111`, `b = 0b1010`, `x = 0b1111`:

| #   | source                                                | emitted                         | mimz      | Icarus                     |
| --- | ----------------------------------------------------- | ------------------------------- | --------- | -------------------------- |
| ①   | `fn allset(x) -> bit { &extend(x, 8) }`               | `allset = (&(x));`              | 0         | **1** ✗ silent             |
| ②   | `fn nandit(x) -> bit { nand(extend(x, 8)) }`          | `nandit = (~&((x)));`           | 1         | **0** ✗ silent             |
| ③   | `fn packit(x, b) -> bits[12] { { b, extend(x, 8) } }` | `packit = {b, (x)};`            | 2575      | **175** ✗ silent           |
| ④   | `fn topbit(x) -> bit { extend(x, 8)[7] }`             | `topbit = (x)[7];`              | 0         | **syntax error**           |
| ⑤   | `fn lowbits(x) -> bits[2] { extend(x, 8)[1:0] }`      | `lowbits = (x)[1:0];`           | 3         | **syntax error**           |
| ⑥   | `fn low2(x) -> bits[2] { trunc(extend(x, 8), 2) }`    | `low2 = (x)[(2)-1:0];`          | 3         | **syntax error**           |
| ⑦   | `module Fuzz(W: int = 8) { y = &extend(a, W) }`       | `assign y = (&(a));`            | 0         | **1** ✗ silent             |
| ⑧   | `module Fuzz(W: int = 8) { y = { b, extend(a, W) } }` | `assign y = {b, (a)};`          | 2575      | **175** ✗ silent           |
| ⑨   | `expect &extend(y, 8) == 0` in a clocked `test`       | `if ((((&(y)) == 0)) !== 1'b1)` | test PASS | **testbench FAIL**         |
| ⑩   | `expect extend(y, 8)[7] == 0` in a `test`             | `((y)[7] == 0)`                 | test PASS | **testbench syntax error** |

③ and ⑧ are **BUG-28's original divergence**, byte for byte (2575 vs 175), still
live: ③ has been live since `fn` bodies existed; ⑧ since module parameters did.
① and ② are **BUG-60**, in a context its one-commit-old fix does not reach.
④⑤⑥ are **BUG-20/49/61**. ⑨⑩ are the testbench emitter, which nothing in this
series has looked at.

**Severity CRITICAL.** ③⑦⑧ are silent wrong hardware from checker-clean,
`mimz test`-passing source. `fn` is chapter 9 of the user guide; `extend` is
chapter 6; a module parameter is the first thing anyone writes when they
generalise a width. The combination is a beginner's second week, not an exotic
corner.

**Fix shape.** Two independent halves.
_(a)_ Give the non-module contexts a real `decls`: `render_fn_decl` should build
and install a `decls` map from the `fn`'s params + `let`s (their widths are
already computed — `LocalLet::inferred_width`, and `self.width(&param.ty)`), and
restore the module's afterwards; `emit_testbench` should install the DUT's own
`decls` for the module under test.
_(b)_ Stop failing open. A hoist site that cannot resolve a `Kind` at a position
whose _shape_ requires a named wire (a slice/bit-select/`trunc` base) has no safe
rendering — it should emit a diagnostic, not invalid Verilog. For the width-
mismatch sites, a `debug_assert!` on `None` at a position known to need one would
have surfaced ①②③ the first time any test touched a `fn` body.

**Category** (round 4's taxonomy): **a fix that doesn't recurse into a nested
position**, generalised one level — not a nested _AST_ position this time, but a
nested _emitter context_. Compounded by **arm present, reasoning wrong**: the
`None => text` fallback carries a written claim that it is "already-correct".

### 7.2 BUG-63 (HIGH) — when the hoist _does_ fire in a `fn` body, it captures the wrong signal

**Status: OPEN at `1bd8b81`.**

The fail-open above is what happens when the module's `decls` cannot resolve a
`fn` parameter's name. When it _can_ — because a module signal happens to share
that name — the hoist fires with the **module signal's** `Kind`, emits its wire
at **module scope**, and the function body references it:

```mimz
fn pack(a: bits[4], b: bits[4]) -> bits[12] { { b, extend(a, 8) } }
module Fuzz { in a: bits[4]  in c: bits[4]  in b: bits[4]  out y: bits[12]
  y = pack(c, b) }
```

```verilog
function automatic [(12)-1:0] pack;
    input [(4)-1:0] a;
    begin  pack = {b, __mimz_sub_1};  end     // reads a module-scope wire
endfunction
wire [7:0] __mimz_sub_1;
assign __mimz_sub_1 = (a);                    // ← the MODULE's `a`, not the argument
```

```text
iverilog  error: Unable to bind wire/reg/memory `__mimz_sub_1' in `tb.dut.pack'
          : A symbol with that name was declared here. Check for declaration after use.
```

Two defects in one emission: the wire is declared **after** the function that
uses it (Verilog forbids the forward reference — this is BUG-45's ordering bug in
a new place), and even if it were ordered correctly it would compute over the
module's `a` while the call passes `c`. `mimz check` OK, `mimz compile` exit 0.

**Severity HIGH** rather than CRITICAL only because Icarus refuses it loudly
today. If the ordering half were fixed alone, this becomes a silent wrong-value
bug.

**Fix shape.** Falls out of BUG-62's fix (a): with a real `fn`-scope `decls`, the
name resolves to the parameter and the hoist is either correct or not attempted.
Until then, `render_fn_decl` should not share `hoisted_decls` with the module at
all.

**Category:** **position not analysed at all** — nobody has asked what a hoist
means inside a `function automatic`.

### 7.3 BUG-64 (HIGH) — every combinational emitted testbench checks before its own stimulus lands

**Status: OPEN at `1bd8b81`.** Independent of BUG-62.

BUG-51's fix made every `TestStmt::Drive` non-blocking (`testbench.rs:64-70`),
which is correct for a clocked test: `tick(clk)` renders
`repeat (N) @(posedge clk);`, so time advances and the NBA lands before the
`expect`. A **combinational** test has no `tick`. Nothing advances time, so every
`expect` executes in the same time step as the drive and reads the **pre-drive**
value.

Swept every shipped example that has `test` blocks — emitted its testbench,
elaborated it, ran it, and compared the verdict with `mimz test`'s:

| example         | shape         | `mimz test` | emitted testbench |
| --------------- | ------------- | ----------- | ----------------- |
| `blinker`       | clocked       | PASS        | PASS ✅           |
| `traffic_light` | clocked       | PASS        | PASS ✅           |
| `vilakku`       | clocked       | PASS        | PASS ✅           |
| `enum_encoding` | combinational | PASS        | **FAIL** ✗        |
| `shift`         | combinational | PASS        | **FAIL** ✗        |
| `tested_adder`  | combinational | PASS        | **FAIL** ✗        |

```text
FAIL: expect (var_shift == 12) failed        # examples/english/shift.mimz
```

**Half the shipped self-checking testbenches report failure on correct designs**,
and have been doing so unnoticed, because
`every_emitted_testbench_passes_iverilog` (`tests/icarus.rs:409`) only asserts
that the testbench **elaborates** (`iverilog -t null`). The single verdict-level
test in the suite, `emitted_testbench_reset_deassert_does_not_race_the_dut`, uses
a **clocked** design — the one shape that works.

The failure is not always loud. A vacuous PASS is just as reachable:

```mimz
test "…" for Fuzz { a = 0b1111  expect &extend(y, 8) == 0 }
```

passes in the emitted testbench while `y` is still `0` from the initialiser — the
check never observed the stimulus at all. That is BUG-54's _false green_ class,
reintroduced by a different mechanism one round after it was closed.

**Fix shape.** One line: emit a `#1;` (or `#0`) after the drive block and before
the first `Expect` when the test declares no clock — or, equivalently, keep
blocking `=` for a test with no `tick`, since BUG-51's race requires a clock edge
to exist. And promote the sweep above into the suite: run each emitted testbench
and assert `PASS`, not merely that it elaborates.

**Category:** **a fix that doesn't recurse into a sibling position** — BUG-51's
`=`→`<=` change applied to every drive, correct only where a `tick` follows.

## Part 8 — The structural finding

**1. Rule (a′) is a better rule aimed at the wrong object.** Round 4 diagnosed
"wrong reasoning in an arm" and prescribed an arm audit. Round 5 found the arm
audit had re-committed the error and prescribed a mechanical arm rule. Both are
correct about arms. Neither is about where the defects are: since round 3, **10
of 14 live instances have been at a hoist call site or in the plumbing that
feeds it**, and the last one a well-worded arm would have prevented was BUG-52,
two rounds ago. Round 5's own
BUG-60 fix says it plainly — the classifier arms were left unchanged because
their answer was right; only the call site was wrong. Filed as GAP-17.

**2. The failure mode has migrated from "what does this arm answer?" to "who is
allowed to ask?"** Every defect this round comes from a context where the
question is never asked at all — a `fn` body, a testbench, a symbolic width — and
where the code's own comment says that not asking is safe. The `None => text`
fallback is now the single largest unaudited surface in the emitter: **twelve
call sites, one shared silent branch, zero tests**.

**3. A clean 5000/5000 gate is now two-ways uninformative.** Round 5: the
generator reaches the shape but not the value. Round 6: the generator cannot
reach the region at all — one trivial `fn` per program, no module parameters, no
emitted-testbench verdicts. The gate is measuring a subset of the language and
reporting it as coverage of the whole. GAP-11's own framing needs restating: it
is not only depth and not only values, it is **grammar**.

**4. The instruments improved, and the thing they measure got smaller.**
`gate.sh` works, the bias works, the assert fires, the corpus replays. Every one
of those is real and verified here. All of them watch the module-body expression
emitter. Nothing in the project watches `render_fn_decl`, `emit_testbench`, or a
parametric width — and this round found a CRITICAL in each.

**5. The count.** Round 5 counted twenty-seven in the "two implementations of one
width rule disagreed" family. Add BUG-62 (which is BUG-28, BUG-60 and BUG-61
simultaneously, in three contexts), BUG-63 and BUG-64: **thirty**. Six rounds,
six rounds of new instances, and for the first time the new instances include the
family's _founding_ bug, unfixed, in a context nobody had looked at.

**6. What would actually close it.** Not another rule about arms.

- **(c) Make the fail-open loud.** `infer_kind` returning `None` at a hoist site
  is a _bug report_, not a fallback. Assert on it in debug (the shapes that
  legitimately cannot resolve are enumerable and few), and diagnose it in release
  where the position's grammar requires a wire. This is XS and it would have
  caught ①–⑧ the first time any test compiled a `fn` body.
- **(d) Give every emitter context a real `decls`.** S effort, mechanical.
- **(e) GAP-1.** Unchanged, and stronger again: a typed elaborated IR has one
  width per node in every context, so "which `decls` is in scope" stops being a
  question that can be answered wrong.

## Ship / do-not-ship

**Do not ship v0.2.**

Six rounds, six rounds of new instances. This one is the widest: the founding bug
of the family (BUG-28) is live at HEAD in two contexts, one commit after the
round that closed its sixth instance.

intuition reworded — it is a genuinely better rule than round 4's, and it does
not close the class, because it constrains the arms of four `match`es while the
defects live at the call sites those arms feed.** Round 5 could have discovered
that from its own fix, which explicitly left the arms unchanged.

Categorised against round 4's three failure modes, plus the fourth this round
watched for:

| instance        | category                                                                                                                                                                                                   |
| --------------- | ---------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| **BUG-62**      | **fix that doesn't recurse into a nested position** — generalised to a nested _emitter context_ — compounded by **arm present, reasoning wrong** (the `None => text` fallback's "already-correct" comment) |
| **BUG-63**      | **position not analysed at all** — a hoist inside `function automatic`                                                                                                                                     |

| **`Trunc` arm** | **circular (a′-2) citation** — the fourth mode: "exactly N bits regardless of position" is a property of the operator standing in for a hoist that does not always fire, and it is false                   |

Does rule (a′) need revision, or was this a case it was never meant to catch?
**Both, and the distinction matters.** BUG-62/63/64 are cases (a′) was never
meant to catch, and that is the finding: the closure condition does not cover the
surface that fails. The `Trunc` arm _is_ a case (a′) was meant to catch, was
looked at by the sweep written to catch it, and survived — so the rule needs
revision too, in one specific way: **(a′-2) must admit a fourth category, "a
checked fact about what the emitter renders", and must forbid resting on a hoist
without naming the call site that performs it and the condition under which it
fires.**

The gap to shippable is once again described as small — three XS fixes and one S.
That description has been accurate every round, and a further instance has been
found in the remainder every round. The difference this time is that the
remaining work is not another arm: it is one invariant, at twelve call sites,
