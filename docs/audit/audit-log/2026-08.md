## 2026-08-09 — **BUG-47 fixed — v0.2 release gate now 5 of 5** (branch `bug-41-42-43-self-determined-class-closure`)

Diagnosis before code: a 21-case matrix over operator x signedness x context width, each cell through both `mimz eval` and Icarus. **Only `Shr` with a signed left operand diverges** — `+%`/`-%`/`*%`/`^`/`&`/`+`/`*`, unsigned `>>` and `<<` all match — which ruled out the feared "any narrow operand under a wider context" width-rules refactor. One matrix cell was a false negative: `(p1 ^ p2) >> 2` read as passing only because the operand happened to be positive for the chosen inputs, so sign extension added zeros; it diverges once negative, and is pinned as its own test. **Cause: a guard that outlived its reason.** `Builtin::Extend` passed `allow_shift: false` to `hoist_width_effect_operand`, suppressing the hoist for a shift argument, justified in a detailed comment by the simulator threading extend's target width in via `eval_ctx(r, &args[0], Some(n))` — but **`eval_ctx` no longer exists**: BUG-34's fused-shift rework replaced it with `binary::eval_shift_chain`, which uses the chain's own bottom-up width and never consults an ambient width.
