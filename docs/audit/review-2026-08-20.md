## Part 2 - The widened invariant, and whether GAP-18 is closed

This is the question rounds 7 and 8 each got wrong about a previous round's own
claim, so it was treated as the round's centre of gravity.

### 2.1 It fires when the fix is reverted

Task 1 was reverted **faithfully**: the `declare_instance_outputs` pre-pass call
disabled in `module()` **and** the pre-Task-1 inline `wire` declaration restored
in `instance()`'s `Dir::Out` arm. The plan is right that disabling the pre-pass
alone is not a revert - it produces a different failure, an undeclared implicit
net, because Task 1 replaced the declare mechanism rather than relocating it.

All three constructions then fail at compile time, exit 1:

```console
$ mimz compile nc1.mimz -o nc1.v
error: GAP-18: declared name `u1_q` referenced before its own declaration -
use at line 9 (`assign __mimz_sub_2 = (u1_q);`), declared at line 10
(`wire [(4)-1:0] u1_q;`). A render site is writing this module's text out of
declare-before-use order - see BUG-70, docs/audit/bugs.md.
```

Identifier and both line numbers, as specified. The `mem`-init case reports
`u1_q` (use 8, declared 14); the `repeat` case reports `u__1_q` (use 11, declared
14), so BUG-53's array naming convention is covered too.

**This is a `Diag` and an exit code, not a panic** - round-8 Task 5's
diagnose-don't-abort fix verified in the same run, on a real binary where
`cfg!(test)` is false, rather than inferred from an in-process test.

### 2.2 It is silent across the corpus with the fix in place

All 226 shipped `.mimz` files compile clean. Reverted, the corpus is **also**
clean - which confirms the plan's own honest note: no shipped file reaches
BUG-70's shape, so the corpus elaboration sweep is a regression net, not a
detector. Recorded here so the next round does not re-derive it.

### 2.3 Independently constructed traps, one per claimed category

The plan lists five categories of false positive it says it handled. Each was
reconstructed from scratch rather than trusting the plan's own examples to map
onto the hazard space.

| Category                           | Construction                                                                                                                                                                      | Outcome                                |
| ---------------------------------- | --------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- | -------------------------------------- |
| Declaration self-reference         | Every `wire`/`reg` line across 226 corpus files                                                                                                                                   | No fire                                |
| **String literals**                | `cover(a[0] == 1)` + `assert(a[1] == 0, "beware __cover_0_count and __cover_0_cond")` - message at line 10, both names declared at 15/16                                          | **Guard load-bearing**; compiles clean |
| `.portname(signal)`                | Parent `wire d` / `wire q` alongside `Sub u1 (.d(q), .q(u1_q))`                                                                                                                   | Clean - but see below                  |
| **`function`/`endfunction` scope** | (a) user `fn helper(value: bits[8])` vs. module `reg value`; (b) `clog2(DEPTH)` width with module `reg i` **and** `reg value`, colliding with **both** of `CLOG2_FN`'s own locals | **Guard load-bearing**; compiles clean |
| **`mem` declaration ordering**     | `wire [(DEPTH)-1:0] w;` emitted **before** `reg [(8)-1:0] m [0:(DEPTH)-1];`                                                                                                       | **Guard load-bearing**; compiles clean |

Three of the five guards are genuinely load-bearing and all three hold. The
`clog2` case is stronger than the plan's own example, which cites a single
colliding local; a design can collide with both.

Two findings about the remaining two:

**`.portname(` is defensive only.** No false positive or false negative could be
constructed. Every `wire`/`reg` declaration precedes every instance line by
construction, so an instance line's port half can never sit before its own
declaration. Correct safety net, not load-bearing. No defect - recorded so a
future round does not spend the same afternoon on it.

**The string-literal guard's doc comment was wrong, and the guard matters.**
`strip_string_literals` claimed no `$display` is ever emitted into a plain module
body. An `assert` emits one directly, at module-item level
(`module/mod.rs`'s `ModuleItem::Assert` arm) and inside an `on` block
(`module/seq.rs`'s `SeqStmt::Assert` arm). With the optional message omitted, the
string's text is the **rendered condition** - real signal identifiers, verbatim.
A user-supplied message is arbitrary text. Either sits textually before the
combinational `cover` block, which declares `__cover_N_cond` / `__cover_N_count`
at the very end of the module - so the construction above is a genuine false
positive that only this function prevents. **No corpus example uses `assert` at
all**, which is why the shape had never been exercised. Comment corrected.

The naive quote toggling in that function is nonetheless safe: mimz's lexer has
no string escape, so E1002 ("unterminated string") rejects any source whose
message contains a quote before emission is ever reached. Confirmed, not assumed.

### 2.4 Header exclusion

`header_end` takes the first line trimming to `);`. Checked across all 243
modules the corpus emits: **exactly one such line per module, always the
header**. A clock/reset-only module still emits a port list, so the `None` branch

- which would restore the BUG-73 shape as a false positive - is unreached.

### 2.5 Residual narrowing, recorded not blocking

The widened invariant skips `function`/`endfunction` blocks **entirely**, so the
`__mimz_fn_sub_N` regs that round 7's narrow scan **did** watch are no longer
covered. Safe today because `render_fn_decl` splices them at a fixed `regs_pos`
before `begin`, i.e. their ordering is structural rather than checked. Likewise,
only `wire`/`reg` lines populate the declaration map - a body `integer` or
`localparam` is outside it; `integer __mimz_m_i;` is emitted immediately before
its only use.

Both are real coverage trades the closure note does not mention. Neither is
reachable today. Worth a sentence in GAP-18's entry if a future round touches
this code.

### 2.6 BUG-73

Not ship-blocking, and **not open**. Reproduced the filed repro at HEAD:

```console
$ mimz check bug73.mimz
OK
$ mimz compile bug73.mimz -o bug73.v
error: `a_tx` is declared more than once in this module
   = help: a port, wire, reg, mem, or instance output already uses this name in
     the emitted Verilog - often a bundle field flattening to `{name}_{field}`
     colliding with an existing signal of that name; rename one of them
$ echo $?

```

A loud compile-time refusal where there used to be a self-referential `assign`
and a duplicate declaration. `docs/audit/bugs/bug-71-80.md` records it correctly
as FIXED 2026-08-19; two **other** places still said it was out of scope and not
fixed (round-8 plan Task 2's status note, and GAP-18's "what widening actually
required" item 4), contradicting the commit they describe. Both corrected.

## Part 6 - BUG-72 and BUG-74

Both were found and fixed (or filed) outside round 8's original plan scope and
had not been reproduced by anyone but their author.

**BUG-72 - reproduced fixed.** The `ShiftRegister` repro
(`sr <- &trunc(sr << 1, WIDTH) | extend(din, WIDTH)`) passes `mimz check`,
compiles exit 0, and elaborates. Both new differentials pass in the full run.

One observation, not a finding: the hoisted base wire takes a **literal** width
derived from the parameter's default (`wire [1:0] __mimz_sub_1` at `WIDTH = 1`)
while the part-select bound stays symbolic (`[(WIDTH)-1:0]`). Unreachable from
mimz - the checker re-checks the module at each instantiation and rejects a
`WIDTH: 8` override with E0402 - but a Verilog-level parameter override of the
emitted module would not do what it looks like it does. A pre-existing property
of the dumb-emitter design, not introduced by this fix, not ship-blocking.

**BUG-74 - reproduced open, and the rotation is not masking anything.**

```console
$ mimz check bug74.mimz
OK
$ mimz compile bug74.mimz -o bug74.v
error: cannot determine `(((toggle == 0)) ? ({1'd0, k, 4'd0}) : ({1'd1, v}))`'s
width here - GAP-16: hoist_unresolved: `infer_kind` returned `None` at
`encoding operand` ...
$ echo $?
1
```

Matches the filed entry, loud rather than silent, and the recorded reachability
is accurate - only a **direct** `if`/`match` argument to `encoding()`; binding it
to a named `wire` first short-circuits through `is_plain_identifier` and is
unaffected.

The pattern worth checking here was tests being quietly repointed at whatever bug
is convenient. It is not what happened: `task2_unresolvable_concat_member_is_a_

## Part 7 - Task 9's deferral

**Acceptance criterion reproduced independently.** Rather than trusting the named
seed index, the criterion was re-derived the way it is stated: with Task 1
reverted, the clocked differential at `MIMZ_DIFF_FUZZ_CLOCKED_N=400` fails in
5.0 s -

```console
thread 'differential_fuzz_clocked_matches_icarus' panicked:
`mimz compile ...mimz` failed:
error: GAP-18: declared name `s_q` referenced before its own declaration -
use at line 14 (`assign __mimz_sub_1 = (s_q);`), declared at line 21
(`wire [(14)-1:0] s_q;`).
```

Same identifier the plan names. The generator genuinely reaches BUG-70's shape
well inside 400 seeds, and the widened invariant genuinely catches it there. Both
halves of the criterion hold.

**GAP-20's deferral reasoning checked against the kernel, not just read.** The
claim is that a non-constant `reg` reset or `mem` initialiser cannot be added to
the generated grammar without a separate Icarus-only oracle, because `mimz-sim`
requires a compile-time-constant power-on value. Confirmed directly for **both**
sites: each passes `mimz check` and `mimz compile` and is rejected by
`mimz-sim`'s elaborator with **E0201 - "this expression is not a compile-time
constant"**. Teaching either generator site a real expression would therefore
break `differential_fuzz_clocked_matches_icarus`'s own `elaborate_project`/`run`
calls for every program reaching it. The deferral is accurate and the remaining
half is correctly tracked as GAP-20 rather than silently folded in.
