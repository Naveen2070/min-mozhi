Written fresh from the round-2 filing (not copied from the repo's tests), driven
through the real `mimz` binary and `iverilog -g2005` + `vvp`:

```text

   emitted  wire [4:0] __mimz_sub_1; assign __mimz_sub_1 = (ident4(a) + a);
   mimz test ok    iverilog 101011110 == sim 101011110      PASS
② y = { b, s.q + a }                    (plain, non-array instance)
   emitted  wire [4:0] __mimz_sub_1; assign __mimz_sub_1 = (s_q + a);
   mimz test ok    iverilog 101011110 == sim                PASS
③ y = { b, (if cond { a } else { b }) + a }
   emitted  wire [4:0] __mimz_sub_1; assign … = (((cond)?(a):(b)) + a);
   mimz test ok    iverilog 101011110 == sim                PASS
④ y = { b, m[raddr] + m[raddr] }        (mem read, after one rising edge)
   emitted  wire [4:0] __mimz_sub_1; assign … = (m[raddr] + m[raddr]);
   mimz test ok    iverilog 101011110 == sim                PASS
⑤ y = { b, extend(ident4(a), 8) }       BUG-28 verbatim through a fn call
   emitted  wire [7:0] __mimz_sub_1; assign __mimz_sub_1 = (ident4(a));
   mimz test ok    iverilog 101000001111 == sim             PASS
```

I also added `match` in the same position (round 2 listed `Match` among the
shapes the retired gate swallowed, and the repo has no `Match` regression test
for it). It hoists correctly:

```text
y = { b, (match sel { 0b00 => a; 0b01 => b; _ => a }) + a }
   emitted  wire [4:0] __mimz_sub_1;  ✓
```

**Structural verification.** `kind_is_inferrable` is **gone** — a repo-wide grep
returns only comments referring to the retired function, no live code. That is
better than round 2 asked for: rather than making the second match exhaustive,
the second match was deleted, so there is nothing left to hand-sync. `infer_kind`
now returns `Option<Kind>` and there is no `panic!` on its path — **SEC-10 is
closed** in the same change, as recommended.

**Where the fix diverges from the recommendation, and why it matters.** Round 2
asked for "non-analyzable → **hoist conservatively**". What shipped is
"non-analyzable → **skip the hoist**", documented as a deliberate choice
(`kinds.rs:77–82`, `expr.rs:196–202`) with the argument that a `wire`
declaration needs a concrete width, which is exactly what the `None` branch does
not have. **That argument is technically correct** — you genuinely cannot
declare `wire [?:0]` in Verilog-2005 — and I am not going to pretend otherwise.
But the consequence was not carried through: the unsafe default survived, so
every shape `infer_kind` still cannot resolve is still a silent miscompile
waiting for someone to write it. Two of them are written below.

**Revert test (round 2's own standard, re-run).** I disabled the five arms

### BUG-44 — minimized, and **not** a duplicate

Round 3 was asked to confirm which, not assume. It is a **distinct root cause**:
`trunc(x, N)` keeps its operand's signedness in the checker, the simulator and
`kinds.rs`, but renders as a Verilog part-select, and a part-select is
unconditionally **unsigned** in Verilog-2005 (IEEE 1364-2005 §5.1.7) even off a
`signed` wire. Fixed by wrapping the part-select in `$signed(...)` when the base
is signed.

Proved by revert: I disabled that wrap and replayed the corpus at `N=0`:

```text
seed 202427830, cycle 1: kernel y=13806 but Icarus y=11010110011110   ← BUG-44's original seed
```

So the filed seed reproduces the filed bug, through the filed fix. That is the
evidence round 3 asked for. It is worth recording that this is the same
disagreement family as BUG-41/42, on the **`signed`** half of `Kind` rather than
the `width` half — which is precisely why round 2's re-audit of `Trunc`, which
reasoned only about width, concluded "no mismatch possible" and was wrong.

### GAP-11(a) — the oracle

What round 2 asked for: _"run at every sub-expression, comparing against the
**checker's** `Ty`, not the kernel's own resolved signal width."_

What shipped is different, and mostly better. `gen_expr_collecting` now
**materializes every internal node as its own output port** (up to 8 per
module), so each intermediate is:

1. declared at the generator's width, which the **checker** must accept — and
   the simulator's independently resolved `Output::width` is asserted equal to
   that declaration (`differential_fuzz.rs:1211`). Two authorities on width.
2. compared **kernel vs Icarus** in its own right, not only as it survives to
   the root.

**Is it load-bearing?** Yes — proven, not argued. With BUG-44's `$signed` wrap
reverted, comb seed 12648671 fails **at `y3`**, a materialized intermediate,
while the root `y` (2 bits) agrees:

```text
seed 12648671, vector 0: our kernel y3=Small(0) but Icarus y3="1"
```

A root-only differential misses that seed entirely. This is a genuinely good
piece of test engineering and it is the strongest thing in this round's work.

**Why it deviates from the literal recommendation, and why that is fine.**
`gaps.md` records the reason and it is a good one: the checker's `Ty`/`infer_ty`
are private by design (_"lives only inside this pass — the AST stays untyped"_),
so comparing against them from `tests/` would mean punching a public hole in the
checker for a test. Materialising the intermediate as a declared port gets the
same two authorities without that. The project ran the same A/B I ran
independently, and reached the same result. **Credit where it is due: this is
better engineering than what round 2 asked for.**

**What is still open, by the project's own account.** `assert_bits_fit_width`
— the actual _width-conformance_ assertion, the thing round 2 called vacuous —
is unchanged and still tautological. Both the test source
(`tests/differential_fuzz.rs:1209`) and `gaps.md` say so: _"on its own it remains
tautological, which was the original finding."_

The honest summary: **a per-sub-expression _differential_ oracle now exists,
works, and is proven load-bearing; a per-sub-expression _width-conformance_
oracle still does not exist.** For catching miscompiles the first is stronger.
For the specific F-2 shape (value exceeds its declared width, but sim and Verilog
agree with each other and both disagree with the type) it is not sufficient —
materialising such an intermediate into a declared-width port makes both engines
truncate it identically, so the differential agrees and the width assert passes.
That shape is currently unreachable because BUG-30's growing-shift fix removed
the only known instance; nothing structurally prevents the next one. Call GAP-11
**closed enough to ship on**, with the residual noted rather than re-litigated.

One stale line: GAP-11's mid-entry _"direction 3 (the (a) half) is untouched and
GAP-11 stays open on it"_ was superseded by the `(a) resolved 2026-08-09`
section below it and never removed, so the entry reads as contradicting itself.

### GAP-11(b) — fuzz depth

Closed, and done thoughtfully. The first draft raised the in-source default and
was correctly reverted: depth costs ~3 process spawns per seed, so it belongs in
CI, not in every contributor's `cargo test`.

| where                              | seeds | measured                      |
| ---------------------------------- | ----- | ----------------------------- |
| in-source `DEFAULT_FUZZ_N`         | 20    | fast local default            |
| `ci.yml` → `check` (per PR)        | 400   | 78.6 s here, release          |
| `ci.yml` → `fuzz-nightly` (weekly) | 5000  | not run; 2000 run here, clean |

Plus `tests/fixtures/fuzz-seeds/{comb,clocked}.txt` — every seed that ever
failed, replayed **before** the fresh seeds at every depth including `N=0`, with
an assert against an empty/all-commented corpus so coverage cannot be lost
silently. Four of the ten sit past the per-PR depth and are only reachable from
there. This is the right design.

One nit, and it is not cosmetic: round 2 asked for a **nightly** deep run;
`fuzz-nightly` is scheduled `0 4 * * 1` — **weekly**, on Mondays. The job that
would have caught BUG-47 before the release gate did runs 52 times a year, not 365. Given the project's own note that _"every deeper run on 2026-08-09 found
something,"_ that is the wrong frequency for the phase the project is in.

### GAP-12 — performance

Re-measured with the same shape round 2 used (one module of N 8-bit registers),
release build, this machine, best of 3, process startup measured separately at
17.8 ms:

| regs  | lines  | `check` | `compile` | round-2 `compile` |
| ----- | ------ | ------- | --------- | ----------------- |
| 1,000 | 2,009  | 0.036 s | 0.047 s   | 0.43 s            |
| 2,000 | 4,009  | 0.047 s | 0.064 s   | 1.00 s            |
| 4,000 | 8,009  | 0.088 s | 0.131 s   | 3.51 s            |
| 8,000 | 16,009 | 0.241 s | 0.345 s   | 10.57 s           |

**~30× faster at 8k registers.** A second, hoist-heavy variant (every register
driven by `{ b, a + a }`, so the hoist machinery runs per assignment) to make
sure the win is not an artefact of a trivial body:

| regs   | `compile` | per-doubling |
| ------ | --------- | ------------ |
| 1,000  | 0.060 s   | —            |
| 2,000  | 0.082 s   | 1.36×        |
| 4,000  | 0.167 s   | 2.04×        |
| 8,000  | 0.501 s   | 3.00×        |
| 16,000 | 1.069 s   | 2.13×        |

End to end, 16× the input costs 25× the time (startup subtracted) — a scaling
exponent of **≈1.16**, against ≈1.5–1.7 before. So: **not perfectly linear, but
no longer meaningfully superlinear**, and the absolute numbers are now
irrelevant at any size a user will write. `Rc<HashMap>` for `cur_decls` was the
right local fix and did not need the IR. Golden files are byte-identical, which
is the correct proof that a perf change was behaviour-preserving.

Docs nit: `gaps.md`'s GAP-12 body still reads **"Status: OPEN"** while the index
table two screens up says **CLOSED**.

### Round-2's `assert`/`cover` observations — all four still open

Verified in `emit_verilog/module/mod.rs`:

1. `assert` is still unqualified combinational — `always @(*) if (!(cond)) $fatal(1)` (`:435`). Fires during reset and during combinational settling.
2. `cover` is still edge-sensitive — `always @(__cover_N_cond) if (…)` (`:461`). A condition true from time 0 that never toggles is never counted.
3. Cover counts are still never printed. `__cover_N_count` is incremented and read by nothing.
4. Hoisted wires for assertion conditions are still injected outside the `` `ifndef SYNTHESIS `` guard.

None blocking; all four are cheap and #2 makes `cover` quietly under-report,
which is the worst failure mode a coverage feature can have.

## Part 3 — New defects

### 🔴 BUG-48 (CRITICAL) — Two more `ExprKind` shapes fall through `infer_kind`, reopening BUG-28/29 with byte-identical output

**Filed as [BUG-48](bugs.md).**

`kinds.rs::infer_kind` is now the single gate. It is exhaustive over `Builtin`
but **not** over `ExprKind`: it ends in `_ => None` (`:191`), and two of the arms
BUG-41's fix added contain their own early `return None`:

```rust
ExprKind::Field { base, field } => {
    let ExprKind::Ident(base_name) = &base.kind else {
        return None;                       // kinds.rs:171 — array-instance port
    };
    …
}
ExprKind::Slice { hi, lo, .. } => {
    let hi_v = const_fold(hi)?;            // kinds.rs:132 — literal bounds only
    let lo_v = const_fold(lo)?;
    …
}
```

Every one of those `None`s reaches `expr.rs`'s call sites, which respond by
skipping the hoist — the exact mechanism of BUG-41. Two ordinary, shipped-syntax
shapes land there.

**Shape A — an array-instance output port** (`s[0].q`, the `Field { base: Index }`
form that `examples/english/ripple_adder.mimz:22` already uses in production
code as `fa[i - 1].cout`):

```mimz
module Sub { in x: bits[4]  out q: bits[4]  q = x }

module Top {
  in a: bits[4]  in b: bits[4]  out y: bits[9]
  repeat i: 0..1 { let s[i] = Sub() { x: a } }
  y = { b, s[0].q + a }
}
```

```text
emitted    assign y = {b, (s__0_q + a)};      ← no __mimz_sub_N
mimz test  ok (1 passed)
iverilog   y = 010101110  (174)
sim        y = 101011110  (350)               ✗
```

`010101110` is byte-identical to round 2's BUG-41 repro ②.

**Shape A′ — the same shape under `extend`**, i.e. BUG-28 verbatim:

```mimz
  y = { b, extend(s[0].q, 8) }                 // y: bits[12]
```

```text
emitted    assign y = {b, (s__0_q)};          ← BUG-28's original emission
mimz test  ok
iverilog   y = 000010101111  (175)
sim        y = 101000001111  (2575)           ✗
```

`000010101111` is byte-identical to **round 1's Repro A** and **round 2's BUG-41
repro ⑤**. Third round, same bytes.

**Shape B — a slice whose bounds are a `const`/parameter** rather than a
literal. The bound folds correctly in the _emitted text_ (`a[3:0]`), but the AST
still holds an `Ident`, so `const_fold` returns `None`:

```mimz
module S {
  const HI: int = 3
  in a: bits[8]  in b: bits[4]  out y: bits[9]
  y = { b, a[HI:0] + a[HI:0] }
}
```

```text
emitted    assign y = {b, (a[3:0] + a[3:0])};  ← no hoist
mimz test  ok
iverilog   y = 010101110  (174)
sim        y = 101011110  (350)                ✗
```

**Blast radius.** Instance arrays are how this language expresses a bit-sliced
datapath — the ripple adder, the shipped example for `repeat`, is exactly that.
`const`-bounded slices are how a parameterised design slices a bus. Neither is a
corner case; they are simply combinations no test happened to write.

**Severity.** CRITICAL, same as BUG-41: simulator green, hardware wrong, no
diagnostic, survives `mimz check`, `mimz test`, the Icarus example suite and the
differential fuzzer (whose generator emits neither shape).

**Fix.** Two lines of coverage plus one line of principle:

- `Field`: when `base` is `Index { Ident(arr), idx }` and `idx` const-folds,
  look up the same `{arr}__{n}_{field}` key `expr.rs:280` already renders. That
  is one `else if` next to the existing `Ident` case.
- `Slice`: fold `hi`/`lo` through `consteval::eval` against the module env
  rather than the literal-only `const_fold`, which is the same authority the
  checker's `slice_ty` already used to accept the program.

Neither is the real fix. The real fix is Part 4.

### 🟠 BUG-49 (HIGH) — The same residue emits _invalid_ Verilog: a part-select on a composite base

**Filed as [BUG-49](bugs.md).**

BUG-36 established that `trunc(expr, N)` must hoist a composite base to a named
wire, because Verilog's part-select grammar accepts only an identifier. BUG-46
extended that to module parameters. Both hoists are gated on
`infer_kind(base)` — so both fail open on BUG-48's two shapes:

```mimz
module B {
  in a: bits[4]  out y: bits[3]
  repeat i: 0..1 { let s[i] = Sub() { x: a } }
  y = trunc(s[0].q + a, 3)
}

module D {
  const HI: int = 3
  in a: bits[8]  out y: bits[3]
  y = trunc(a[HI:0] + a[HI:0], 3)
}
```

```text
emitted   assign y = (s__0_q + a)[(3)-1:0];
          assign y = (a[3:0] + a[3:0])[(3)-1:0];
mimz test ok (2 passed)
iverilog  sweep_more.v:25: syntax error
          sweep_more.v:25: error: Syntax error in continuous assignment
          exit 2
```

**`mimz check` and `mimz test` both pass and `mimz compile` emits Verilog that
does not parse.** Less dangerous than BUG-48 because it is loud — but it means
the compiler's own output is not guaranteed to be syntactically valid Verilog,
which is a weaker guarantee than the project currently claims anywhere it
mentions Icarus.

Same root cause, same fix, and it is the second distinct symptom class from one
`None`, which is the argument for fixing the class rather than the instances.

### 🟡 GAP-13 (MEDIUM, testing) — The position matrix's `ExprKind` axis still does not exist, and the only structural coverage assertion was deleted

**Filed as [GAP-13](gaps.md).**

Round 2's priority #6 was: _"Extend the position matrix's second axis — every
`ExprKind` shape in a self-determined position, not only every `Builtin`.
Without it, #2 regresses on the next expression form added."_

What landed instead:

- Five hand-written regression tests, one per BUG-41 repro. Excellent tests —
  my revert proved all five are load-bearing — but they are a list of five
  shapes, not an axis.
- `matrix_shape` / `ALL_BUILTINS` were **deleted** (Task 4), on the reasoning
  that the real matches are already wildcard-free so the compiler enforces the
  builtin axis. That reasoning is correct _for `Builtin`_. It removed the file's
  only structural coverage assertion of any kind, and nothing replaced it for
  `ExprKind` — where the match is **not** wildcard-free.
- The comment block that justified concat-only position coverage
  (`self_determined_regression.rs:566–584`) was kept and extended. It is the
  same "one gate-and-classifier pair, so shape coverage is redundant" argument
  round 2 identified as _the assumption that let BUG-41 hide_. It is still true
  about positions and still silent about shapes.

My revert test is the measurement: breaking the classifier for five `ExprKind`
shapes failed **exactly five tests, all five of them the hand-written repros for
those exact shapes**. Nothing generalises. A sixth shape — and there are two,
filed above — is caught by nothing.

**Recommendation.** An exhaustive `match` over `ExprKind` in the test file,
each arm returning either a `.mimz` source that places that shape in a concat
member, or an explicit `NotApplicable` with the reason. A new `ExprKind` variant
then fails the build until someone classifies it. That is what `matrix_shape`
did for `Builtin`, aimed at the axis that actually still needs it. Pair it with
teaching the fuzz generator to emit `fn` calls, instance ports (plain **and**
array), `if`/`match`, `mem` reads and `const`-bounded slices — the generator's
expression vocabulary is currently why 2000 seeds cannot find BUG-48.

## Part 4 — The structural finding

Three rounds have now each found the same defect in a place the previous round
did not check. It is worth being precise about why, because the fixes have been
good and the outcome has not changed.

| Round | Instance                    | The surface that was not exhaustive                                  |
| ----- | --------------------------- | -------------------------------------------------------------------- |
| 1     | BUG-28/29 (`extend`, `abs`) | the classifier's `Builtin` match                                     |
| 2     | BUG-41 (5 shapes)           | the _gate_'s `ExprKind` match                                        |
| 2     | BUG-42 (`min`/`max`)        | the classifier's _reasoning_, not its coverage                       |
| 3     | BUG-48/49 (2 shapes)        | the surviving gate's `ExprKind` match — the _same_ surface as BUG-41 |

Round 2's fix collapsed two matches into one, which correctly removes the
hand-sync failure. But the merged function kept `None`-means-skip, so the
property "an unclassified shape is silently unprotected" survived the
refactor unchanged. The number of places to get it wrong went from two to one;
the consequence of getting it wrong in the remaining one did not change at all.

There are only two ways out, and the project should pick one deliberately rather
than a third time by attrition:

**(a) Make `None` impossible in a hoist-relevant position.** Give the emitter a
width for every expression that can legally appear in a self-determined
position. Concretely: `Field` over an array instance, `Slice` with a const-folded
bound, and then a build-time-enforced `ExprKind` match with an explicit
"structurally cannot appear here" arm for each remaining variant, so the next
expression form fails the build. This is the small version, and GAP-13 is its
test half.

**(b) Do GAP-1.** With a typed elaborated IR, `Ext` is a node the emitter
_must_ materialise, and there is no "shape the emitter could not analyse"
because the emitter no longer analyses shapes. Round 2 counted fifteen bugs in
the "two implementations of one width rule disagreed" family; this round adds
BUG-47, BUG-48 and BUG-49, making it **eighteen**, and three of those were
generated by the fixes for the previous ones.

My recommendation is (a) now — it is a day, it closes the two live defects, and
the build-enforced match is what makes the release-note claim true rather than
nearly true — and (b) as the v0.3 headline, promoted above every remaining
language feature. The project's own plan already reaches this conclusion in
`phase-2-ir-synthesis.md`; what this round adds is that the cost of deferring it
is now measurable at roughly one CRITICAL per release cycle.

One more thing worth saying plainly, because it cuts the other way: **the
project found BUG-47 itself, by running its own gate at a depth CI does not
reach, and filed it against itself with a full write-up including a false
start.** That is exactly the behaviour that makes an audit worth running. The
process here is working; it is the exhaustiveness discipline that is not yet
mechanised.
