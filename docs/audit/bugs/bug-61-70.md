## BUG-61 (HIGH, FIXED 2026-08-13) — `ExprKind::Index`'s base is never hoisted: a bit-select over a composite expression emits unparseable Verilog

**What.** BUG-20 forces a non-identifier **slice** base to a named wire. Nothing
does the same for a **bit-select** base, so `extend(a, 8)[7]` emits a bit-select
applied directly to a parenthesized expression, which is not legal
Verilog-2005.

Two reproductions, both `mimz check`-clean and `mimz compile` exit 0:

| source                | emitted                 | `iverilog -g2005`                                        |
| --------------------- | ----------------------- | -------------------------------------------------------- |
| `y = extend(a, 8)[7]` | `assign y = (a)[7];`    | `syntax error` · `Syntax error in continuous assignment` |
| `y = {a, b}[3]`       | `assign y = {a, b}[3];` | `syntax error` · `Syntax error in continuous assignment` |

`mimz eval` answers correctly (0 for the first, on `a = 0b1111`), so the checker
and the kernel agree with each other and only the emitter is wrong — the same
shape as BUG-49.

**Control case, which pins the diagnosis.** The **slice** form of the identical
expression, `extend(a, 8)[7:4]`, hoists correctly
(`wire [7:0] __mimz_sub_1; assign y = __mimz_sub_1[7:4];`) and agrees with
Icarus at 0. The machinery exists and is correct; `Index` was never wired into
it.

**Cause.** `ExprKind::Slice`'s render arm calls `hoist_slice_base_if_needed`;
`ExprKind::Index`'s bit-select branch (`emit_verilog/expr.rs:703`) does not.
The coverage axis's `Index` arm reads _"a bit-select is 1 bit in both models; a
`mem` read renders as the declared element width"_ and cites
`bug_41_mem_read_operand_of_add_in_concat_matches_icarus` — again a claim about
the **result**, and a citation covering only the mem-read branch. The
bit-select branch's **base** is unexamined in both the code and the Task 4
audit.

**How found.** Round-5 review ([`review-2026-08-13.md`](review-2026-08-13.md)),
same sweep as BUG-60 — probing every classifier arm that returns `None` with an
operand that renders narrower than its mimz width.

**Severity.** HIGH, not CRITICAL — same reasoning as BUG-49: a loud Icarus
elaboration failure at the user's first `iverilog` step, not a silent wrong
value. Not ruled out: whether another synthesis toolchain accepts this text and
assumes some width.

**Fix (2026-08-13, round-5 plan Task 3).** Called the existing
`hoist_slice_base_if_needed` from `ExprKind::Index`'s bit-select render arm,
exactly as `ExprKind::Slice`'s arm already does a few lines away, same
`signed: false` argument. 2 new differentials in
`tests/self_determined_regression.rs`
(`bug_61_bit_select_of_an_extend_hoists_the_base_and_matches_icarus`,
`bug_61_bit_select_of_a_concat_hoists_the_base_and_matches_icarus`). Watched
fail first: reverted just the new hoist call, both failed (real Icarus syntax
error, matching the filed repro), restored, both pass. Coverage doc's `Index`
arm (`expr_kind_self_determined_coverage`) rewritten to state the base is a
separate self-determined position from the result the arm's own `None`
answers, and to cite the new tests. Workspace **1256/1256** (35 suites),
fmt/clippy clean.

**Category** (round-4 taxonomy): _a fix that doesn't recurse into a nested
position_ — BUG-20's slice-base hoist, never extended to the sibling node.

## BUG-62 (CRITICAL, OPEN) — the self-determined hoist machinery is inert outside a module body: `fn` bodies, testbench bodies, and parameter-valued widths

**Status:** OPEN at `1bd8b81`. Filed 2026-08-15 by round 6
([`review-2026-08-15.md`](review-2026-08-15.md)).

**What.** Every hoist call site in `emit_verilog/expr.rs` is gated on
`kinds::infer_kind` resolving a `Kind`, and reacts to `None` by rendering the
text unchanged. `infer_kind`'s only data source is `cur_decls`, which
`module()` builds **once per module** from that module's own signals. Three
emitter contexts therefore run the whole machinery blind:

1. **`fn` bodies** — `render_fn_decl` (`emit_verilog/module/funcs.rs:22`)
   renders the body under the enclosing module's `cur_decls`; the `fn`'s own
   parameters and `let`s are never inserted.
2. **Testbench bodies** — `emit_testbench` (`emit_verilog/testbench.rs:151`)
   constructs its `Emitter` with `cur_decls: Default::default()` — empty.
3. **Parameter-valued width arguments**, inside an ordinary module body —
   `infer_call`'s `Extend`/`Trunc` arm is `const_fold(&args[1])?`, which is
   `None` for a module `parameter`.

Ten reproductions, every one `mimz check` **OK** and `mimz compile` **exit 0**
(`a`/`x` = `0b1111`, `b` = `0b1010`):

| #   | source                                                | emitted                         | mimz      | Icarus                     |
| --- | ----------------------------------------------------- | ------------------------------- | --------- | -------------------------- |
| ①   | `fn allset(x) -> bit { &extend(x, 8) }`               | `allset = (&(x));`              | 0         | **1** — silent             |
| ②   | `fn nandit(x) -> bit { nand(extend(x, 8)) }`          | `nandit = (~&((x)));`           | 1         | **0** — silent             |
| ③   | `fn packit(x, b) -> bits[12] { { b, extend(x, 8) } }` | `packit = {b, (x)};`            | 2575      | **175** — silent           |
| ④   | `fn topbit(x) -> bit { extend(x, 8)[7] }`             | `topbit = (x)[7];`              | 0         | **syntax error**           |
| ⑤   | `fn lowbits(x) -> bits[2] { extend(x, 8)[1:0] }`      | `lowbits = (x)[1:0];`           | 3         | **syntax error**           |
| ⑥   | `fn low2(x) -> bits[2] { trunc(extend(x, 8), 2) }`    | `low2 = (x)[(2)-1:0];`          | 3         | **syntax error**           |
| ⑦   | `module Fuzz(W: int = 8) { y = &extend(a, W) }`       | `assign y = (&(a));`            | 0         | **1** — silent             |
| ⑧   | `module Fuzz(W: int = 8) { y = { b, extend(a, W) } }` | `assign y = {b, (a)};`          | 2575      | **175** — silent           |
| ⑨   | `expect &extend(y, 8) == 0` in a clocked `test`       | `if ((((&(y)) == 0)) !== 1'b1)` | test PASS | **testbench FAIL**         |
| ⑩   | `expect extend(y, 8)[7] == 0` in a `test`             | `((y)[7] == 0)`                 | test PASS | **testbench syntax error** |

③ and ⑧ are BUG-28's original divergence, value for value (2575 vs 175), still
live. ① and ② are BUG-60 in a context its own fix does not reach. ④⑤⑥ are
BUG-20/BUG-49/BUG-61's class.

**Cause.** The shared fallback, at twelve call sites:

```rust
match crate::emit_verilog::kinds::infer_kind(inner, &decls, &self.env) {
    Some(k) => self.hoist_if_needed(inner, x, k, &decls),
    None => x,                    // ← silent, everywhere
}
```

`hoist_width_effect_operand`'s own comment names these exact shapes ("a
`fn`-body local, a module `parameter`, a testbench signal, or a symbolic
parametric width") and calls the fallback "the same, already-correct fallback
these shapes had before this task". It is not correct — it is silent. This is
the same `infer_kind`-returns-`None` residue as BUG-41/46/48/49, whose fixes
each removed one _source_ of `None` without ever making the _fallback_ safe.

**How found.** Round-6 review, sweeping the hoist call sites rather than the
classifier arms — the surface rule (a′) does not cover ([GAP-17](gaps.md)).

**Why no instrument saw it.** The differential fuzzer emits exactly one `fn`
per program, `fn identW(x: bits[W]) -> bits[W] { x }`
(`tests/differential_fuzz.rs:1086`), whose body is a bare parameter, and never
emits a module `parameter` at all. Both regions are unreachable by the
generator's grammar at any depth and under any value policy. The emitted
testbench layer is checked for elaboration only (`tests/icarus.rs:409`), never
for its verdict. No shipped example puts a width-effect expression in a
self-determined position inside a `fn` (`foreach_sum.mimz` comes closest, and
its `acc +% extend(v, 11)` is context-determined, hence benign).

**Severity.** CRITICAL — ③⑦⑧ are silent wrong hardware from checker-clean,
`mimz test`-passing source, and `fn` plus a parametric width is ordinary
second-week code, not a corner.

**Fix shape.** Two independent halves.
_(a)_ Give the non-module contexts a real `decls`: `render_fn_decl` should
build one from the `fn`'s params (`self.width(&param.ty)`) and `let`s
(`LocalLet::inferred_width`), install it for the body, and restore the module's
afterwards; `emit_testbench` should install the DUT module's own `decls`.
_(b)_ Stop failing open: at a position whose _grammar_ requires a named wire (a
slice/bit-select/`trunc` base) an unresolvable `Kind` has no safe rendering and
should be a diagnostic; at the width-mismatch sites a `debug_assert!` on `None`
would have surfaced ①–③ the first time any test compiled a `fn` body.

**Category** (round-4 taxonomy): _a fix that doesn't recurse into a nested
position_, generalised from a nested AST position to a nested **emitter
context** — compounded by _arm present, reasoning wrong_ (the fallback's own
"already-correct" comment).

## BUG-63 (HIGH, OPEN) — a hoist inside `function automatic` emits a module-scope wire that captures the module's signal, after the function that reads it

**Status:** OPEN at `1bd8b81`. Filed 2026-08-15 by round 6
([`review-2026-08-15.md`](review-2026-08-15.md)).

**What.** BUG-62 above is what happens when the module's `decls` cannot resolve
a `fn` parameter's name. When it _can_ — because a module signal happens to share that name — the
hoist fires with the **module signal's** `Kind` and emits its wire at **module
scope**:

```mimz
fn pack(a: bits[4], b: bits[4]) -> bits[12] { { b, extend(a, 8) } }
module Fuzz { in a: bits[4]  in c: bits[4]  in b: bits[4]  out y: bits[12]
  y = pack(c, b) }
```

```verilog
function automatic [(12)-1:0] pack;
    input [(4)-1:0] a;
    begin  pack = {b, __mimz_sub_1};  end     // reads a module-scope wire
endfunction
wire [7:0] __mimz_sub_1;
assign __mimz_sub_1 = (a);                    // the MODULE's `a`, not the argument
```

```text
iverilog  error: Unable to bind wire/reg/memory `__mimz_sub_1' in `tb.dut.pack'
          : A symbol with that name was declared here. Check for declaration after use.
```

Two defects in one emission: the wire is declared **after** the function that
references it (BUG-45's ordering class, in a new place), and it computes over
the module's `a` while the call passes
`c` — so even correctly ordered it would be the wrong value.

**Severity.** HIGH — Icarus refuses it loudly today. It becomes a silent
wrong-value bug the moment the ordering half is fixed on its own.

**Fix shape.** Falls out of BUG-62's fix _(a)_: with a real `fn`-scope `decls`
the name resolves to the parameter and the hoist is either correct or not
attempted. Until then `render_fn_decl` must not share `hoisted_decls` with the
enclosing module.

**Category** (round-4 taxonomy): _position not analysed at all_ — nobody has
asked what a hoist means inside a `function automatic`.

## BUG-64 (HIGH, OPEN) — every combinational emitted testbench checks before its own stimulus lands; 3 of 6 shipped examples report FAIL on a correct design

**Status:** OPEN at `1bd8b81`. Filed 2026-08-15 by round 6
([`review-2026-08-15.md`](review-2026-08-15.md)). Independent of BUG-62.

**What.** `mimz compile --emit-testbench` on a **combinational** design emits a
testbench whose every `expect` reads the value the design had **before** the
test's own stimulus:

```console
$ mimz test examples/english/shift.mimz
1 passed, 0 failed
$ iverilog -g2005 -o shift.vvp shift.v shift_tb.v && vvp shift.vvp
FAIL: expect (var_shift == 12) failed
```

Swept every shipped example with `test` blocks — emitted, elaborated, ran, and
compared verdicts with `mimz test`:

| example         | shape         | `mimz test` | emitted testbench |
| --------------- | ------------- | ----------- | ----------------- |
| `blinker`       | clocked       | PASS        | PASS              |
| `traffic_light` | clocked       | PASS        | PASS              |
| `vilakku`       | clocked       | PASS        | PASS              |
| `enum_encoding` | combinational | PASS        | **FAIL**          |
| `shift`         | combinational | PASS        | **FAIL**          |
| `tested_adder`  | combinational | PASS        | **FAIL**          |

**Cause.** BUG-51's fix made every `TestStmt::Drive` non-blocking (`emit_verilog/testbench.rs:64`),
which is right for a clocked test because `tick(clk)` renders
`repeat (N) @(posedge clk);` and time advances before the `expect`. A
combinational test has no `tick`, nothing advances time, and the `expect`
executes in the same time step as the drive — so the non-blocking update has
not landed. `a = 0; a <= 5; if ((y == 5) !== 1'b1) …` reads `y == 0`.

**It is not always loud.** A vacuous PASS is equally reachable:

```mimz
test "…" for Fuzz { a = 0b1111  expect &extend(y, 8) == 0 }
```

passes in the emitted testbench while `y` is still `0` from its initialiser —
the check never observed the stimulus. That is BUG-54's false-green class,
reintroduced by a different mechanism one round after it was closed.

**How found.** Round-6 review, checking whether the testbench emitter shares
the module emitter's `decls` (it does not — BUG-62 ⑨⑩); the race turned up in
the same experiment.

**Why the suite missed it.** `every_emitted_testbench_passes_iverilog`
(`tests/icarus.rs:409`) asserts only that the emitted testbench **elaborates**
(`iverilog -t null`). The one verdict-level test,
`emitted_testbench_reset_deassert_does_not_race_the_dut`, uses a **clocked**
design — the one shape that works.

**Severity.** HIGH — loud, but it makes the project's own headline claim ("two
independent implementations agree") false for combinational designs, and the
vacuous-PASS variant is silent.

**Fix shape.** Emit a `#1;` after the drive block and before the first `Expect`
when the test declares no clock — or equivalently keep blocking `=` for a test
with no `tick`, since BUG-51's race requires a clock edge to exist. Then
promote the sweep above into the suite: run each emitted testbench and assert
`PASS`, not merely that it elaborates.

**Category** (round-4 taxonomy): _a fix that doesn't recurse into a sibling
position_ — BUG-51's `=`→`<=` applied to every drive, correct only where a
`tick` follows.
