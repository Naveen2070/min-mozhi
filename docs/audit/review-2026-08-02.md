### 🔴 F-1 (CRITICAL) — Silent miscompile: `extend()` / `abs()` in Verilog self-determined positions

**Filed as [BUG-28](bugs.md) (`extend`) and [BUG-29](bugs.md) (`abs`).**

Simulator passes, synthesized hardware is wrong. No diagnostic. Three
independent reproductions verified against real `iverilog`/`vvp`.

#### Repro A — `extend` in a concat

```mimz
module CC { in a: bits[4]  in b: bits[4]  out y: bits[12]
  y = { b, extend(a, 8) } }

test "concat with extend" for CC { a = 0b1111  b = 0b1010
  expect y == 0b1010_0000_1111 }
```

```text
mimz test  → ok (1 passed)
emitted    → assign y = {b, (a)};
iverilog   → y = 000010101111     ✗  (expected 101000001111)
```

#### Repro B — `extend` in a replication

```mimz
module R { in a: bits[2]  out y: bits[8]
  y = {2{ extend(a, 4) }} }

test "rep" for R { a = 0b11  expect y == 0b0011_0011 }
```

```text
mimz test  → ok (1 passed)
emitted    → assign y = {2{(a)}};
iverilog   → y = 00001111         ✗  (expected 00110011)
```

#### Repro C — `abs` in a concat

```mimz
module Q { in a: signed[4]  in b: bits[4]  out y: bits[9]
  y = { b, unsigned(abs(a)) } }

test "abs concat" for Q { a = -8  b = 0b1010
  expect y == 0b1010_01000 }
```

```text
mimz test  → ok (1 passed)
emitted    → assign y = {b, $unsigned(((a < 0) ? (-a) : (a)))};
iverilog   → y = 010101000        ✗  (expected 101001000)
```

#### Why it matters

This is the worst failure mode an HDL compiler has: the design verifies green in
simulation and is wrong in silicon. It survives `mimz check`, survives
`mimz test`, survives the Icarus example suite, and survives the random-program
differential fuzzer.

It survives the fuzzer because that fuzzer's oracle is **simulator vs. Verilog on
generated programs**, and its generator is documented as checker-clean _"by
construction — every combine step unifies operand widths via `extend()`"_
(`tests/differential_fuzz.rs:8`), which keeps every `extend` in a
**context-determined** position. The broken case only appears in a
**self-determined** position, which the generator never produces. See
[GAP-5](gaps.md) for the oracle gap this exposes.

#### Root cause (single site)

`crates/mimz-core/src/emit_verilog/self_determined.rs:22`.
`verilog_self_determined_kind` models Verilog's self-determined width for
`ExprKind::Binary` and for `$signed`/`$unsigned`, then falls through:

```rust
_ => None,     // "no Verilog-specific rule differs from mimz's own here"
```

`Builtin::Extend` and `Builtin::Abs` land in that arm. Both **do** differ:

- `extend(x, N)` is emitted as the bare `(x)` — it relies entirely on the
  enclosing assignment's context width to zero/sign-extend. A concat member or
  replication body has no such context, so the padding bits are never
  materialized and every field to the left shifts down.
- `abs(x)` renders to a ternary, which Verilog self-determines at
  `max(operand widths)` — not at mimz's grown `N+1` result.

The hoisting machinery that fixes this **already exists** (`hoist_if_needed`,
`__mimz_sub_N` in `emit_verilog/module/ports.rs:266`) and works correctly for
binary operators. Verified:

```text
y = { b, a + b }   →   wire [4:0] __mimz_sub_1;
                       assign __mimz_sub_1 = (a + b);
                       assign y = {b, __mimz_sub_1};        ✓ matches iverilog
```

`if`/`match` branches are also correctly hoisted. **BUG-19's fix was landed for
operators and never extended to the builtin table.**

#### Recommended fix

Make the match exhaustive so a new builtin cannot silently inherit `None`:

```rust
// crates/mimz-core/src/emit_verilog/self_determined.rs
ExprKind::Call { func, args } => match func {
    // `extend(x, N)` renders as bare `(x)` — Verilog gives it the
    // ARGUMENT's width in a self-determined position, never N. Report
    // that so the caller sees the mismatch against mimz's Kind{N} and
    // hoists to `wire [N-1:0] __mimz_sub_k`.
    Builtin::Extend => Some(Kind {
        width: self_determined_operand_width(&args[0], decls),
        signed: infer_kind(expr, decls).signed,
    }),
    // Renders to a ternary: Verilog sizes it at max(operand widths),
    // not mimz's grown N+1 result.
    Builtin::Abs => Some(Kind {
        width: self_determined_operand_width(&args[0], decls),
        signed: infer_kind(expr, decls).signed,
    }),
    // `trunc` renders as an explicit part-select `x[N-1:0]` — already
    // exactly N bits in Verilog. Min/Max render to a ternary whose
    // operands are same-width by the checker's own rule, so max() == N.
    // Reductions are 1-bit on both sides. No mismatch possible.
    Builtin::Trunc | Builtin::Min | Builtin::Max
    | Builtin::Nand | Builtin::Nor | Builtin::Xnor => None,
    Builtin::SignedCast | Builtin::UnsignedCast =>
        verilog_self_determined_kind(&args[0], decls),
    Builtin::Clog2 => None,  // const-folded before emit
    Builtin::SyncDoubleFlop | Builtin::SyncPulse => None, // lowered to items
},
```

`Min`/`Max` were empirically confirmed correct-as-is during this review
(`y = { b, min(a, b) }` matches Icarus exactly); they are listed explicitly
rather than left to a wildcard so the reasoning is recorded at the site.

#### Test gap to close in the same commit

Add to `tests/self_determined_regression.rs` a case per `Builtin` variant ×
each of the five self-determined positions (concat member, replication body,
replication count, comparison operand, `$signed`/`$unsigned` argument), driven
off the `Builtin` enum so a newly added builtin fails the build until it is
classified. See [GAP-5](gaps.md).

### 🟠 F-2 (HIGH) — The static type does not bound the value it describes; naming an intermediate changes the result

**Filed as [BUG-30](bugs.md).**

```mimz
module Ref { in din: bits[4]
  out direct: bits[8]   out named: bits[8]
  wire w: bits[4] = din << 2
  direct = extend(din << 2, 8)
  named  = extend(w, 8) }
```

```text
mimz test  → FAIL: direct = 60, named = 12
iverilog   → direct = 60, named = 12      (simulator and hardware agree)
```

Both `din << 2` and `w` are typed **`bits[4]`**. One yields 60 (needs 6 bits),
the other 12. The simulator and the emitted Verilog agree with each other; both
disagree with the declared type.

This is BUG-11's residue. That fix threaded a real context width through
`Shl`/`Shr` so the simulator matches Verilog — correct as far as it goes, and
`bugs.md` BUG-11 is candid about it — but it left the checker's `shift_ty`
asserting a width the value provably exceeds. `width_rules.rs:64` documents the
split as intentional: _"a STATIC type-system invariant, not a claim about the
runtime value."_

#### Why it matters

`spec/01` sells "safe by default" and `spec/02 §1.1` sells _"the type system
catches the classic dropped-carry bug."_ A width type that does not bound the
value is not a safety property — it is a naming convention.

It also **breaks referential transparency**: extracting a subexpression into a
named wire silently changes behavior. That is exactly the Verilog wart the
language exists to remove, and it is the single hardest thing to explain to a
beginner ("why did giving it a name change the answer?").

#### Recommendation — pick one; do not leave it split

- **(a) Self-determined shifts, enforced.** `bits[W] << k` is `bits[W]`, and the
  emitter hoists every shift into a `wire [W-1:0]` before use. Predictable,
  teachable, and the declared type matches the value everywhere. Cost:
  `extend(din << 2, 8)` now yields 12, so widening requires
  `extend(din, 8) << 2` — which is _more honest_, and the checker can suggest
  exactly that rewrite in the diagnostic.
- **(b) Growing shifts.** `bits[W] << const k` is `bits[W+k]`; reject
  non-constant shift amounts in a widening position, or grow by
  `2^width(amount) - 1`. Matches the value; costs bits on dynamic shifts.

**(a) is recommended** for a teaching language, and it is the smaller diff — the
hoisting machinery is the same machinery F-1 needs.

### 🟠 F-3 (HIGH, architectural) — No IR; width/kind semantics implemented three times

**Filed as [GAP-1](gaps.md).**

The pipeline is `lex → parse → AST → (AST→AST lowerings) → check → emit-text`.
There is no intermediate representation, no netlist, no elaborated graph, and no
optimization pass.

| Consumer  | Type model                             | Location                                     |
| --------- | -------------------------------------- | -------------------------------------------- |
| Checker   | `Ty<'a>`                               | `crates/mimz-core/src/checker/widths/`       |
| Emitter   | `Kind` via `infer_kind`                | `crates/mimz-core/src/emit_verilog/kinds.rs` |
| Simulator | `Val { bits, width, signed, unknown }` | `crates/mimz-sim/src/sim/value/`             |

`kinds.rs:6` states the duplication is deliberate — because `foreach`/`sync_loop`
lowering produces **fresh `Expr` trees** at ~6 call sites, so an annotation set
by one pass cannot reach another. That constraint is real, and the chosen
workaround (recompute from AST, share the rules via `width_rules.rs`) is a
reasonable local fix. But it treats the symptom.

**Evidence this is the structural cause.** BUG-11, 18, 19, 20, 21, 22, 23, 24 in
[`bugs.md`](bugs.md) are all _"two implementations of one width rule
disagreed."_ So are F-1 and F-2. And `width_rules.rs:14` admits the unification
is partial:

> Deliberately narrow: only `shift_result`/`slice_result` so far … the
> `same_width`/`lossless`/`concat` families remain in `checker/widths/ops.rs`,
> unconverted.

Every future operator or builtin re-opens the same three-way drift surface.

#### Recommendation

Introduce a minimal **typed elaborated IR** between check and emit. This is the
single highest-leverage change available to the project.

```rust
// One node, one resolved type, one owner. Names are interned ids, not Strings.
pub struct Net { pub id: NetId, pub kind: Kind, pub clock: Option<ClockId>, pub span: Span }

pub enum Op {
    Const(Bits),
    Ref(NetId),
    Bin(BinOp, NetId, NetId),
    Mux(NetId, NetId, NetId),
    Slice(NetId, u32, u32),
    Concat(Vec<NetId>),
    Ext { src: NetId, to: u32, signed: bool },
    Reg { d: NetId, clk: ClockId, rst: Option<(NetId, Bits)>, edge: Edge },
    // …
}
```

Run `foreach` / `sync_loop` / `bundle` lowering **into** the IR, have the checker
annotate it, and have both the emitter and the simulator consume the _same_ IR.
Width is then computed exactly once, by construction. `Ext` becomes an explicit
node the emitter **must** materialize, which makes F-1 structurally impossible
rather than a case-table entry.

Also unlocks: constant folding, dead-signal elimination, `--emit-netlist` for
debugging, per-module parallel emit, and any future non-Verilog backend — which
the Constitution's _"Verilog interop forever, even after native backends exist"_
clause already presumes.

### 🟡 F-4 (MEDIUM) — Simulator is 2-state with a whole-value unknown flag; no X/Z, no tri-state

**Filed as [GAP-2](gaps.md).**

`Val` (`crates/mimz-sim/src/sim/value/mod.rs:36`) carries `unknown: bool` — a
single flag for the entire vector, with `bits` documented as _"MEANINGLESS when
`unknown` is `true`."_ There is no per-bit X, no Z, and no `inout` (a `grep` over
`spec/` returns zero hits for `inout` / `tristate` / `'bz`).

**Impact:**

- `{1'b0, x_value}` cannot be modeled — the known half is lost.
- Uninitialized-register detection (the number-one real-world use of X in RTL
  simulation) is impossible.
- Bidirectional buses, open-drain I²C, external memory DQ pins — all
  unrepresentable. This blocks most board-level IoT work, which the README lists
  as a target domain.
- X-optimism / X-pessimism mismatches against the emitted Verilog are
  undetectable, so an entire class of sim-vs-synthesis divergence has no oracle.

#### Recommendation

Move to a two-plane representation:

```rust
pub struct Val { pub val: Bits, pub mask: Bits, pub width: u32, pub signed: bool }
// mask bit set = that bit is unknown
```

This is the standard encoding (Verilator, CXXRTL). It costs one extra `Bits` per
value and turns every operator's X-propagation into a bitwise rule rather than a
special case. Ship `inout` / tri-state **after**, as a separate design — it needs
resolution-function semantics that directly contradict the current single-driver
rule (E0501).

### 🟡 F-5 (MEDIUM) — `mem` lowers to an `initial` block: FPGA-only, not ASIC-synthesizable, and unresettable

**Filed as [BUG-32](bugs.md).**

`examples/english/regfile.mimz` emits:

```verilog
reg [(8)-1:0] m [0:(4)-1];
integer __mimz_m_i;
initial for (__mimz_m_i = 0; __mimz_m_i < (4); __mimz_m_i = __mimz_m_i + 1) m[__mimz_m_i] = 0;
```

`initial` is inferred by Vivado/Quartus into BRAM init contents. It is **ignored
by every ASIC synthesis flow** (Genus, Design Compiler) — the array powers up
undefined, and the language's stated "no uninitialized state" guarantee silently
evaporates. The example's own comment — _"there is no reset line because a memory
initializes itself"_ — is true on FPGA and false on ASIC.

Also missing: no way to express a memory reset, no memory-style attribute
(`(* ram_style = "block" *)` / `ramstyle`), no init-from-file (`$readmemh`), and
no explicit dual-port or read-during-write policy. The inference outcome is
therefore entirely at the vendor's discretion and unspecifiable from source.

#### Recommendation

1. Emit a synthesis-flow note in the generated header comment when any `mem` is
   present, and document the ASIC caveat in `docs/guide/`.
2. Add an optional memory-attribute syntax that lowers to the vendor pragma.
3. Long-term: model memories as an IR node ([GAP-1](gaps.md)) with an explicit
   read-during-write policy, so the emitter picks a correct template per target
   instead of hoping the vendor infers one.

### 🟡 F-6 (MEDIUM) — Parser violates the project's own mandatory-help contract

**Filed as [GAP-3](gaps.md).**

`Checker::err` (`crates/mimz-core/src/checker/mod.rs:109`) takes `help` as a
**required** parameter — _"the teaching contract (spec/01 G1) is not optional."_
The parser's `Parser::error` (`crates/mimz-core/src/parser/mod.rs:164`) takes no
help at all; `self.help()` is a separate opt-in call.

Counted across `crates/mimz-core/src/parser/`:

| File                     | `self.error(` | `self.help(` |
| ------------------------ | ------------- | ------------ |
| `expr.rs`                | 13            | 4            |
| `mod.rs`                 | 5             | 1            |
| `items/mod.rs`           | 6             | 2            |
| `items/module.rs`        | 8             | 3            |
| `items/seq.rs`           | 6             | 3            |
| `items/file.rs`          | 5             | 1            |
| `items/test.rs`          | 8             | 0            |
| `items/func.rs`          | 4             | 0            |
| `items/extern_module.rs` | 4             | 0            |
| `items/bundle.rs`        | 1             | 0            |
| `items/inst.rs`          | 0             | 0            |
| **Total**                | **60**        | **14**       |

Roughly **77% of syntax errors ship with no `= help:` line.** Observed:

```text
error[E1101]: expected a value here, found `}`
  --> p.mimz:1:56
   |
  1 | fn f(x: bits[4]) -> bits[8] { return extend({x, x}, 8) }
   |                                                        ^
                                    ← no help; the real issue is that a `fn`
                                      needs a tail expression, not just `return`
```

A beginner cannot recover from that. Syntax errors are the **first** errors a
learner hits — this is the highest-traffic diagnostic surface in the compiler and
it is the least covered.

#### Recommendation

Change the signature so the decision cannot be skipped, mirroring the checker:

```rust
fn error(&mut self, span: Span, code: &'static str,
         msg: impl Into<String>, help: impl Into<String>)
```

Then fill in all 60 sites. Add a test asserting every `E11xx` fixture renders a
`= help:` line, the same way `tests/errors.rs` already guards the `E0xxx`
catalog.

### 🟡 F-7 (MEDIUM) — `E0403` emits an unrelated help line for enum-as-data

**Filed as [BUG-31](bugs.md).**

```text
error[E0403]: enum `S` is not data
  --> p.mimz:9:12
   |
  9 |   y = { a, s }
   |            ^
   = help: clocks and resets only appear in `on rise(clk)` and module connections
           — they never enter expressions (spec/02 section 1.2)
```

`Checker::not_data` (`crates/mimz-core/src/checker/widths/mod.rs:429`) is
documented as the _"clocks/resets are not data"_ helper but is reached for enum
values too. `mimz explain E0403` gives the correct three-case text; the inline
help does not — and the inline line is what users actually read.

**Fix:** branch the help on the `Ty` variant.

- Enum → _"an enum is a symbolic state, not a number; match on it, or add an
  explicit encoding."_
- Clock/reset → existing text.

**Related expressiveness gap** ([GAP-7](gaps.md)): there is **no way to obtain an
enum's bit encoding**. The emitter already assigns
`localparam [1:0] STATE_RED = 0;`, so the encoding exists and is stable — it is
simply unreachable from source. Debug ports, state-trace outputs, and one-hot
exports all need it. Recommend `unsigned(enumval)` or an explicit `encoding(e)`
builtin.

### 🟡 F-8 (MEDIUM) — `panic!` in the emitter's kind inference

**Filed as [SEC-10](security.md).**

```rust
// crates/mimz-core/src/emit_verilog/kinds.rs:52
ExprKind::Ident(name) => *decls.get(name)
    .unwrap_or_else(|| panic!("emit_verilog::kinds::infer_kind: `{name}` not in decls")),
```

A compiler crash — aborting process, no diagnostic, no span — if `build_decls`
ever misses a name form. It is currently guarded by a `kind_is_inferrable`
pre-check at the call sites: an invariant enforced by **convention across
files**, not by types.

Not reachable today. Roughly 20 targeted probes (module parameters, file consts,
enum values, `fn` parameters, bundle fields, `foreach` variables) were all
correctly rejected or handled by an earlier pass. So this is **latent, not
live** — but every new expression form re-tests the invariant by hand.

**Fix:** return `Option<Kind>` and treat `None` as _"cannot analyze → hoist
conservatively."_ The conservative branch is safe by construction (an extra
`__mimz_sub_N` wire is always correct), so there is no reason to keep a panic
here. This also removes the need for `kind_is_inferrable` to stay in sync at
every call site.

`#![forbid(unsafe_code)]` on `mimz-core` is good and should be replicated to
`mimz-sim` and the shell crate ([HARD-7](hardening.md)) — but it does not cover
this class.

### 🟡 F-9 (MEDIUM) — Repo is currently red: absolute performance threshold in a test

**Filed as [BUG-33](bugs.md).**

```text
counter kernel: 641750 cycle-events/sec (best of 5, debug=false)

thread 'the_counter_kernel_clears_the_perf_baseline' panicked at tests\sim.rs:221:5:
counter kernel too slow: best 641750 cycle-events/sec < 1000000

test result: FAILED. 16 passed; 1 failed
```

A hardcoded absolute throughput floor will fail on any slower machine, any shared
CI runner under load, any laptop on battery, and every contributor's first
`cargo test`.

The project already made the right call elsewhere — CI runs `cargo bench --no-run`
with the comment _"microbench timings on shared runners are too noisy to gate
on."_ This test contradicts that reasoning.

**Secondary effect worth noting.** Because `cargo test` stops after the first
failing binary unless `--no-fail-fast` is passed, this one failure **masks 13
suites / 880 tests** locally:

```text
cargo test --workspace --release                  → 22 suites,  234 passed, 1 failed
cargo test --workspace --release --no-fail-fast   → 35 suites, 1114 passed, 1 failed
```

**Fix:** move it behind `#[ignore]` plus an explicit `--ignored` perf job, or
gate on `MIMZ_PERF_GATE=1`, and track the number as a trend in the existing
`bench-history.jsonl` instead of asserting a constant.

### 🔵 F-10 (LOW→MEDIUM, scaling) — String-keyed name resolution throughout

**Filed as [GAP-4](gaps.md).**

`ExprKind::Ident(String)`, `HashMap<String, …>` symbol tables,
`HashMap<(usize, String), Rc<Scope>>` scopes, and ~203 `.clone()` calls in
non-test `mimz-core`. Every one of the nine checker passes re-resolves each name
by string hash; the emitter and the simulator then do it again.

**Measured, this is not currently a problem.** Release build, this machine:

| Design                    | `mimz check` | `mimz compile` |
| ------------------------- | ------------ | -------------- |
| 4,008 lines / 2,000 regs  | 0.77 s       | 1.67 s         |
| 16,008 lines / 8,000 regs | 1.65 s       | —              |

Scaling is roughly linear (4× input → 2.1× wall, startup-dominated). No quadratic
blow-up in name resolution, driver analysis, or the combinational-cycle DAG
check — better than a `HashMap<String, _>` design would suggest.

But there is no interning, no `SymbolId`, no arena, and only
`QualIdent.resolved_file` caches anything. The ceiling arrives with real designs
(a soft CPU plus peripherals is 50–200k lines of generated RTL) and it arrives as
a wall, not a slope.

**Recommendation.** Bundle this with [GAP-1](gaps.md): intern identifiers to
`Symbol(u32)` during parse, key everything on the id, and give `Ident` a
`Cell<Option<DefId>>` resolved once. Expect 3–10× on the checker and a large drop
in allocator pressure. **Do not do it as a standalone refactor** — do it as part
of the IR, or the churn is paid twice.

## Part 2 — Assessment by area

### 2.1 Language design — 7.5 / 10

#### Strong, defensible calls

- **Lossless arithmetic by default** (`bits[W] + bits[W] → bits[W+1]`; wrapping
  requires an explicit `+%`). This is the single best decision in the language.
  Verilog silently drops carries; SystemVerilog silently drops carries; Chisel
  requires `+&` to _opt in_ to growth. Min-Mozhi makes the safe case the default
  and the dangerous case visible — and the diagnostic teaches the distinction at
  the point of failure.
- **Mandatory reset values on `reg`.** No uninitialized state (modulo F-5).
- **`=` for combinational, `<-` for sequential, enforced.** Kills the
  blocking/non-blocking class of bug outright — the most common beginner error in
  Verilog.
- **`if` is an expression with a mandatory `else`; `match` must be exhaustive.**
  Latch inference is structurally impossible. Confirmed in the emitted code: all
  combinational logic is continuous `assign`, never `always @*`. This is correct
  and it is not what most HDLs do.
- **Clock and reset are declarations, not `bit` inputs** — which is what makes
  the CDC check below possible at all.

#### The standout feature — clock-domain crossing as a type rule

```text
error[E0701]: `a` belongs to clock `c1`, but this block runs on `c2`
   |   on rise(c2) { b <- a }
   |                      ^
   = help: reading across clock domains causes metastability — cross it explicitly
           with `sync.double_flop`/`sync.pulse`, or move this logic into the
           owning clock's `on` block
```

Verilog and SystemVerilog cannot do this. Chisel/SpinalHDL have clock domains but
weaker enforcement. Spade and Clash do not check it. Static CDC checking is
otherwise a separate five-figure tool (Spyglass CDC, Questa CDC) run late in the
flow.

Having it in the compiler, for free, with a teaching message, is a genuine
contribution and is the strongest single argument for this project's existence.
**It should be the headline of any release announcement.**

Min-Mozhi's real peer is **Spade**, not Chisel — a standalone safe HDL rather
than an embedded DSL. Against Spade it wins on CDC and diagnostics and loses on
type-system depth. The trilingual axis is genuinely unoccupied.

#### On the trilingual design specifically

Executed better than expected. The word-order profile (`syntax thamizh`, SOV
clause heads) is consumed at the parser and **never reaches the AST**
(`parser/mod.rs:6`), so a Tamil-order file and its English twin emit
byte-identical Verilog. That is the right architecture — a front-end skin, not a
fork.

NFC normalization at the lexer boundary, a Tamil→ASCII transliteration pre-pass
before emit with a reserved-word table, and a round-trippable `NameMap` for
`translate --romanize` are all correct choices. The localized error catalog
carries `{token}` interpolation args **structurally** on `Diag.args` rather than
string-formatting them, which is the right call for translation quality.

This is not a marketing veneer; it is real engineering and it is the project's
defensible moat.

### 2.2 Compiler architecture — 6 / 10

#### Good

- Clean three-crate split: `mimz-core` (pure, no fs, no optional deps) →
  `mimz-sim` → shell crate (fs, CLI, LSP, hw-emulation). The purity boundary is
  **enforced by the WASM build** (`default-features = false` must compile for
  `wasm32`), which is a far stronger guarantee than a convention.
- Feature gating is disciplined; each `optional = true` carries a comment
  explaining _why_ it cannot build on `wasm32`.
- Nine named checker passes with an explicit ordered pipeline and a documented
  rationale per pass (`checker/mod.rs:36`).
- **Dual parser entry points** — strict `parse` (any error discards the tree, so
  codegen never sees an `Error` node) and `parse_recover` (best-effort with
  `Error` placeholders for the LSP). That separation is exactly right and most
  compilers get it wrong.
- Depth guard is well done: `MAX_DEPTH = 64` with E1113, and the comment does the
  arithmetic (_"~12 Rust frames per source nesting level, 1 MB default Windows
  stack"_). That is the right way to pick a constant.

#### Weak

- **No IR** (F-3) — this is the rating ceiling.
- **No optimization passes at all.** The emitter is documented as "deliberately
  dumb," a fine v1 stance, but it means constant folding, CSE, and dead-signal
  elimination all fall to the downstream synthesizer, and `--emit-netlist`-style
  debugging is impossible.
- **No symbol interning** (F-10).
- **Type info computed three times** (F-3).
- **Error recovery is `sync_to_newline` only** — no brace-level or item-level
  recovery, so one unbalanced `{` cascades.

### 2.3 Rust code quality — 8 / 10

Best-rated area.

- `#![forbid(unsafe_code)]` on `mimz-core`.
- `overflow-checks = true` in the release profile, with correct domain reasoning:
  _"turns any overflow we missed into a loud, debuggable abort rather than a
  silent miscompile of hardware."_
- `lto = true`.
- `Result`-based errors with `Vec<Diag>` accumulation; passes never print and
  never panic (F-8 excepted).
- Checked arithmetic in the evaluators.
- `Rc<Scope>` used precisely where a pass must hold a scope while reporting
  through `&mut self` — a considered choice, not a reflex.

**Comment quality is unusually high.** Nearly every non-obvious decision carries
its rationale and often the bug number that motivated it. `width_rules.rs`
explains _why_ it exists (BUG-21's drift) and is explicit about what it
deliberately does not yet cover. This is the documentation style that actually
survives contact with maintenance — keep it.

**Nits:** ~203 `.clone()` in non-test core (mostly `String` name cloning —
F-10); one `panic!` in a production path (F-8); `#![forbid(unsafe_code)]` not
replicated to `mimz-sim`/shell ([HARD-7](hardening.md));
`#[allow(clippy::too_many_arguments)]` on `err_args` suggests a `DiagBuilder`
would read better. None of these are structural.

### 2.4 HDL correctness — 5 / 10

Rated on **confirmed behavior**, not intent.

#### Correct (verified)

- Sequential lowering: `posedge`/`negedge`, synchronous and asynchronous reset
  with the right sensitivity list (`always @(posedge clk or posedge rst)`),
  non-blocking `<=` throughout.
- Single-driver enforcement (E0501).
- Combinational cycle detection with a readable path (`p -> q -> p`, E0504).
- Clock ownership and CDC (E0701).
- Signed handling: `wire signed`, `$signed`/`$unsigned` casts, `extend`
  sign-extending a signed operand.
- Reductions (`^a`, `~&a`), `trunc` as an explicit part-select.
- FSM lowering to `localparam` + ternary chain is clean and reads well.

#### Against that

- **F-1 is a confirmed silent miscompile** — that alone caps this score.
- **F-2** means the width type is not a value bound.
- **F-4** means no X semantics at all.
- **F-5** means memory init is FPGA-only while the docs imply it is universal.
- The emitter's parenthesization is heavy
  (`((op == 'b00)) ? ((a + b)) : …`) — safe, but it hurts the readability that is
  otherwise a stated goal and makes hand-verifying generated code harder than
  necessary.

### 2.5 Performance — 7 / 10

Measured on this machine, release build:

| Design                    | `check` | `compile` |
| ------------------------- | ------- | --------- |
| 4,008 lines / 2,000 regs  | 0.77 s  | 1.67 s    |
| 16,008 lines / 8,000 regs | 1.65 s  | —         |

Scaling is roughly linear (4× input → 2.1× wall, startup-dominated). No quadratic
blow-up in name resolution, driver analysis, or the combinational-cycle DAG
check. Simulator throughput: ~640k cycle-events/sec.

**Not present:** incremental compilation (the whole project is re-checked every
time), parallel compilation (single-threaded; per-module emit is embarrassingly
parallel and `rayon` would be a ~20-line change once [GAP-1](gaps.md) lands),
caching, and any optimization pass. For the target scale these are correctly
deferred.

Criterion micro-benchmarks + a separate `mimz-bench` harness +
`bench-history.jsonl` trend tracking is more perf infrastructure than most
projects this size have. The only problem is F-9 gating on an absolute number.

### 2.6 Error reporting — 8 / 10 (checker) · 4 / 10 (parser)

#### Checker diagnostics are genuinely rustc-grade

```text
error[E0401]: expected `bits[8]`, found `bits[9]`
  8 |   wire t: bits[8] = a + b
    |                     ^^^^^
    = help: `+`/`-` are lossless — the result grows one bit so the carry is never
            dropped. For same-width wrap-around use `+%`/`-%`; to keep the carry,
            widen the target by one bit (spec/02 section 1.2)
```

That teaches the language's central design decision at the moment the user needs
it. Also present:

- Multi-error reporting works (three distinct errors from one broken file,
  correctly ordered).
- Stable append-only E-code catalog (73 codes), guarded by `tests/errors.rs`
  against the human-readable catalog, with a required end-to-end fixture per code
  and coverage measured by `mimz-bench`.
- `mimz explain E0403` gives long-form prose; `--list` enumerates.
- `--json` wire format with byte spans and character columns for editors.
- Colorized output with a global toggle.
- Localized message catalog with structured interpolation args.

#### Against that

- **F-6** — 77% of parser errors have no help line.
- **F-7** — wrong help on E0403.
- **No suggested-edit / fix-it spans in the JSON output**, so an editor cannot
  offer a quick-fix even where the help text describes an exact mechanical change
  (`+` → `+%` is the obvious first one). Adding a `fix: { span, replacement }`
  field to `JsonDiag` would be cheap and high-visibility
  ([GAP-9](gaps.md)).

### 2.7 Testing strategy — 8 / 10

Strong and unusually well-considered for the project's size:

- **1114 tests across 35 suites** (unit + integration), organized by topic rather
  than by file-of-origin.
- **Icarus differential in two layers** — every emitted module must elaborate
  under `iverilog -t null`, _plus_ a hand-written self-checking testbench per base
  example encoding the documented semantics, run under `vvp`. Two independent
  interpretations compared.
- **`REQUIRE_IVERILOG=1` in CI** so a missing install is a hard failure — the
  differential can never silently skip. Exactly the right instinct.
- **Random-program differential fuzzer** (`tests/differential_fuzz.rs`, 1003
  lines) generating checker-clean designs across unsigned/signed/clocked scope,
  run through the full pipeline into Icarus.
- **4 libFuzzer targets** including `pretty_roundtrip` and `translate_roundtrip`
  (round-trip _properties_, not just crash-freedom), plus a weekly extended fuzz
  cron.
- **`tests/docs_sync.rs` and `tests/grammar_sync.rs`** — the docs and the grammar
  are tested against the code. Very few projects do this.
- **`tests/wasm_parity.rs`** guards the playground against the native pipeline.
- 175 examples across 5 keyword flavors, all compiled and Icarus-checked.

#### The gap that let F-1 through

Precise and worth naming. Every oracle here compares **simulator vs. Verilog**.
There is **no oracle asserting declared type vs. produced value**.

- F-1 passes the simulator, fails the hardware — and the fuzzer's generator never
  places `extend`/`abs` in a self-determined position because it uses `extend()`
  for width normalization in context-determined position _by construction_.
- F-2 fails neither oracle, because the simulator and Verilog agree with each
  other and both disagree with the type.

#### Two additions, in priority order

1. **Width-conformance property.** After every simulator evaluation, assert the
   produced `Val` fits the checker's declared width for that expression. Wire it
   into the existing fuzzer — it needs no new generator, only a new assertion,
   and it catches the entire F-2 class.
2. **Position-aware generation.** Extend the fuzzer to place every `Builtin` and
   every operator into each of the five self-determined positions {concat member,
   replication body, replication count, comparison operand, `$signed` argument}.
   Drive the matrix off the `Builtin` enum so a new builtin fails until covered.
   This catches the entire F-1 class.

Both are filed as [GAP-5](gaps.md).

Also missing: no coverage measurement (`cargo llvm-cov`) in CI, so untested paths
are invisible; and no fuzz target for the **checker** or the **emitter** — the
current four cover lex/parse/eval and the two round-trips, so the passes where
F-1 lives are unfuzzed ([GAP-10](gaps.md)).

## Part 5 — Roadmap

### v0.2 — "Correct" (next release)

Priorities 1–7. Nothing new in the language except `assert`/`cover` and the
enum→bits cast.

The release note should be able to say the compiler produces Verilog that matches
its own type system — and prove it with the position-matrix test.

### v0.3 — "Structured"

The typed elaborated IR (priority 8). Move `foreach` / `sync_loop` / `bundle`
lowering into it, intern symbols, retire the three parallel type models, add
`--emit-netlist`. Constant folding and dead-signal elimination fall out nearly
free.

This is the release that determines whether the project can keep growing or
starts fighting itself.

### v0.4 — "Real hardware"

X/Z two-plane values (priority 9), `inout` / tri-state with resolution semantics,
synthesis attributes with a vendor-mapping table, memory read-during-write policy
and `$readmemh` init.

This is the release that makes FPGA projects beyond blinkers practical.

### v0.5 — "Expressive"

`fn` parameterization by module scope (BUG-12 — the biggest daily tax),
parameterized types / generic modules, a `pipeline`/`stage` construct, and an
interface/handshake abstraction layered over `bundle`.

Consider a `spec/` RFC process before this milestone; these are the changes that
are hard to take back.

### v1.0 — "Trustworthy"

LSP feature-complete (references, rename, code actions driven by fix-it spans in
`JsonDiag`), incremental and parallel compilation, formal-verification hooks (SVA
emission or a SymbiYosys bridge), an edition-stability commitment, and a
conformance suite a third party could run against an independent implementation.

### Strategic note

The two things nobody else has are **static CDC checking in the compiler** and
**first-class non-English keyword flavors over one grammar**. Both are
implemented well.

Everything in this review is in service of making the rest of the compiler
trustworthy enough that those two features get taken seriously — a novel safety
check is worth nothing if the code generator quietly drops bits.

**Fix F-1, then lead with CDC.**
