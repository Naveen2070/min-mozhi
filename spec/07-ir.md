# Min-Mozhi - Intermediate Representation (IR)

> **Spec v0.3 - IR v1 (2026-10-02).** Describes the netlist the compiler builds
> between checking a program and generating hardware from it. The machine source
> of truth is [`crates/mimz-core/src/ir/`](../crates/mimz-core/src/ir/mod.rs);
> this document states the contract that code implements. Phase 2 exit
> criterion #1 (`docs/plan/phase-2-ir-synthesis.md`).

The IR is **not part of the language**. A program's meaning is defined by
[spec/02](02-syntax-and-grammar.md); the IR is how the compiler represents a
checked, elaborated program so that optimizer passes and the synthesis backend
work on one typed netlist instead of re-deriving widths from the AST. Changing
the IR never changes what a valid program means.

---

## 1. Where the IR sits

```text
.mimz -> lex -> parse -> check -> elaborate -> ir::lower -> ir::validate
                                                   -> ir::opt::optimize -> ir::validate -> backend
```

- **Input:** one `elaborate::Design` - a single module with every parameter
  folded, every instance flattened, every `repeat`/`foreach` unrolled and every
  `fn` call inlined.
- **Output:** one `ir::Module`. The IR has **no hierarchy**: a design lowers to
  exactly one module. Only `extern module` instances stay opaque
  (`BlackBox`, section 3.5).
- Every IR module the backend sees has passed `ir::validate` both before and
  after optimization (section 5). A module that fails validation is a compiler
  bug, never a user error.

## 2. Nets and bit-vectors

- A **net** (`NetId`) is one bit. Nets are numbered densely from 0.
- A **pin connection** (`Bits`) is an ordered list of nets, **index 0 = LSB**,
  plus a `signed` flag: whether the value on those nets is read as two's
  complement. The flag is set once, at construction, by the same rule the
  checker uses for `signed[N]` vs `bits[N]` (spec/02 types).
- A net may carry a **source name** (the `.mimz` wire, port or register it came
  from) or none (a value the lowering pass made up).
- **Ports** are an ordered list of `(name, Bits, direction)`. An input port
  drives its nets; an output port's nets must be driven by a cell.

## 3. Cells

A cell is an operation with named pins, a kind (33 as of v0.2), and the source span
it came from. Pins named `out`, `q` and `rdata` are outputs; every other pin is an
input. The widths below are **required** - `ir::validate` rejects a cell that
breaks them.

### 3.1 Arithmetic

| Kind                            | Pins            | `out` width                 | Meaning                       |
| ------------------------------- | --------------- | --------------------------- | ----------------------------- |
| `Add`, `Sub`                    | `a`, `b`, `out` | `max(a, b) + 1`             | lossless (spec/02 `+`, `-`)   |
| `Mul`                           | `a`, `b`, `out` | `a + b`                     | lossless (spec/02 `*`)        |
| `AddWrap`, `SubWrap`, `MulWrap` | `a`, `b`, `out` | `max(a, b)`                 | wrapping (`+%`, `-%`, `*%`)   |
| `Neg`                           | `a`, `out`      | `a + 1` if signed, else `a` | two's-complement negate       |
| `Shl`                           | `a`, `b`, `out` | see below                   | left shift, result grows      |
| `Shr`                           | `a`, `b`, `out` | `a`                         | logical right shift (see 3.6) |

`Shl`'s `out` is `a + k` when `b` is driven entirely by one `Const` cell of
value `k`, and worst-case growth otherwise - the same rule as
`width_rules::shift_result`. A shift whose worst-case growth is too wide to
represent is rejected (`ShiftGrowthTooWide`).

Signed arithmetic reads each operand's own `Bits::signed` flag.

### 3.2 Bitwise, reduction, logical

| Kind                  | Pins            | Rule                                  |
| --------------------- | --------------- | ------------------------------------- |
| `And`, `Or`, `Xor`    | `a`, `b`, `out` | `a` and `b` the same width            |
| `Not`                 | `a`, `out`      | bitwise invert                        |
| `RedAnd/RedOr/RedXor` | `a`, `out`      | `out` is 1 bit                        |
| `LogicAnd`, `LogicOr` | `a`, `b`, `out` | `a` and `b` the same width; 1-bit out |
| `LogicNot`            | `a`, `out`      | 1-bit out                             |

### 3.3 Comparison

`Eq`, `Ne`, `Lt`, `Le`, `Gt`, `Ge` take `a`, `b` (same width) and a 1-bit
`out`. Equality ignores sign. The four ordering comparisons carry a `signed`
flag in the cell kind itself, because the same bit pattern orders differently
under two's complement.

### 3.4 Wiring and selection

| Kind               | Pins                   | Rule                                              |
| ------------------ | ---------------------- | ------------------------------------------------- |
| `Mux`              | `sel`, `a`, `b`, `out` | `sel` 1 bit; `a`, `b`, `out` the same width       |
| `Concat`           | parts, `out`           | `out` is the input pins' nets, in pin-name order  |
| `Slice { lo, hi }` | `a`, `out`             | `out` is bits `lo` to `hi` of `a`, both inclusive |
| `Const { value }`  | `out`                  | no inputs; `out` holds `value` at its width       |

`Mux` picks `a` when `sel` is 1 and `b` when `sel` is 0. Constants are ordinary
cells so that "every net has a driver" needs no special case.

`ir::lower` never emits `Concat` or `Slice`: source concatenation, replication
and slicing just reorder existing nets into a new `Bits`, with no cell. The two
kinds exist for hand-written IR and are handled by every pass and printer.

### 3.5 State and black boxes

- **`Dff { clock, edge }`** - pins `d`, `q` (same width). On the given edge
  (`Rise` or `Fall`) of the `clock` net, `q` takes `d`. Power-on value is 0.
- **`Adff { clock, edge, value }`** - a register with an asynchronous
  active-high reset. Pins `d`, `q`, `arst` (`arst` is 1 bit). While
  `arst` is 1, `q` is `value`; otherwise `q` takes `d` on the given
  edge of `clock`. `d` and `q` are as wide as `value`. Power-on value
  is 0. Text form `$adff[Rise:8'd5]`. That is the hardware meaning (what a
  backend emits). `ir::exec`, like `mimz sim`, is cycle-based and samples
  `arst` only at the clock edge, so between edges, and before the first one,
  it does not show the reset value.
- **`Mem { depth, init, read_ports }`** - `depth` words, each as wide as
  `rdata`/`wdata`, seeded to `init`. One write port as ordinary pins (`waddr`,
  `wdata`, `wen`, and `clock` unless the memory is a ROM); any number of read
  ports in `read_ports`, each an `(raddr, rdata)` pair. Reads are
  **combinational** (asynchronous). A ROM is a `Mem` whose `wen` is tied low.
- **`BlackBox { module_name }`** - one `extern module` instance. Its pins are
  the extern's own port names. Which pins it drives comes from the extern's
  declared port directions (`Module::extern_decls`), not from pin names.

### 3.6 Known v1 limits

These are deliberate v1 boundaries, tracked in `docs/audit/gaps.md` GAP-1:

- **Resets are per register.** A synchronous reset is a `Mux` (reset selects
  the reset value) in front of a plain `Dff`'s `d`; an async reset is an
  `Adff`. Each register uses its own module's first declared reset, async
  when any reset in that module is `async` (the Verilog emitter's rule); a
  child's reset follows the signal it is connected to. A module with no reset
  gives its registers neither.
- **`Shr` is logical only** - an arithmetic (sign-extending) right shift is not
  yet a separate kind.
- **No module-level clock list.** Clocks are only the `clock` nets on
  `Dff`/`Adff`/`Mem` cells.

## 4. Text formats

Two printers, for reading and diffing the IR. Neither is a stable interchange
format yet.

- **Line format** (`ir/print_line.rs`, parsed back by `ir/parse_line.rs`): a
  `module <name>` line, one `port in|out <name>[0:<width>]` line per port, a
  blank line, then one line per cell:

  ```text
  cell $<op> :<index> <pin>=<bits> ...
  ```

  `<bits>` is `name[0:width]` when every net is one contiguous run of the same
  named signal, or a net-id list `{3,4,7}` otherwise, followed by `s` when the
  pin is signed (`a[0:8]s`, `{3,4}s`): signedness is per pin and changes what
  arithmetic computes. Cell-kind arguments go in
  brackets: `$dff[Rise]`, `$adff[Rise:8'd5]`, `$lt[signed]`, `$slice[2:5]`, `$mem[16]`,
  `$const[8'd255]`, `$blackbox[Pll]`. A `Mem`'s read ports print as numbered
  `raddrN=`/`rdataN=` pins. An unknown bracket argument is a parse error, never
  a silent default.

- **S-expression format** (`ir/print_sexpr.rs`): print-only, for humans.

`mimz ir <file>` prints the optimized line format (`--sexpr` for the other,
`--no-opt` to skip the optimizer, `--stats` for cell counts).

**Not round-tripped in v1:** `Module::signals`, `extern_decls` and
`port_declared_widths` (so a parsed module cannot be checked against them); a
`Dff`/`Adff` clock net and a `Mem`'s `init`; and an output port whose nets are
another signal's or a cell's unnamed nets (the `port` line gives only a width,
so after parsing that port is connected to nothing).

## 5. Validation

`ir::validate` re-checks what the checker already guaranteed, to catch a bug in
lowering or in an optimizer pass. Every check runs and reports independently:

1. **Drivers** - every net read has exactly one driver (`MultipleDrivers`,
   `UndrivenNet`).
2. **Pin widths** - the per-kind rules in section 3 (`WidthMismatch`,
   `ShiftGrowthTooWide`).
3. **Matched operands** - `a`/`b` the same width where section 3 requires it.
4. **No combinational cycles** - every loop passes through a `Dff`, `Adff` or a `Mem`
   write (`CombinationalCycle`).
5. **Black-box shape** - a `BlackBox` cell's pins match its extern's declared
   ports (`BlackBoxPortMismatch`).
6. **Output widths** - each output port has its source-declared width
   (`PortWidthMismatch`).

Checks 5 and 6 are skipped when the module carries no declaration to check
against (a module parsed from text).

## 6. Optimization

`ir::opt::optimize` runs three passes, every pass every round, until a round
changes nothing (at most 32 rounds):

- **Constant folding** - a cell whose inputs are all constants becomes a
  `Const`.
- **Mux simplification** - bypass a mux with a constant `sel`, a mux bit whose
  two data bits are equal, and an inner mux on the same `sel`.
- **Dead-cell elimination** - remove combinational cells nothing reads, then
  drop unused nets. `Dff`, `Adff`, `Mem` and `BlackBox` cells are always kept.

Every pass must keep the module `validate`-clean and must not change any
output's value on any cycle. `tests/ir_opt_corpus.rs` checks both over the
example corpus.

## 7. Equivalence

The IR must behave exactly like the source program as `mimz sim` runs it
(spec/05). `ir::exec` runs an IR module cycle by cycle using the same value
functions as the simulator, and `tests/differential_fuzz.rs` compares the two
on random programs. Any difference is a compiler bug.

## Changelog

- **v0.3 (2026-10-02)** - signed pins round-trip through the line format
  (trailing `s`); the not-round-tripped list now names the clock net, `Mem`
  init and output-port aliasing. Clock nets include `Adff`'s; `Adff`'s
  reset is sampled at the edge by `ir::exec` (final-review fixes).

- **v0.2 (2026-10-02)** - per-register reset and the `Adff` cell kind (async
  reset, pins `d`/`q`/`arst`, text `$adff[Edge:width'dvalue]`); removes
  the synchronous-only-reset limit.

- **v0.1 (2026-10-02)** - initial IR v1 contract: nets and `Bits`, the 32 cell
  kinds and their width rules, the line and s-expression formats, the six
  validation checks, the three optimizer passes, and the known v1 limits
  (logical-only `Shr`, no clock list, partial text
  round-trip).
